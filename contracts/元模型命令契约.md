# 元模型(M2)授权命令契约 v1.0（addendum）

- 性质：对《数据内核命令与事件正式契约 v1.1》的**附录扩展**，登记 M2 类型授权命令；不改 v1.1 既有 M1 命令集（AG-301）。
- 端点：`POST /workspaces/{id}/meta-commands`（与 M1 `/commands` 分离，保持 M1 注册集纯净）
- 信封：`{ commandType, workspaceId, correlationId, idempotencyKey, payload }`（同 v1.1 信封风格）
- Schema：`contracts/schemas/meta-commands.schema.json`（Draft 2020-12，已纳入 `pnpm contracts:check`）
- 蓝本：`docs/04-metamodel-m2-design.md`
- 红线：AG-109（模板组不跑重任务）、AG-110/201（命令入口、事务内零出站）、AG-321（审计字段）

## 命令清单（批1）

| commandType | 语义 | 幂等键建议 |
|---|---|---|
| DefineObjectType | 建/改对象类型 | `define-ot-<code>-<n>` |
| DefineFieldDef | 建/改属性定义（含 dataType+constraints） | `define-fd-<code>-<n>` |
| DefineRelationType | 建/改关系类型 | `define-rt-<code>-<n>` |

> 发布/实例化/兼容校验（PublishTemplateVersion / InstantiateWorkspace / ApplyTemplateVersion）属批2，另行 addendum，本契约不含。

## 详规

### DefineObjectType
- payload：`templateVersionId?(uuid,可空)`、`code(snake_case,1..128)`、`name(1..256)`
- 校验：`(workspace, code)` 唯一；`templateVersionId` 非空且其状态为 published → 拒 `KERNEL-409-TEMPLATE-VERSION-IMMUTABLE`
- 事件：批1 不发元模型事件（进 Outbox 属批2）

### DefineFieldDef
- payload：`objectTypeId(uuid)`、`code`、`name`、`dataType(枚举)`、`required(bool,默认 false)`、`constraints(object)`
- dataType 封闭集：`string|text|integer|number|boolean|date|datetime|enum|ref|json`（集外 → `KERNEL-400-SCHEMA-INVALID`）
- 校验：归属对象类型不存在 → `KERNEL-404-TYPE-NOT-FOUND`；约束与类型不相容（enum 无 enumValues、ref 无 refObjectTypeCode 或其指向类型不存在、number 的 min>max、pattern 超长/危险）→ `KERNEL-422-FIELD-CONSTRAINT-INVALID`（details 列违例）

### DefineRelationType
- payload：`code`、`name?`、`sourceTypeId`、`targetTypeId`、`direction(directed|undirected)`、`cardinality(one_to_one|one_to_many|many_to_many)`、`semantics(weak|strong)`、`hierarchical(bool,默认 false)`
- 校验：`(workspace, code)` 唯一；source/target 类型存在（否则 `KERNEL-404-TYPE-NOT-FOUND`）；`hierarchical=true` 必须 `cardinality=one_to_many`（承 V2 约束）→ 否则 `KERNEL-422-FIELD-CONSTRAINT-INVALID`

## 类型校验挂点（M1 写命令）
DefineFieldDef 落地的 `dataType+constraints` 由 `FieldValidator` 在 CreateObject/UpdateFields 预检中执行：类型不匹配/必填缺失/越界/越长/非枚举/不匹配 pattern/ref 指向不存在对象 → `KERNEL-422-FIELD-VALUE-INVALID`（details 逐违例字段）。校验在事务预检内完成、零出站（AG-201）。

## 错误码（登记于 error-codes.yaml）
`KERNEL-409-TEMPLATE-VERSION-IMMUTABLE`、`KERNEL-422-FIELD-CONSTRAINT-INVALID`、`KERNEL-422-FIELD-VALUE-INVALID`（复用既有 `KERNEL-400-SCHEMA-INVALID`、`KERNEL-404-TYPE-NOT-FOUND`、`KERNEL-409-IDEMPOTENCY-CONFLICT`）。

# v1.1 addendum（泛化 / 重定义 / 值类型）

- 性质：对本契约 v1.0 的**增量扩展**，蓝本 `docs/15-m2-generalization-redefinition.md`。Schema 升至 `meta-commands/1.1`（新增 `DefineValueType`，扩 `DefineObjectType`/`DefineFieldDef`）。**不改既有 M1 命令集**（AG-301）。
- 两条同型继承线：**对象类型**（`object_type.parent_type_id`）与**值类型**（一等实体 `value_type`，自身可泛化）。机制：单继承 + 重定义只能协变收紧 + 沿链解析有效集 + 发布即冻结 + 环检测。

## 新增/扩展命令

| commandType | 改动 | 关键校验（错误码） |
|---|---|---|
| `DefineValueType`（**新**） | 定义/改值类型：`code/name/basePrimitive/parentValueTypeCode?/constraints` | 父存在（`META-422-PARENT-NOT-FOUND`）；父子根原语一致（`META-422-VALUETYPE-BASE-MISMATCH`）；不成环（`META-422-GENERALIZATION-CYCLE`）；约束相对父只收紧（`META-422-REDEFINITION-INCONSISTENT`）；published 下改 → `META-409-PUBLISHED-IMMUTABLE` |
| `DefineObjectType` | 增可选 `parentTypeCode` | 父存在/同模板版本（`META-422-PARENT-NOT-FOUND` / `META-422-PARENT-CROSS-TEMPLATE`）；不成环（`META-422-GENERALIZATION-CYCLE`） |
| `DefineFieldDef` | 字段类型由 `dataType` **或** `valueTypeCode`（二选一，oneOf）指定；增可选 `redefinesFieldCode` | `valueTypeCode` 不存在 → `META-422-PARENT-NOT-FOUND`；`redefinesFieldCode` 触发协变收紧一致性，放宽 → `META-422-REDEFINITION-INCONSISTENT` |

## 协变收紧（重定义一致性，维度判定）

子（字段或值类型）相对父逐维只能更严：值类型只能换成**同类或子孙**；`required` false→true；`maxLength`↓；`minLength`↑；`min`↑/`max`↓（区间收窄）；`enumValues` 取子集；`refObjectTypeCode` 改为原类型的子类型。任一放宽 → `META-422-REDEFINITION-INCONSISTENT`（details 返回违例维度与父基准）。

## 有效解析（实现约束，纯读纯函数 AG-105）

- `resolveEffectiveValueType(valueTypeId)`：沿 `parent_value_type_id` 合并约束（子收紧覆盖）→ `{base_primitive, 约束}`。
- `resolveEffectiveFields(objectTypeId)`：沿 `parent_type_id` 合并 `field_def`（子同 code 覆盖父），字段类型再经上式折算 → `Map<code, FieldDefinition>`（喂现有 `FieldValidator`，其逻辑不改）。
- ref/关系端点类型匹配改为"目标类型 ∈ 期望类型子孙闭包"（IS-A）。

## 错误码（追加登记）
`META-422-PARENT-NOT-FOUND`、`META-422-PARENT-CROSS-TEMPLATE`、`META-422-GENERALIZATION-CYCLE`、`META-422-VALUETYPE-BASE-MISMATCH`、`META-422-REDEFINITION-INCONSISTENT`、`META-409-PUBLISHED-IMMUTABLE`。

## Schema fixtures（meta-commands）
正例：`define-value-type`、`define-object-type-with-parent`、`define-field-def-redefine`；反例：`define-field-def-both-types`（违 oneOf）、`define-value-type-missing-base`（缺 basePrimitive）。语义类（环/跨模板/根原语不符）属实现卡集成测试，非 Schema 可判。

# 批2 addendum（模板版本生命周期）

- 性质：对本契约的**增量扩展**，蓝本 `docs/16-template-lifecycle.md`。Schema 增 3 命令；**不改既有命令**（AG-301）。
- 端点同 `/workspaces/{id}/meta-commands`。

## 新增命令

| commandType | payload | 语义 / 关键错误码 |
|---|---|---|
| `PublishTemplateVersion` | `templateVersionId` | draft→published 冻结；已发布重复→`KERNEL-409-TEMPLATE-VERSION-IMMUTABLE`；空版本→`KERNEL-422-TEMPLATE-EMPTY` |
| `InstantiateWorkspace` | `templateId, version, newWorkspaceId, workspaceName` | 仅 published 版本（否则 `KERNEL-422-TEMPLATE-NOT-PUBLISHED`）；复制该版本类型(含 value_type/object_type/field_def/relation_type/rule_def，**id 重映射**)进 `newWorkspaceId`；信封 `workspaceId`=操作上下文，新空间 id=`newWorkspaceId`（客户端供、幂等） |
| `ApplyTemplateVersion` | `toVersion` | 目标=信封 `workspaceId`；比对 from→to 逐项判级：新增兼容自动应用 / 收紧阻断→`KERNEL-409-TEMPLATE-MIGRATION-REQUIRED`+受影响存量。**含泛化/重定义/值类型演化维度（= gen-d）** |

## 演化判级（两档，含 gen-d）

- **新增兼容（自动）**：新类型/值类型/关系；新可选字段；放宽约束；新枚举值；新增子类型；重定义进一步收紧。
- **收紧阻断**：新必填字段（存量缺值）；收紧约束；删字段/类型；删有引用枚举值；改 data_type；**改父类型**；**重定义/值类型改为非子孙**；**父级字段改严致存量子类型实例违反** → `KERNEL-409-TEMPLATE-MIGRATION-REQUIRED`。

## 错误码（追加登记）
`KERNEL-422-TEMPLATE-NOT-PUBLISHED`、`KERNEL-409-TEMPLATE-MIGRATION-REQUIRED`、`KERNEL-422-TEMPLATE-EMPTY`（`KERNEL-409-TEMPLATE-VERSION-IMMUTABLE` 已登记）。

## Schema fixtures
正例：`publish-template-version`、`instantiate-workspace`、`apply-template-version`；反例：`instantiate-workspace-missing-version`、`apply-template-version-bad-version`。语义类（未发布版本、演化判级、id 重映射完整性）属实现卡集成测试。

# 派生属性 addendum（派生/计算层）

- 性质：对本契约的**增量扩展**，蓝本 `docs/18-derivation-computation-layer.md`。Schema 增 `DefineDerivedField`；**不改既有命令**（AG-301）。
- 派生属性是对象类型上的**只读计算字段**（不落主数据），随模板版本发布锁版、随实例化/演化复制（承批2）。

## 新增命令

| commandType | payload | 语义 / 错误码 |
|---|---|---|
| `DefineDerivedField` | `objectTypeId, code, name, resultType(dataType), derivation(表达式), templateVersionId?` | 在对象类型上定义派生字段；表达式语法错→`DERIVE-400-SYNTAX-INVALID`；派生间依赖成环→`DERIVE-409-DEPENDENCY-CYCLE`；求值超界→`DERIVE-422-EVAL-LIMIT`；code 与既有 stored 字段冲突→`KERNEL-422-FIELD-CONSTRAINT-INVALID` |

## 表达式语法附录（封闭集，der-a 实现）

在规则 DSL 标量/比较/逻辑/白名单之上新增：

- **路径/遍历**：`traverse('relTypeCode', 'out'|'in')` → 关联对象集合；`traverseDeep('relTypeCode', dir, maxDepth)` 多跳（`maxDepth` 有上限,见 der-a）；可链式。
- **聚合**（over 集合, 目标字段）：`sum(set,'field')`、`avg`、`max`、`min`、`count(set)`、`any(set,cond)`、`all(set,cond)`。
- **算术 / 条件**：`+ - * /`、`if(cond, a, b)`。
- **引用**：`field('code')` 可指 stored 或**另一派生**字段（组合/嵌套,依赖 DAG 无环）。
- **查表/插值**（interp-spec addendum,长板3）：`interp(key, x1,y1, x2,y2, …, xn,yn)` 线性插值;`lookup(key, x1,y1, …)` 分段常数（阶梯,取最大 `xi ≤ key` 对应 `yi`）。约束:断点对数 `n ≥ 1`、`x` 严格递增、参数个数为奇数（1 个 key + 偶数个表项）;**越界钳到端点**(key<x1→y1,key>xn→yn,工程安全,不报错);表畸形(奇偶不符/不足一对/x 非递增)→`DERIVE-400-SYNTAX-INVALID`。用途:DOD-循环次数(lookup)、温度/辐照衰减曲线(interp)。表项为字面量,无需新实体/命令/迁移。**同样适用于规则 DSL**(共用求值器)。

## 求值与安全（实现约束）

读时惰性求值、依赖拓扑序;遍历深度/结果集/步数三重上限(超限 `DERIVE-422-EVAL-LIMIT`);纯求值器(engines)+ 只读数据上下文;派生不落主数据(AG-105)。

## 错误码（追加登记）
`DERIVE-400-SYNTAX-INVALID`、`DERIVE-409-DEPENDENCY-CYCLE`、`DERIVE-422-EVAL-LIMIT`。

## Schema fixtures
正例：`define-derived-field`；反例：`define-derived-field-missing-derivation`。语义类（语法/依赖环/求值上限）属实现卡(der-a/b/c)集成测试。

# 联邦 / M2M addendum（跨 profile 转换）

- 性质：对本契约的**增量扩展**，蓝本 `docs/20-federation-m2m.md`。Schema 增 `DefineTransformation`/`RunTransformation`；**不改既有命令**（AG-301）。
- **对应（correspondence）复用既有 `DefineRelationType`**：定义一个跨 profile 的关系类型(source/target 属不同 profile)即可,无需新命令;联邦互查走读侧查询端点。

## 新增命令

| commandType | payload | 语义 / 错误码 |
|---|---|---|
| `DefineTransformation` | `code,name,correspondenceRelationCode,objectMappings[],relationMappings[]?` | 定义 M2M 映射(源类型→目标类型+字段映射;源关系→目标关系);映射结构/表达式错→`M2M-400-MAPPING-INVALID`;源类型/关系不存在→`M2M-422-SOURCE-UNRESOLVED`;目标/对应关系不存在→`M2M-422-TARGET-UNRESOLVED` |
| `RunTransformation` | `transformationCode` | 对信封 workspaceId 的源模型执行:读源→经命令(CreateObject/CreateRelation)生成目标对象/关系→用 `correspondenceRelationCode` 回指源→记 provenance;**幂等**(按 correspondence 找已生成则更新);生成的写经命令入口(AG-110)、过目标 profile 规则校验 |

## 映射语义

- `objectMappings[i]`:源类型 `sourceTypeCode` 的每个对象 → 生成 `targetTypeCode` 目标对象;`fieldMappings` 的 `expression` 对**源对象**求值(复用派生/规则表达式引擎)填目标字段。
- `relationMappings[i]`:源关系 `sourceRelationCode` 的每条 → 在两端源对象**各自对应的目标对象**之间建 `targetRelationCode` 关系(端点经 correspondence 解析)。
- 每个生成目标对象用 `correspondenceRelationCode` 建一条 目标→源 关系(身份回指,可反查/重投影)。

## 红线
M2M 生成经命令入口(AG-110)、可被目标 profile 规则校验;读源只读(AG-105);correspondence + provenance 必留;重叠/冲突按人定规则,不静默覆盖(BL-11)。

## 错误码（追加登记）
`M2M-400-MAPPING-INVALID`、`M2M-422-SOURCE-UNRESOLVED`、`M2M-422-TARGET-UNRESOLVED`。

## Schema fixtures
正例：`define-transformation`、`run-transformation`；反例：`define-transformation-empty-mappings`(objectMappings 空)。语义类(源/目标解析、幂等重投影、生成走命令)属实现卡(fed-2)集成测试。

# 模板创作 API addendum（tpl-api,缺口修复）

- 性质:对本契约的**增量扩展**,蓝本 `docs/tasks/T-V33-TPL-API-模板创作API.md`。fed-3/energy e2e 暴露"模板创作链缺创建入口"(现状靠测试 SQL 建 `scene_template`/`scene_template_version`、patch `relation_type.template_version_id`)。本 addendum 补齐**纯 API 创作 profile 模板**。Schema 增 `CreateTemplate`/`CreateTemplateVersion`、`DefineRelationType` 加可选 `templateVersionId`;**不改其它既有命令语义**(AG-301)。**无需迁移**(表/列已在 V3)。

## 新增 / 扩展命令

| commandType | payload | 语义 / 错误码 |
|---|---|---|
| `CreateTemplate` | `code,name` | 创建 `scene_template` + 其**草稿首版**(version=1,status=draft);返回 templateId + templateVersionId;`code` 全局唯一,重复→`KERNEL-409-TEMPLATE-CODE-CONFLICT` |
| `CreateTemplateVersion` | `templateId` | 在该模板下新建 **version=max+1 的 draft 版本**;返回 templateVersionId;模板不存在→`KERNEL-404-TEMPLATE-NOT-FOUND`(允许多个未发布草稿) |
| `DefineRelationType`(扩展) | …既有… + 可选 `templateVersionId` | 给定时关系类型归属该 **draft** 模板版本(写 `relation_type.template_version_id`),取代测试 SQL patch;published 版本下→`KERNEL-409-TEMPLATE-VERSION-IMMUTABLE`;版本不存在→`KERNEL-404-TEMPLATE-NOT-FOUND` |

## 纯 API 创作链(验收路径)

`CreateTemplate` → (可选 `CreateTemplateVersion`) → 草稿版本上 `DefineObjectType/DefineFieldDef/DefineValueType/DefineRelationType`(均带 templateVersionId)→ `PublishTemplateVersion` → `InstantiateWorkspace` → 业务命令 + 规则检查。**全程零 SQL**。

## 红线
模板/版本/关系类型写入经命令入口 handler(AG-110);published 版本不可改(IMMUTABLE);命令/错误码人发起(AG-301/501);夹具随契约入库(AG-406)。

## 错误码（追加登记）
`KERNEL-409-TEMPLATE-CODE-CONFLICT`、`KERNEL-404-TEMPLATE-NOT-FOUND`。

## Schema fixtures
正例:`create-template`、`create-template-version`、`define-relation-type-templated`;反例:`create-template-missing-name`、`create-template-version-missing-template`。语义类(版本号递增、归属校验、纯 API 链)属实现卡(tpl-api)集成测试。
