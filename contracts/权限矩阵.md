# RBAC 权限矩阵

## 自举规则

工作空间未治理时，`workspace_member` 中该 `workspace_id` 没有成员记录，任何可信
`X-Actor-Id` 都视同 `ADMIN`。首次 `GrantWorkspaceRole` 会同时把发起者登记为
`ADMIN`，工作空间随后进入强制 RBAC 治理。

工作空间已治理时，请求必须携带有效且 `ACTIVE` 的 `X-Actor-Id`。系统按
`(workspace_id, user_id)` 查得角色，角色低于动作最低档位则拒绝。

## 角色层级

`VIEWER < AUTHOR < REVIEWER < ADMIN`

## 动作映射

| 动作类别 | 入口 | 最低角色 |
| --- | --- | --- |
| 读视图/查询 | `/workspaces/{workspaceId}/views/**`、`/members`、附件内容与查询、快照/仿真列表 | VIEWER |
| 写数据 | `/commands`、仿真创建、快照捕获、交换 apply、附件上传/Attach/Detach | AUTHOR |
| 评审/确认 | `/review/commands`、`RunRuleCheck` | REVIEWER |
| 治理 | `/meta-commands`、`DefineRule`、`PublishRule`、`/rbac-commands` | ADMIN |

## 错误码

| 错误码 | HTTP | 说明 |
| --- | --- | --- |
| `AUTH-401-UNKNOWN-ACTOR` | 401 | 已治理工作空间内 actor 不存在、格式无效或已停用 |
| `AUTH-403-FORBIDDEN` | 403 | actor 存在但无成员关系或角色不足 |
| `RBAC-400-SCHEMA-INVALID` | 400 | RBAC 命令信封或载荷无效 |
| `RBAC-409-IDEMPOTENCY-CONFLICT` | 409 | 同一幂等键被不同载荷复用 |
