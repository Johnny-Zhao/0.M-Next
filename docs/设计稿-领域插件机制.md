# 设计稿(征求):领域插件机制 —— 让 室内设计/能源/SysML 都是可装卸插件,不改 core

> 约束(产品负责人):**这些领域必须由插件实现**——室内设计、能源分系统、SysML、Modelica… 每个是一个可装卸插件,**不改 kernel/engines/server/web core 源码**。
> 本稿:① 摆现状(已有什么扩展点、缺什么);② 定义"M-Next 领域插件"的构成;③ 列出需要补的扩展点(这是**最后一批 core 改动**,补完领域永不碰 core);④ 把"室内设计"重定为**首个插件**并重新规划卡。

## 2. 「M-Next 领域插件」定义

一个领域插件 = 一个自包含包(`packages/domains/<name>` + 可选后端 jar/SPI),贡献三类东西,**全部经扩展点注入,绝不改 core**:

1. **Profile 清单(声明式数据)**:value-types / object-types / fields / relations / derived / rules。
   **运行时经命令路径装载**(ProfileLoader → tpl-api 命令),所以 profile 是**数据制品**,不是 core 代码、也不是测试。
2. **前端贡献(可选)**:维度、控件库 stencil、面板、视图类型——经**前端注册表**贡献(不改 `dimensions.ts`/`workbench.tsx`)。
3. **后端引擎(可选,★)**:碰撞检测/报价/光照分析等——经 **SPI(ServiceLoader)** 实现,**复用现有 `ExchangeAdapter` 等先例**;仅当领域要**自定义规则函数/派生算子**时才需新增"函数 SPI"。

> core 只提供:**扩展点 + 装载器/注册表 + 模板目录(`/views/templates`)**。领域只生产清单与注册。

## 3. 需要补的扩展点(最后一批 core 改动)

**后端**
- **F1 · ProfileLoader + 声明式 profile 格式**(P0,室内 v1 必需):定义 JSON/YAML profile 清单 schema;Loader 把清单按序翻译成 tpl-api 命令(经 MetaCommand/Rule/Kernel 命令服务,或扩 `BatchCommandHandler`)→ 建模板/发布/(按需)实例化。**经现有命令路径,不改契约。**
- **F2 · 规则函数 / 派生算子 SPI**(P1,**室内 v1 不需要**——只用现成 `field/*/sum/traverse`):把 `RuleFunctions` 的 `switch` 改为可注册函数表;仅当某领域要自定义算子时落地。
- **F3 · 分析/出图 ★engine**:**已有 SPI**,复用 `ServiceLoader` 先例,无需新基建。

**前端**
- **F4 · DimensionRegistry**(P0,室内 v1 必需):core 内置注册 energy/thermal/mass;暴露 `registerDimension()`,领域包注册自己的维度(室内注册 风/光)。`diagram-panel` 改为读注册表而非 import 常量。
- **F5 · Panel/Stencil/ViewType 注册表**(P1,室内要自定义控件库/面板时再做):`dockviewComponents`/`workbenchPanelDefinitions`/命令 改为注册表发现。
- **F6 · `packages/domains/*` 约定**(P0):pnpm workspace 加 `packages/domains/*`;每个领域包导出 `{ profileManifest, dimensions?, stencils?, panels? }`,主应用启动时发现并注册。

**平台 catalog(非领域)**
- **`/views/templates` 只读端点**(已规划,卡 ③不变):列已装载/发布的模板,供 HOME 向导"选 profile"。属平台基建。

## 5bis. 装卸生命周期(硬要求:install / uninstall,可逆、非破坏)

插件是**可装卸单元**,不是"启动塞数据"。每个插件有描述符 `plugin.json`(`id`/`name`/`version`/`profileManifest`/`frontendModule?`/`engines?`)。

- **装(install)**:后端 ProfileLoader 读清单 → 经 tpl-api 命令建模板+发布(**幂等**,重装不重复);前端发现领域包 → 经注册表注册其维度/(后续)stencil/面板。模板随即出现在 `/views/templates`,可实例化。
- **卸(uninstall)**:**撤下模板目录项**(模板版本标 `withdrawn`/停用 → 不再出现在目录、不可再新实例化)+ **注销前端贡献**(从注册表移除维度等)。
  - **非破坏、可逆**:实例化时类型/字段/规则**已拷入工作空间**(`template_version_id IS NULL`),故**已建工作空间照常工作**;卸载**只撤目录与贡献,绝不硬删模板/用户数据/工作空间**(符合"不永久删除数据"红线)。重装即恢复可用。
- **隔离**:一个插件的装卸**不影响其它插件/工作空间**;失败要原子回滚(装到一半失败 → 不留半个模板)。

> 验收里必须含:装 → 列出/实例化 → 卸 → 目录不再含、不可新实例化、**老工作空间仍可用** → 重装恢复。

## 6. 决策:**B 薄切片证模型**(已定)

只补室内 v1 必需的 **F1 + F4 + F6**,出首个插件 **D-INTERIOR** 跑通"装→实例化→派生/规则灯/维度→卸";F2/F5/引擎 SPI、老 profile 迁移按需后置。下方为原决策备忘。
