# M-Next 北极星:统一真值的多重表达

> 一句话定位:**一处真值,处处表达;表达之间永远对得上。**
> M-Next 不是更聪明的数据库,也不只是数据集线器——它是**让同一份工程真值在不同工具语言、不同设计阶段、不同分析维度之间自由表达,并保证这些表达彼此一致**的引擎。

本文是产品重心的锚:定义这件事的本质、三根表达轴、跨表达一致性这条核心价值回路,以及它对 UI 与落地顺序的含义。供产品定调、回喂设计、校正前端优先级之用。

---

## 1. 为什么是这个重心

平台能做三件事:① 多专业真值集线;② 跨专业闭环校核;③ 方案比选决策。三件平权,就没有重心,UI 看起来像"部件陈列"——这就是当前高保真稿"能用但差点意思"的根因。

把重心定在**"统一真值的多重表达"**,另外两件不丢,反而被收编为它的两个侧面:

- **闭环校核 = 表达之间没掉队**(不同表达若对不上,就是需要校核/收敛的信号);
- **方案比选 = 在表达的变体里挑一个**(候选方案本质是同一问题的不同表达取舍)。

所以这是更高一层的重心:它统辖校核与比选,而不是与它们并列。

---

## 2. 三根表达轴

同一份真值,沿三根正交的轴被表达出来。三根轴的"表达关系"性质**不同**,产品对它们的处理方式也应不同。

### 语言轴 —— 同一模型用哪个工具的话说
SysML 块图 ↔ Modelica 方程 ↔ Excel 行 ↔ 3D 几何 ↔ ReqIF 需求。
关系性质:**翻译/转换**,可能**有损**,需要**往返对账**(round-trip)。
例:能源分系统在 SysML 里是结构块,在 Modelica 里是一组功率平衡方程——同一对象,两种形式语言。

### 阶段轴 —— 同一实体在哪个成熟度
方案 → 初样 → 正样(→ 在轨/运维)。
关系性质:**细化**,身份不变、保真度递增,**累加不替换**。命门是可追溯:"正样这个实测值,能追到方案阶段哪条假设。"
例:能源分系统从方案阶段的粗功率预算,演进到正样的实测放电深度——还是同一个分系统。

### 维度轴 —— 同一对象看哪个物理侧面
风 / 热 / 光 / 结构 / 能量 ……
关系性质:**投影/选取**,**无损**,只是换一组字段与规则去看同一个东西。
例:一栋房子,同一份几何,既可作 CFD 风环境看、作热工看、作采光看。

> **三种关系一句话区分:维度是选取(无损视图)、阶段是细化(累加)、语言是翻译(可能失真)。**
> 因此:维度只要切视图,阶段要存血缘链,语言要做映射 + 一致性核对。三者的工程难度也由此从低到高。

---

## 3. 核心价值回路:跨表达一致性

平台的"魔法时刻"不是看到一个派生值,而是**在两个表达之间发现它们对不上,并被帮着判断这意味着什么**。

> SysML 标称总线功率 120 W,Modelica 仿真得 135 W。
> 平台要回答:这是**真不一致**(设计尚未收敛,需校核/迭代),还是**转换误差**(口径/边界条件不同,需对齐映射)?

这条回路把"表达"从静态展示变成活的工程行为:任一表达发生改动 → 沿轴重新投影/重算 → 其它表达若掉队则**亮出不一致**,并标注"真不一致 / 口径误差"的判别线索 + 责任归属。这就是闭环校核在本重心下的真正形态——不是"规则灯变红",而是"**表达之间出现了裂缝**"。

---

## 4. UI 的主角要换:从"五镜头"到"表达切换台"

当前五镜头(树/表/图/矩阵/文档)是**通用看法**——换排版看同一份数据,不是表达轴。它们应保留为"读统一模型"的方式,但**不再是门面**。

门面应是**表达切换 + 映射透明 + 跨表达一致性**:

- 选中一个实体(如"能源分系统"),顶部一排切换轴:
  `[语言:SysML | Modelica | Excel | 3D]` · `[阶段:方案 | 初样 | 正样]` · `[维度:风 | 热 | 光 | 能量]`
- 切换时,平台显式告诉你:**映射了什么、哪里有损、哪份过期、两个表达对不对得上**。
- 一致性状态是第一类公民:并排呈现差异、给出"真不一致 vs 口径误差"的判别线索、可一键发起校核/收敛或投影重算。
- provenance(来源 / 新鲜度 / 下游依赖)作为**贯穿所有表达的视觉常量**,而非详情里的一个功能——因为"这个表达可不可信"取决于它的来源与新鲜度。

---

## 5. 架构已经认了这个重心

这不是推倒重来——说明书的数据脊柱本就是"**规范模型 + 多重投影**"的结构:

- **语言轴** ← `ExchangeAdapter` SPI(已有 json / reqif / sysml 入向适配;Modelica、双向往返为后续);
- **阶段轴 / 维度轴** ← `profile` + `M2M 投影`("同一实体多镜头互引、互引不互拷,把此模型映射到彼模型");
- **跨表达一致性** ← 派生字段(`DerivedEvaluator` 知其输入)+ 规则校核 + `SourceInfo`(每条命令/对象都带来源)+ `updatedAt`(新鲜度)。

缺的不是地基,是**把"表达轴 + 映射 + 一致性"这层长出来并顶到台前**:血缘/依赖经 view-API 暴露、跨表达差异检测、新鲜度与口径上界面。

---

## 6. 落地顺序(先易后难,逐根轴证明思想)

**先维度轴(最便宜,先证明)。** 同一对象 + 不同字段/规则子集,现有模型直接能做。建议第一刀做一个三维度 demo(如卫星某分系统的 能量 / 热 / 质量 三视图切换),把"同一真值多侧面"演出来。后端几乎零新增。

**再阶段轴(中等)。** 给"同一实体跨阶段 profile"建链 + 差异对比(diff),profile/联邦机制能撑一部分。需补:阶段间身份对应 + 细化血缘 + 阶段 diff 视图。

**后语言轴(最深,慢长)。** 先把已有入向适配(sysml/reqif/json parse)用起来;SysML↔Modelica 双向语义投影、Modelica 本身属研究级("Later"),**不打头阵**,让往返对账随能力成熟逐步落地。

---

## 7. 相对现有设计/前端优先级的调整

- 首页/门面:从"模型浏览器"调为**以实体 + 表达切换台为中心**;模型浏览器退为读模型的一种方式。
- 新增**表达轴切换 + 映射透明 + 一致性对比**为核心交互(优先于美化既有五镜头)。
- provenance 升为贯穿所有表达的视觉常量(来源/新鲜度/下游依赖)。
- **WEB-1(五镜头壳视觉重构)仍有效**——它是承载这一切的骨架;但其后的前端重心是"维度轴 demo + 一致性",而非继续堆砌浏览器细节。
- 接入/导入(已落地的 Excel IMP-A)从"一个功能"理解为"**表达的进水口**":每种工具适配都是把外部表达引入统一真值的一根管子。

---

## 8. 不变的红线(本重心下依然成立)

- **互引不互拷**:表达之间是映射/投影,不是复制——切换语言/阶段/维度,底下是同一份真值。
- **一切写入经命令入口、留审计与版本**;视图只读、零拷贝。
- **AI 不直接写**:AI 在本重心下的角色是"**表达一致性守门人**"——主动指出"两个表达对不上""某表达基于过期来源""手填值无来源",并以可审查的变更集提议,由人确认。
- 契约/模式/迁移变更**人发起**;表达层的 view-API 新增同样走人发起的契约。
