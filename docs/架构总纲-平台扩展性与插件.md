# 架构总纲 · M-Next 平台扩展性与插件(单一权威来源)

> 把"项目/模块/profile/视角"分层、命名空间、装卸机制、能力市场,以及已落地的治理底座,收敛到这一份。
> 细节实现见:`设计稿-领域插件机制.md`、`设计稿-视图API扩展-*.md`、`AI上下文执行层-设计稿.md`、`RBAC权限-设计稿.md`,以及各 `T-V33-*` 实现卡。

## 一、一句话定位
M-Next 是**数据驱动的多领域工程建模平台**:统一的受治理数据底座 + **可装卸的领域插件**;图/表/矩阵/文档/平面图只是同一份真值的多重表达,改一处全联动。

## 二、分层模型(自顶向下)
```
项目 Project
  └─ 模块 Module(= 一个领域,如 室内设计 / 系统工程 / 技术方案)
        └─ profile(领域内的一个子部分:元模型 + 功能 + 视图 + 流程)
              └─ 视角 perspective(面向某类用户/场景的取景,可跨多 profile)
```
- **模块 = 领域**;**子部分 = profile**。一个项目可**组合多个模块**。
- profile 四要素:**元模型**(对象/字段/关系/派生/规则)、**功能**(命令/引擎)、**视图**(图/表/矩阵/文档/领域专属视图)、**流程**(评审/状态机)。
- **视角**对应多模块:用向导 + 引导步骤进入,不是结构层级。

## 三、命名与扩展规则
- **命名空间分隔符 `::`**(如 `interior::room`),避免跨插件同名冲突。
- **extends 只增不改**:profile/类型可继承扩展,只能新增字段/关系/规则,不得改写既有定义(受治理、可回滚)。

## 四、装卸机制(两条腿)
1. **即需即装**:按触发器自动建议/装载能力——`onModulePresent`(项目里出现某模块时)、`onAction`(用户做某动作时)、`onIntent`(用户表达某意图时)。UI 用前端弹窗 + 向导引导。
2. **能力市场**:按 **行业 / 专业 / 场景** 三类**多值标签**组织检索(标签是检索维度,**不是**结构层级;用户天然跨场景)。条目 = 可装卸的模块/profile/视图/引擎。

## 五、治理底座(已落地,所有插件共享)
- **CQRS 读写分离**:命令 → event_outbox →(RabbitMQ)→ 投影 → rm_*(只读视图/零拷贝)。写经命令入口(KernelCommandService/MetaCommandService),视图只读。
- **乐观锁**:对象版本(`ObjectUpdated` 追平读模型)+ 每字段版本(`field_versions`,旧/重复事件不覆盖新值)。
- **派生 + 规则**:派生 fx 后端实时算;规则灯 BLOCK/WARN/OK,改一处即重算重判。
- **血缘 / 维度叠加 / 多重表达**:同一真值,多视图同步。
- **RBAC**:工作空间成员角色(VIEWER/AUTHOR/REVIEWER/ADMIN);**无成员=未治理=开放**(dev/新建项目即走此路)。
- **AI 上下文执行层**:5 类上下文 + AiActionProvider SPI,AI 产出经 CQRS+评审确认+RBAC 治理(受治理的写入者),context_hash 全覆盖可复核/回放/比对/回滚。

## 六、扩展点(SPI)与注册
- `ProfileLoader.install/uninstall`(声明式 `profile.manifest.json` 装卸)— 实现卡 F1。
- 模板版本生命周期 `withdraw/restore`(F0,F1 前置)。
- `DimensionRegistry`(维度叠加注册/注销,F4)、面板/视图 registry(F5)、图元控件调色板(F5b)。
- Exchange SPI(JSON/ReqIF/XMI)、Render SPI(Md/Docx/Pdf/Html/Xlsx/Csv)、Sim SPI、决策 MCDA、评审状态机。

## 七、首个领域插件:室内设计(参照实现)
- `packages/domains/interior-design`:`profile.manifest.json`(floorplan/room、字段、contains/adjacent、派生 area_fx/window_floor_ratio_fx、规则)+ `plugin.json` + `src/index.ts`(导出维度数据,web 侧注册)。
- 依赖矩阵:domain 只依赖 shared;web 可依赖 domain;**禁 web→domain 反向耦合之外的越界**(architecture/dependencies.json 守)。
- 端到端验证:装卸 E2E、dev 种样板户型、改一处全联动闭环。
