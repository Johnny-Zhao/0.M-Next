# M-Next 平台定位:多专业分析集线器

> 一页总纲。统领各域评估(能源、室内设计)、能力规划(fUML/Modelica/联邦)、OMG 评估。对外/立项时以此为准。

## 一句话定位

**M-Next 是统一数据驱动的多专业工程分析集线器(hub):收集各专业工具的数据、统一建模呈现、做单一工具做不到的跨专业综合分析与闭环校核。专业求解外挂,综合与追溯在平台。**

切忌说成"我们做采光/CFD/热/仿真/CAD"。我们**不做**这些,我们**集成并编排**这些。

## 三层逻辑(= 三个动词)

| 动词 | 平台层 | 实现 |
|---|---|---|
| **收集** | 集成适配器 | 各专业工具数据进来:交换适配器导入、外部求解器结果经**命令入口回灌 + provenance**(哪次 run、哪个工具、哪份输入快照) |
| **统一展示** | 统一模型 + 视图 | 一份数据、多种镜头:MOF 式 M2 元模型 + profile 承载各专业;视图 SDK(表/图/矩阵/文档)只读零拷贝呈现 |
| **综合分析** | 派生 / 规则 / 联邦 | 跨专业闭环:换个材料/选型→采光+热+成本一起重算;SysML→总线→带宽判超;派生/计算 + 规则校核 + M2M 投影 + correspondence 互引 |

## 定位必然:平台永不自研专业求解

每次能力缺口的答案都一样——**外接工具 + SimulationEngine SPI + 结果回灌**,从不是"自己造引擎":

- 采光/气流/热 → Radiance / CFD / EnergyPlus 外挂;
- fUML 执行 → 外接 EPL 引擎(进程外)挂 SPI,不自研 VM;
- Modelica 方程 → 外接求解器;几何 → 引用工件(IFC/glTF),不做 CAD 内核;
- 数值时序(SOC 等)→ 自研**轻量**算子(唯一例外:简单到无需外部库)。

这不是妥协,是定位的必然:跟单专业工具拼深度必输,hub 的护城河在别处。

## 护城河(重点投入)

1. **统一元模型 + 联邦(correspondence / M2M)+ 派生/规则** —— 单一工具给不了的"综合";平台价值 ≈ **接入专业数 × 跨专业连接密度**,资产是那张"一份数据、互引不互拷"的网。
2. **集成接缝**(SPI、适配器、快照进/结果回、provenance)—— hub 的命脉,做厚做稳。
3. **可追溯**(provenance)—— 跨专业结论可信的前提:每个回灌结果钉得住"哪个工具、哪份输入算的"。

## 两个真正的难点(不在"收集",在"统一"与"综合")

- **统一**:元模型要通用到能装下多专业、又不退化成一团浆糊——MOF 底座 + profile + 泛化/重定义/值类型在挣这个钱。
- **跨专业身份对齐(BL-11,人定)**:这台设备 = 那个 SysML block = 总线节点 = 热模型里的热源。**真集成 vs 只是把数据堆在一起,差别就在这条**。对齐做扎实,hub 才是 hub;做不扎实,只是个数据库。

## 边界(明确不做)

- 不做专业物理求解器(采光/CFD/热/结构…)、不做 CAD/几何内核、不做执行引擎(fUML VM)、不做中间件(CORBA/DDS 运行时)。
- 对外口径恒为:"**集成 + 编排 + 统一承载 X 的数据**",不为"实现 X / 通过 X 一致性认证"。

## 已验证的支撑(非空话)

- **能源分系统**(航天域):profile + 派生 + 规则,换选型→重算→报警,纯配置零生产代码闭环(v1.32 实测)。
- **联邦**:SysML→M2M→总线→派生→规则一条链贯通(v1.30)。
- **室内设计**(差异极大的第二域):评估显示同底座可承载(数据/流程/选材/估算 + 仿真编排),强证领域无关性。
- 两域同底座 = "统一数据驱动多专业集线器"不是 PPT,是已落地的能力。
