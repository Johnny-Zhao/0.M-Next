# 执行/计算引擎策略 spike(fUML + 数值时序)

状态:**已拍板(2026-06-19)**。四点决策全部采纳:①fUML 外接现成引擎、不自研 VM;②结构 profile 先行、执行后置;③引擎作独立进程(喂 snapshot/收 trace)、不内嵌;④对外口径"结构子集+挂载执行 SPI",不称"支持 fUML 执行/一致性"。不写代码,产出是路线决策。蓝本:OMG 评估 §5(执行语义=最大空白、第2插件)、能源可行性备忘"长板2"(SOC 时序)。

## 0. 问题陈述

平台目前能"建模 + 校核 + 标量派生",但**两类"算"还没引擎**:

- **A. 数值/时序计算**:能源 SOC 逐轨收支曲线、工况时间轴排程——标量代数之外的迭代/积分。
- **B. 行为执行语义**:fUML(可执行 UML 子集)、PSSM(状态机)、PSCS(组合结构)——模型"跑起来"。

两者都落在**"平台只编排、不亲自算"**的既有原则上(AG-107:server 不拼装仿真代码;AG-208:渲染/交换入参=snapshotId;已有 SimulationEngine SPI/L0)。本 spike 统一定这两类引擎**怎么挂**。

## 1. 统一接缝:SimulationEngine SPI(已存在)

两类引擎都走同一接缝,不新造写路径:

- **输入 = snapshotId**(只读快照,AG-208);引擎读快照、算、回**结果工件**(trace / 曲线 / 检查项),经命令入口落库(run 记录 + provenance),**不改源**(AG-105)。
- 引擎实现挂在 SPI 后(server 注入),**进程内**(轻量数值)或**进程外服务**(重引擎);server 不内联引擎逻辑(AG-107)。
- 已有 L0 雏形(SimulationRun + SPI),复用。

## 2. A 类:数值/时序计算引擎(能源 SOC 等)—— 自研、轻、可控

- 结论:**自研一个轻量数值算子引擎**(进程内,engines 域),输入快照 + 工况,输出时序结果(SOC 曲线、排程)。本质是定步长积分/简单调度,不涉外部库、不涉许可。
- 边界:有界步数/时长(AG-202/203 式上限);纯函数式、无副作用;结果作工件回写。
- 工作量:**中**,但**可控、无许可风险**,直接解锁能源详细模式。energy 阶段B 的 SOC 即此。

## 3. B 类:fUML 行为执行 —— 外接引擎挂 SPI,不自研 VM

三个选项:

| 选项 | 说明 | 评价 |
|---|---|---|
| 1. 自研 fUML 子集 VM | 在 engines 实现 fUML 语义子集 | **不推荐**:fUML 语义面大、一致性是无底洞,自研子集既重又难维护 |
| 2. 外接引擎挂 SimulationEngine SPI | 用成熟 fUML 引擎(如 Eclipse 的 fUML 参考实现/Moka,**EPL 许可**),**进程外**跑,喂 snapshot/取执行 trace | **推荐**:最快拿到"可执行模型"能力;平台只编排 |
| 3. 仅结构 profile,执行后置 | 先把 activity/状态机建成数据(profile),不执行 | 过渡态:广度先行,执行能力留 SPI 挂点 |

- **许可澄清**:ADR-008/AG-502 允许的 license 含 **EPL**——所以 EPL 的 fUML 参考实现**不违禁**;"门"在于走 ADR 准入 + **进程外集成**(避免把重引擎/其依赖塞进内核,AG-506/507),不是许可禁止。
- **推荐路线**:**选项 3 → 选项 2**。先上 fUML **结构 profile**(activity/object/control flow 建成 M2 数据,可被联邦/视图用),把执行作为**外接引擎(进程外、EPL、挂 SPI)**的后续卡;**不自研 VM**。PSSM/PSCS 更靠后(研究级)。

## 4. 待你拍板的决策点

1. **fUML 执行**:认同"外接引擎挂 SPI、不自研 VM"吗?(影响第2插件形态)
2. **结构先行**:是否先做 fUML 结构 profile(选项3),执行作为独立后续卡?
3. **进程外集成**:接受 fUML 引擎作为**独立服务/进程**(平台喂 snapshot、收 trace),而非内嵌依赖?(符合 AG-107/506)
4. **对外口径**:执行能力达成前,统一说"支持 fUML **结构建模子集 + 挂载执行 SPI**",不说"支持 fUML 执行/一致性"。

## 5. 对其它线的影响

- **energy 阶段B**:SOC = A 类自研轻引擎,**不依赖 fUML 决策**,可立即排卡。
- **第2插件(仿真)**:= fUML 结构 profile(选项3,近期)+ 外接执行引擎(选项2,中期)。
- **契约**:A 类(数值算子运行命令)与 B 类(fUML 结构 profile + 执行命令)各需契约 addendum(人发起),实现卡分别拆。
