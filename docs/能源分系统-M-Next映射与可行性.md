# 卫星能源分系统方案设计工具 → M-Next 映射与可行性评估

- 评估日期:2026-06-19。基于 M-Next 当前 main(至 v1.29:M2 元模型/泛化/值类型、规则、派生/计算层、模板生命周期、SysML/总线 profile、联邦 M2M 已就位)。
- 依据:用户提供的《能源分系统设计工具_原型册》15 屏功能描述。
- 口径:逐能力标注承载方式——【配置】profile/字段/关系定义即可;【派生】派生/计算层;【规则】规则校核;【视图】视图 SDK(表/图/文档/矩阵,只读);【输出】快照→渲染/导出;【扩展·算子】需 engines 小幅扩展;【app·UI】需应用层定制前端。

## 0. 结论

**内核可行性高。** 这套工具的"工程内核"——数据模型 + 闭环核算 + 约束报警 + 选型复算 + BOM/报告/导出——直接落在 M-Next 已验证能力上,且**大部分是定义 profile/派生/规则,而非写引擎代码**。把"能源分系统"做成一个**模板 profile**,`InstantiateWorkspace` 开一个项目 = 一套方案,正是平台"用 profile 定制成领域工具"的标准路径。

真正的额外投入集中在**四块长板**(§2),都是**有明确边界的增量**,挂在已就绪的 SPI/扩展点上,**不动底座**:产品级 15 屏 UI、时序数值计算(SOC 曲线/排程)、查表插值、选型推荐。

## 2. 四块长板拆解(扩展点 + 工作量量级)

### 长板 1:产品级 15 屏桌面 UI 【最大头】
- 现状:平台给通用视图 SDK(表/图/文档/矩阵,只读零拷贝),够撑产品库表、BOM 表、拓扑/RBD 图、报告。
- 缺:工作台 chrome、四阶段流程导航、右侧实时面板 + 报警灯、SOC 曲线 chart、时间轴甘特、可拖拽拓扑编辑。
- 扩展点:应用层前端(与底座 REST/视图端点解耦)。
- 量级:**中–大**(数人月级前端),但**可后置、可分期**——先用通用视图把闭环跑通,再逐屏升级成工作台体验。

### 长板 2:时序/数值计算(SOC 收支曲线、时间轴排程)【中】
- 缺:逐轨时间步积分(SOC)、工况时间轴排程——超出派生层(标量代数/聚合)。
- 扩展点:**挂 SimulationEngine SPI**,实现一个"能源时序计算器"插件(输入快照→输出曲线/排程结果),走 AG-107/AG-208(输入 = snapshotId)。
- 量级:**中**(一个专项算子 + 其契约),独立插件,不动底座。

### 长板 3:查表 / 插值(DOD-循环、温度/辐照衰减曲线)【小】
- 缺:规则/派生 DSL 无 interp/lookup 函数。
- 扩展点:engines/rules **加 `lookup`/`interp` 函数**(有界);曲线/表数据用 value_type 或专表承载。
- 量级:**小**(DSL 小幅扩展 + 契约 addendum)。

### 长板 4:选型推荐算法【小–中】
- 缺:"推荐 + 备选"的匹配/排序逻辑。
- 扩展点:规则驱动过滤 + 排序(轻);或一个小推荐算子(重一点)。替换后复算靠派生,天然成立。
- 量级:**小–中**。

## 3. 立项建议(分期,先验证后投入)

- **阶段 A — 底座验证(低风险、高价值,几乎不写引擎)**:定义"能源分系统"profile(全部对象/字段/关系)+ 标量派生(面积/容量/质量/裕度/成本/可靠度串并联)+ 规则报警 + 通用视图(表/图)+ 快照报告/JSON。**用现有能力即可跑通"输入→核算→校核→出件"闭环**,实证可行性。
- **阶段 B — 专项算子**:插值查表(小)→ 选型推荐(小–中)→ SOC 时序/排程算子(中,挂 SimulationEngine SPI)。每项独立、有界、不动底座。
- **阶段 C — 产品 UI**:逐屏定制前端,把通用视图升级为工作台体验(实时面板/曲线/甘特/拖拽拓扑)。

分期的意义:**阶段 A 先把工程内核焊通、证明闭环成立**,再决定在 UI 和算子上投多少——风险前移、投入后置。

## 4. 与平台战略的契合

能源工具 = 同一底座上的又一个 **profile/插件**,与 SysML/总线 profile 同构;其"设备"还能经联邦(correspondence + M2M)与 SysML block、总线节点互引互转。**这是比抽象 OMG 规范更有说服力的平台验证案例**——它直接兑现"统一数据底座 → 定制成具体领域正向设计工具"的产品主张。
