# 设计稿(定调):室内设计 profile —— 全集愿景 + 三层映射 + 分期路线 + 「选→配→实例化」

> 产品负责人已定调:**采纳完整 13 模块规格作为室内设计 profile 的北极星愿景**(从户型输入 → 功能区 → 风格 → 选材 → 水电暖通 → 风/热/光分析 → 硬装软装 → 智能家居 → 报价/施工图全流程打通)。
> 本稿:① 把 13 模块映射到 M-Next 三层(数据层 kernel / 引擎层 engines / 表现层 views),标清**已建 vs 新建**;② 定义首批可实例化的 **v1 数据底座**;③ 给出覆盖全部模块的**分期卡路线**;④ 锁定「选 profile → 配置 → 实例化 → 进工作台」流程(走真 `/views/templates` 端点)。
> 性质:profile = **元模型配置**(tpl-api:建模板→定义类型/字段/关系/规则→发布→实例化),不改内核契约;新增分析能力 = **新 engine(人发起,过 AG-502/契约门禁)**。参照已有 `EnergyProfileE2E` / `BusProfileE2E`。

---

## 0. 一句话:13 模块 = 同一底座上的 objects + relations + rules + 派生 + 维度 + 推荐

你的规格里自带的 **数据层 / 引擎层 / 表现层** 几乎 1:1 落在 M-Next:

| 你的规格 | M-Next 落点 | 含义 |
|---|---|---|
| 数据层(房间/墙/门窗/家具/材料/灯具/管线/电路/设备/场景/预算项/施工节点) | **kernel 对象类型 + 关系**(经 profile 定义) | 一切皆受治理的对象,画=发命令改对象,互引不互拷 |
| 引擎层(建模/规划/风格/选材/光照/通风/热/碰撞/报价/智能家居) | **engines**(派生 fx / 规则 / 推荐 已建;其余新建 engine) | 真值的计算与校验 |
| 表现层(2D/3D/材料面板/家具库/管线图层/分析报告/施工图/报价单) | **views + 工作台面板**(可停靠) | 同一真值的多重表达,最小常驻+渐进展开 |

**结论**:室内设计不是要做一个新产品,而是 M-Next 底座上**最丰满的一个 profile**——正好把"领域工具 = 同一底座 + profile"讲透。

## 1. 13 模块 × 三层映射(已建 ✅ / 复用现有模式 ◻ / 新建 engine ★)

|---|---|---|---|---|

| 8 | **水管设计** | `pipe`(给水/排水/热水回水)、用水点、地漏;与墙/柜冲突 | **碰撞检测 engine ★**(水管穿承重墙/坡度不足) | 管线图层、碰撞清单 |
| 9 | **暖通 HVAC** | `hvac_device`(地暖/暖气片/空调内外机/新风)、`duct` 风管/冷媒管 | 选型/检修空间/噪音 ★;吊顶高度影响 | 暖通图层 |
| 10 | **电走线** | `circuit` 回路(强/弱电)、`outlet`/`switch`/`fixture` 点位、配电箱 | 负载估算 ◻、水电避让(碰撞)★;"大功率独立回路 WARN" | 强弱电图层、放样图 |
| 11 | **硬装** | `hardscape`(拆改/吊顶/地面/墙面/定制柜/防水) | 工程量统计 = 派生 ◻ | 平面/天花/地铺/立面/节点图导出 |

## 2. v1 数据底座(首批可实例化,本批 seed 卡的范围)

v1 = **所有模块挂载的数据骨架 + 已建引擎能即刻演的部分**。一张 E2E seed 即可让用户走完 选→配→实例化→进工作台→画→看派生/规则灯/维度。

### 类型(object types)
- **`floorplan` 户型(根)**:`name`、`floor`(楼层);派生 `total_area_fx`(=Σ 房间面积)。
- **`room` 房间**:`name`、`usage`(枚举:卧室/客厅/厨房/卫生间/书房)、`length_m`、`width_m`、`orientation`(N/S/E/W)、`window_area_m2`。
  - **派生 fx**:`area_fx`(=length×width)、`window_floor_ratio_fx`(=window_area/area)。
  - **风/热/光维度字段**(命名约定对齐前端 `dimensions.ts`):
    - 光 `light_*`:`light_df`(采光系数%)、`light_illuminance`(照度 lx);
    - 热 `thermal_*`:`thermal_temp`(设计温度℃)、`thermal_u`(U 值)、`thermal_load`(能耗);
    - 风 `wind_*`:`wind_ach`(换气次数 ACH)。
- **`wall` 墙(可选,简化版可省)**:`bearing`(承重/非承重)、`length_m`。
- **`opening` 门窗(可选)**:`kind`(门/窗)、`area_m2`。

### 关系(relations)
- **`contains`**:floorplan → room。
- **`adjacent`**:room ↔ room(相邻,供风/热传递、动线与一致性用)。

### 规则(规则灯 BLOCK/WARN —— 接 RULE-A)
- **`R-LIGHT-01` 采光达标**:`light_df < 2` → **BLOCK**(暗区)。
- **`R-LIGHT-02` 窗地比**:`window_floor_ratio_fx < 0.14`(≈1/7)→ **WARN**。
- **`R-WIND-01` 通风**:`wind_ach < 1.0` → **WARN**。
- **`R-THERMAL-01` 温度裕度**:`thermal_temp` 越出 [18,26] → **WARN**。
- **`R-SPACE-01` 通道宽度(可选,演空间冲突)**:相邻通行间距 < 0.6m → **WARN**。

> 画一套户型后:房间节点显 `area_fx`/`窗地比` 派生芯片 + **规则灯**(暗区红 BLOCK、通风不足橙 WARN);切**维度 风/热/光**换叠加;护照显**来源/新鲜度**(PROV-A);点派生看**血缘**(LINEAGE-B)。一个领域把整条链全演出来。

> 阈值与枚举取自常见住宅标准的工程近似值;非合规结论,正式标准(GB 采光/通风/热工)后续校准——见 §4 跟进。

## 3. 分期路线(覆盖全部 13 模块,逐批成卡)

> 原则:每批 = 数据(profile 配置卡)+(如需)新 engine(人发起契约卡)+ 前端面板卡。先底座、再分析、再出图/报价、最后 3D/智能联动。

- **P1 · 数据底座 + 风热光(本批,现在做)**:§2 模型。① profile seed(后端)+ ② `dimensions.ts` 扩风/光(前端)+ ③ `/views/templates` 端点(后端,支撑「选 profile」)。
- **P2 · 功能区 + 选材**:`circulation`/成员画像 + 自动分区(=BID 比选复用)+ 空间冲突规则;`material` 库 + 选材规则。
- **P3 · 风格 + 软装**:`style` 五维风格板(维度轴复用)+ 风格/材料**推荐 engine**(★)+ `furnishing` 与预算联动。
- **P4 · 水电暖通**:`pipe`/`hvac_device`/`duct`/`circuit` + **碰撞检测 engine**(★,最重)+ 水电避让/坡度/独立回路规则。
- **P5 · 硬装出图 + 报价**:`hardscape` + 工程量派生 + 立面/天花/地铺/节点图导出 + `budget_item` + **报价 engine**(★)。
- **P6 · 智能家居 + 3D**:`smart_device`/`sensor`/`scene` + 场景自动化(规则/关系)+ 3D 实时预览面板 + CAD/PDF 识别导入(★)。

> 每个 ★ engine 落地前单独发**契约/依赖确认卡**(AG-502:不擅自引第三方几何/能耗库;开源可 fork 才入)。

## 4. 「选 profile → 配置 → 实例化 → 进工作台」流程(已定走真端点)

1. **HOME 新建向导 · 步骤2 选插件**:`/views/templates`(本批卡③)**真列已发布模板**——卡片:名称 + 简介 + 类型概览;选 **室内设计**。
2. **步骤3 配置**:项目名 + 默认值/可选项(采光阈值 `light_df` 默认 2%、楼层数、可选邀请成员 + RBAC 角色)。作为实例化参数 / 默认字段值。
3. **实例化**:tpl-api **Instantiate** 从"室内设计"模板建工作空间(类型/字段/关系/规则随模板带入)。
4. **进工作台**:控件库出 `户型/房间/墙/门窗` stencil;拖建房间(=命令建对象)、连 `adjacent`(=建关系);改长宽 → `area_fx`/窗地比即重算;采光不足 → 规则灯红;切风/热/光维度叠加。

> **演示价值**:这条 选→配→实例化 正是"领域工具 = 同一底座 + profile",且把 P1/规则灯/派生/维度/provenance 全用上。后续 P2–P6 模块在同一向导里勾选启用,逐步丰满成你规格里的全流程产品。

## 5. 实现注记(本批落地)
- **`dimensions.ts` 扩两维**:p3c 现配 能量/热/质量(卫星);室内设计加 **光(light_)/风(wind_)**,热复用。命名约定临时,注释标清待元模型 `dimension` 标签替换(见视图API设计稿 ③-正式)。
- **`/views/templates`**:只读列已发布模板;若取列表需改契约才能拿到 → 停下回报、不夹带(同 PROV-A/LINEAGE 的处理)。
- **新 engine(P3+ 的 ★)**:逐个人发起,过 AG-502;基础版优先用**规则引擎/派生**近似(如热/通/光先做规则灯),重型(碰撞/3D/能耗/CAD识别)后置且单独定调。
