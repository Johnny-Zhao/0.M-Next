# M-Next:制图工作台(产品定稿 · 北极星 + Claude Design 提示词)

> 本文是产品定位的**定稿**,合并并取代此前散落的几份(`北极星-统一真值的多重表达.md`、`平台UI-表达切换台-ClaudeDesign-v2.md`、`平台UI-维度轴单屏-ClaudeDesign.md`)的方向部分——它们的"统一真值多重表达""模型优先"都对,但没说清本质:**M-Next 是一个数据驱动的可停靠制图工作台**。既作产品北极星,也作 Claude Design 的整体提示词。

---

## 0. 一句话定位

**M-Next = 一个数据驱动的可停靠制图工作台(dockable diagramming workbench)。**
中央是可编辑的图(= 治理模型的视图,画图 = 发命令改对象);文本、2D 图、3D 模型、表、模型树、控件库、校验、分析**都是可移动 / 浮动 / 停靠的面板**;支持模板导入与图↔文本(AI 双向);**同一份真值的多种表达可并排并存、实时联动**,改一处全场重算。

类比:**draw.io / Visio 的画布 + VS Code 的可停靠面板 + Mermaid 的图↔文本 + 城市天际线的"建即见后果"**,但每个图元背后都是一个**带类型 / 字段 / 派生 / 规则的治理对象**。

---

## 1. 灵魂(保命点):图是治理模型的"可编辑视图",不是死图

这条定了,产品才不会退化成"又一个 draw.io":

- 在画布上**画一个图元 = 发一条命令,创建一个带类型 / 字段 / 派生 / 规则的对象**;连一根线 = 建一条关系;改属性 = 改字段(经命令、留版本与审计)。
- **底层真值只有一份**;2D 图、3D 模型、文本、表都是它的**表达(视图),互引不互拷**。
- 因此"切视图 / 开面板"从不复制数据,只是换一种方式表达同一份真值;改任一表达 → 经命令 → 派生 / 规则 / 其它表达**全场重算**。

> 一句话:**draw.io 画的是图;M-Next 画的是模型,图只是它此刻的一张脸。**

---

## 2. 可停靠面板系统(一切皆面板)

没有"主画布 + 配角",**所有东西都是平等的、可移动 / 浮动 / 停靠的面板**(参考 VS Code / Visual Studio / golden-layout / dockview docking):

- **2D 图面板**(拓扑 / 框图 / 平面图 / 流程,可编辑)
- **3D 模型面板**(几何 / 装配 / 空间布局)
- **文本面板**(Mermaid / DSL,图↔文本 AI 双向)
- **表面板**(对象 / 字段 / 派生值)
- **模型树面板**(层级)
- **控件库面板**(stencil / 图元调色板,拖到画布 = 建对象)
- **校验面板**(规则结果 BLOCK / WARN)
- **分析面板**(引擎:SOC 仿真 / 决策方法 / 质量预算)

面板可拖动标题栏换位、并排、上下分割、浮出、隐藏。布局可存为工作区预设(profile 可带默认布局)。

---

## 3. 多视图并存(2D + 3D + 文本 同时在场)

这是"统一真值的多重表达"在 UI 上的最终形态——**不是"切换",是"并存"**:

- 你可以**同时打开** 2D 拓扑图 + 3D 装配模型 + Mermaid 文本 + 派生表,四个面板并排;
- 它们**全部联动到同一份真值**:在 3D 里选中蓄电池 → 2D 图、文本、表里同步高亮;改文本里一条边 → 2D 图与 3D 关系同步变;
- 表达之间若对不上(如 2D 标 120W、3D 仿真 135W)→ **一致性裂缝**当场亮出(见 §5 第 4 回路)。

---

## 3bis. 最小常驻 + 渐进式展开(交互总原则)

**常驻可见的只有画布 + 最小框架**(顶栏、状态栏、当前关注的少数面板)。**凡是会随 profile/插件增长的东西——视图类型、分析引擎、导出格式、控件库/模板、推荐方法、可开面板……一律做成"入口 → 展开后选择/导航/操作"**,不常驻平铺。

- **理由**:这些项的数量随插件膨胀,平铺工具条既不可扩展、又淹没画布。
- **手段**:① 顶栏少量入口(`视图▾` / `分析▾` / `导出▾` / `+面板▾`);② **⌘K 命令面板**作为到达一切功能的通用入口;③ dockview 面板**按需打开/停靠/隐藏**,不默认全摆出来。
- **给 Design 的硬要求**:**不要把可扩展项摊平成常驻工具条**;要画"入口 + 展开态(菜单/浮层/按需面板)",并标注"列表随插件增减"。

## 4. 三根表达轴 = 面板与叠加(承接原"多重表达")

同一真值沿三轴表达,在工作台里分别落为"开不同面板"或"在面板上换叠加":

- **语言轴**(SysML / Modelica / Excel / 3D / 文本):**开不同表达面板**;翻译可能有损,需往返对账;入向适配已有(sysml/reqif/json),双向/Modelica 为后续(标"预览/待接入")。
- **阶段轴**(方案 / 初样 / 正样):同一实体跨阶段,**面板内切阶段或并排 diff**;细化累加,留血缘链。
- **维度轴**(能量 / 热 / 质量;风 / 热 / 光):**在同一模型面板上换叠加图层**——像《城市天际线》信息视图,模型不动,只重绘热力 / 流线 / 着色;无损、瞬时。

---

## 5. 核心操作回路(产品的"操作",四个已做成可点原型)

制图工具的操作就是**画 + 调 + 摆 + 切**,每个动作都有即时后果。四个核心回路(均已有可交互原型,可导出 HTML 作开发参照):

1. **改值即重算**:改字段 / 选型 → 派生(如能量余量)实时重算 → 规则灯在 BLOCK/WARN/达标 翻转 → 下游校核同步变。
2. **调权重即改排名**(比选):拖指标权重 → 候选综合分实时重排;一票否决命中者置灰删除线、淘汰、不进推荐;权重合计 ≠100% 阻断确认。
3. **维度信息视图叠加**:点 维度按钮 → 同一模型上的叠加图层当场切换(风/热/光、能量/热/质量),数据退为图例 + 悬停。
4. **切表达看一致性**:并排两种表达 → 对不上处亮裂缝 + 差值 → 判别"真不一致(设计未收敛)vs 口径误差" → 一键发起校核 / 重投影。

> 共同特征:**有输入控件、有即时后果、模型为主数据为叠加**——这正是静态稿一直缺的"操作"。

---

## 6. 模板导入 + 图↔文本(AI 双向)

- **模板 / stencil 导入**:每个领域 = 一套 profile = 类型/字段/关系/规则/图元库/默认布局。导入 Visio(.vsdx)/ draw.io XML / 自有 stencil → 实例化一个工作空间。
- **图↔文本互转**:文本面板用 Mermaid 语法或自有 DSL;**AI 双向**——自然语言 / 文本 → 生成图(建对象与关系),图 → 反生成文本;转换走命令入口,受规则与治理约束。

---

## 7. 校验 + 分析(活面板)

- **校验面板**:规则实时结果,BLOCK(阻断,红)/ WARN(告警,橙);点进看命中条件 / 阈值 / 触发字段 / provenance。
- **分析面板**:外接 / 内置引擎(SOC 仿真曲线、决策方法 TOPSIS/AHP/WPM、质量预算);跑完结果回灌模型、落运行记录、可视化(曲线 / 雷达 / 柱状 / 热力)。

---

## 8. 与现有架构的映射(后端基本就绪,前端换中央件)

| 工作台概念 | 平台已有 |
|---|---|
| 图元 / 连线 / 编辑 | 对象 / 关系 / 命令(CQRS,经命令入口、留审计版本) |
| 模板 / stencil | profile(领域模板,可存复用) |
| 图 ↔ 文本 / 跨语言 | ExchangeAdapter(sysml/reqif/json)+ AI |
| 多视图 / 表达轴 | 五镜头(树/表/图/矩阵/文档)→ 升级为可编辑、可停靠面板 |
| 派生值 fx | 后端实时派生求值 |
| 校验面板 | 规则(BLOCK/WARN,跑检查批次) |
| 分析面板 | 引擎(energy-soc / decision-topsis/ahp/wpm) |
| 改即重算 | 命令热路径 → 派生/规则重算 → 投影 |
| 多源进水口 | 导入(Excel)+ Exchange 适配 |
| AI 守门人 | AI 治理变更集(propose→confirm,不直接写) |

**结论:数据脊柱已就位。真正要换的是前端中央件**——从现在只读的"五镜头 SDK",换成**可编辑图编辑引擎 + 可停靠布局系统**(见 §11 待拍板)。

## 9. 视觉风格 + 设计令牌

- **整体风格:模型优先,数据作叠加**;干净、专业工具感、可停靠工作区。
- **令牌由 Claude Design 设计**,基调走**现代 Microsoft Office / Fluent("Office 2026"方向)**:明亮、柔和材质、适度圆角、留白、单一强调色 + 中性灰阶;桌面高密度但不拥挤。无需固定 hex。
- 硬约束:语义色四态可辨(达标/WARN/BLOCK/陈旧·有损)且**色彩非唯一信息载体**;派生值统一标记(fx);否决态灰+删除线;代码/单位/方程用等宽;**亮/暗双主题**;模型画布的物理热力叠加用物理色带(不随主题反相),框架随主题。

---

## 10. 给 Claude Design 的任务(整体提示词)

你是资深产品设计师。为「M-Next 数据驱动制图工作台」设计**完整 UI**:可停靠工作区外壳、面板系统、关键面板高保真、操作交互、全状态、handoff。**桌面优先,中文,亮/暗双主题,令牌自定(Office/Fluent 方向)。**

**必须贯穿**:① 一切皆可移动/浮动/停靠面板;② 中央图可编辑,画=改模型(非死图);③ 2D+3D+文本多表达并存联动;④ 操作即时见后果(改即重算/调权重/切叠加/亮裂缝);⑤ 模型优先、数据作叠加。

**关键屏 / 面板(线框→高保真)**:
1. **可停靠工作台外壳**:面板拖拽/停靠/浮动/隐藏/分割;工作区预设;顶栏(工作空间/profile、命令面板 ⌘K、编辑模式、用户);命令面板驱动写操作。
2. **2D 图编辑面板**:控件库拖建图元、连线、选中编辑、对齐/网格;图元带派生 fx 与规则灯叠加;**编辑=发命令**的反馈(乐观更新 + recomputing)。
3. **3D 模型面板**:几何/装配;选中联动;维度叠加(着色/热力)。
4. **文本面板**:Mermaid/DSL,图↔文本 AI 双向,差异高亮。
5. **多视图并存布局**:2D+3D+文本+表四面板并排、同选联动、跨表达一致性裂缝。
6. **校验面板** / **分析面板**(含 SOC 曲线/雷达/排名图)。
7. **比选评分工作台**:权重→排名实时、一票否决置灰、100% 校验条、雷达+排名+推荐+风险。
8. **模板/导入**:stencil 库、Visio/draw.io/Excel 导入向导(校验+列映射+行级错误)。
9. **AI 守门人/变更集确认**:propose→人 confirm(不直接写)。

**操作交互**(务必有输入控件 + before/after):改即重算、调权重改排名、维度叠加切换、一致性判别(真不一致 vs 口径误差)、拖拽建图元、图↔文本、面板拖停。

**状态**:default / loading(骨架)/ empty(引导)/ error(可重试)/ recomputing / blocked / inconsistent(裂缝)/ stale(陈旧·有损)/ conflict / not-implemented(出向/3D 双向待接入)。

**交付**:面板系统与停靠规范、令牌(自定 Office 方向)、组件库(图元/连线/控件库/派生芯片/规则灯/裂缝/provenance/命令面板/图表/导入向导/AI 变更条/面板 chrome)、关键面板高保真、全状态、handoff。

**落地优先级**:P1 可停靠外壳 + 2D 图编辑面板(改即重算)+ 维度叠加 + 校验面板;P2 多视图并存(2D+3D+文本)+ 一致性 + 分析/比选;P3 模板导入 + AI 守门人 + 阶段/语言轴双向 + 3D 高级。

## 11. 待拍板的关键决策(实现层,可稍后定)

1. **图编辑引擎**:draw.io 的 mxGraph(成熟、偏老)/ tldraw(现代手感)/ React Flow(节点图轻量)/ JointJS / GoJS(工程图强,GoJS 商业授权)。影响一切,需权衡能力与授权(注意 AG-502 依赖与许可)。
2. **可停靠布局库**:golden-layout / dockview / rc-dock / FlexLayout 一类。
3. **模板/stencil 格式**:导 Visio .vsdx / draw.io XML / 自有 = profile stencil。
4. **文本 DSL**:直接用 Mermaid,还是自有 DSL;AI 双向到什么程度。
5. **3D 来源**:已有几何导入 vs 平台内建;3D ↔ 数据的绑定粒度。

> 这些是实现决策;选型可在定位定稿后,由我做一份授权/能力对比再拍。

## 12. 治理红线(本定位下依然成立)

- **互引不互拷**:多表达是视图/投影,底下同一份真值。
- **写一律经命令入口**(画/改/连/导入/AI 都是命令),留审计与版本;视图/面板只读取。
- **AI 不直接写**:AI 角色 = 图↔文本生成器 + 表达一致性守门人;一切以可审查变更集提议,人确认后经命令落库。
- **契约/模式/迁移人发起**;新依赖(图引擎/docking 库)走依赖与授权评审(AG-502)。
