# M-Next 补全路线图 — 第二阶段后端(UI 之后)

- 基线:main = v1.41(数据中心化主链已闭环,见《技术说明书V3.3-覆盖度评估》)。
- 范围:覆盖度评估指出的 7 个未建大块,排成 Now / Next / Later。
- 原则:① 每块仍走"设计稿 → 人确认契约 → 封闭卡发 Codex"既有纪律;② 对齐说明书 §7.15.3(重型转换/联合仿真/全量求解不入主链路、标准适配走插件、AI 可后置);③ 优先解锁"可演示的多用户端到端闭环",高级/部署相关能力按域按需。

---

## NOW(与 UI 并行 / 紧接,解锁"多用户 + 项目级可演示")

### N1. 扩展视图首批:看板(Kanban)+ 甘特(Gantt)
- **为什么先做**:项目/任务管理是最常见、最直观的演示场景;二者是**纯前端插件**挂在现成数据 + 视图 SDK 上,无新后端契约。
- **依赖**:现有对象/字段(状态、起止日期、负责人)+ 五镜头 SDK + 选择联动。
- **量级**:中(前端为主);后端零或极小(可能补 1-2 个派生/排序读端点)。
- **触发**:随 UI 落地一起做。

### N2. RBAC / 权限 MVP(用户 · 角色 · 工作空间级授权)
- **为什么先做**:审阅、协同、资产审核、AI 确认**全都假定有身份与角色**;目前只有 `X-Actor-Id`。这是真正多人部署的前置。
- **范围(MVP)**:用户/角色表 + 工作空间级 RBAC(读/写/评审/管理四档)+ 命令入口鉴权 + 审计带角色;**SSO/组织树/字段级锁押后**。
- **依赖**:命令入口(✅)、审计(✅)。**是 AI 执行层确认权限、资产审核发布的前置。**
- **量级**:中。**契约改动(命令头/鉴权)= 人发起,先出设计稿。**

---

## NEXT(主链增值,强化"数据驱动 + 复用")

### X1. AI 上下文执行层 MVP
- **价值**:平台叫"数据驱动 + AI",这是名义核心能力;且**能复用现成 CQRS + 评审/确认**基础设施。
- **范围(MVP)**:`选择范围 → 组装三类上下文(对话/工作/流程)→ AI 执行 1-2 个动作(先"补全"+"解释检查结果")→ 生成 AI 变更集 → 规则/权限预检 → 用户对比确认/驳回 → 写入正式数据 → 增量检查 → 审计`。**AI 变更集 = 一种待确认命令批**,挂在现有 review/确认链上。
- **依赖**:RBAC(N2,确认权限)、规则(✅)、派生(✅)、事件(✅)。
- **量级**:大(分多卡:变更集模型 → 上下文装配 → 预检确认链 → 首个动作)。**先出设计稿定边界。**
- **红线**:AI 不绕过规则/权限/版本/确认(§3.4)。

### X2. 多源获取:Office 结构化抽取(Excel/Word → 对象/字段/关系)
- **价值**:直击"替代 Office 文件式工作"——把 Excel 表 / Word 结构化块导入为统一数据。
- **范围**:Excel(POI 已在依赖)行→对象、列→字段、跨表引用→关系;Word 结构化块→对象 + 数据引用。走**交换适配器 SPI**(与 ReqIF/XMI 同模式),三级解析(登记→元数据→深解析)。
- **依赖**:交换 SPI(✅)、POI(✅,无新依赖)。
- **量级**:中。外部系统(OA/CRM/PLM/ERP)、DB/API 直连押 Later。

### X3. BI 视图 + 通用图表视图类型
- **价值**:聚合/趋势/对比分析的通用呈现;把比选 UI 里的雷达/柱状/曲线泛化成"chart 视图类型"。
- **范围**:通用 chart 视图(柱/线/雷达/饼/热力)+ 聚合查询读端点(只读、有界)。
- **依赖**:视图 SDK、派生、读模型。
- **量级**:中(前端为主 + 1 个聚合读端点)。

## LATER(按业务域 / 插件,on-demand;多为部署相关或重型)

### L1. PLE 特性驱动复用 + 资产沉淀
- 特性库 / 资产库 / 分级(个人→标准)/ 匹配 / 可变项 / 复用差异 / 审核发布 / 废止。大子系统,经验复用长期价值高,但近期演示收益低。**先做最小资产库(把模板 + 派生 + 规则打包成可复用资产)。**

### L2. 动态 / 性能 / 联合仿真与调度器
- 主步长/子步长/同步点/状态保存/回滚/分支 + FMU/Modelica + 动画回放。**说明书明确"联合仿真不入主链路、走插件"(§7.15.3)。** 按具体工程域(如能源阶段B、机械)以插件形式挂 SimulationEngine SPI;现有数值仿真 + 决策方法已够比选/能源演示。

### L3. 扩展制品适配器 + 双向同步
- STEP / Modelica / FMU / 代码 / SQL / API + 回写·对比·同步。**SPI 已在**,按域逐个加适配器(能源→Modelica、机械→STEP);双向回写同步作为各适配器的进阶能力。

### L4. 其余扩展视图 + 外部集成
- 三维构型 / Map / 白板 / 表单 / 仿真回放视图;OA/CRM/PLM/ALM/ERP 连接器;SSO/组织树/字段级锁。**多为部署/行业相关,随客户需求拉起。**

## 里程碑建议
- **M-UI**:主链前端(五镜头壳 + 比选样例)+ N1 看板/甘特 → 第一个可演示的"数据中心化办公"闭环。
- **M-多用户**:N2 RBAC MVP → 真多人协同/审阅可用。
- **M-AI**:X1 AI 执行层 MVP → 名义核心能力落地。
- **M-导入**:X2 Office 抽取 → "替代 Office"叙事闭环。
- 之后按业务域拉 Later 各块(每块设计稿先行)。
