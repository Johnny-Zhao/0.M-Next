## 1. 结论先行

| 页签 | 数据来源 | 缺口 | 结论 |
|---|---|---|---|
| 属性 | `GET .../views/objects/{id}`(已有 `ObjectDetail`)+ `objectTypes` | 无 | **已具备**,纯前端换肤(已在上一轮完成密排样式) |
| 版本 · 护照 | 身份取自 `ObjectDetail`;来源链取自**新历史读模型**的里程碑切片;字段血缘复用已有 `lineage` | 依赖历史读模型 | **组合可得**,前端组装,不需要第二个端点 |

一句话:**历史与来源链的服务端真值早已存在于内核事件流里**(每条 `FieldChanged/StateChanged/RelationCreated/...` 都带 `before/after/actor/source/occurredAt/version/correlationId`),只是读侧还没把它按对象聚合成时间线。补齐这一条投影,历史与护照两页签一起解锁。

## 2. 现状盘点(数据从哪来)

**写侧 → 事件流(已存在)。** 所有主数据写经唯一命令入口,事务内写 `event_outbox`,经 Outbox → RabbitMQ 投递(契约 §1/§7)。统一事件信封(契约 §4.1)携带历史/护照所需的**全部**字段:

```
eventId, eventType, workspaceId, targetType, targetId, version,
before, after, actor{kind,id,display}, source, occurredAt,
correlationId, causationId, sequence
```

事件类型(契约 §2 / §4.2):`ObjectCreated`、`FieldChanged`、`ObjectUpdated`、`StateChanged`、`RelationCreated/Updated/Unlinked`、`Archived`、`SoftDeleted`、`AIChangeSetConfirmed`、以及外部同信封的 `CommentAdded`、`ReviewDecision`、`CheckCompleted`、`SimulationCompleted`。

**读侧 → 投影链(已存在)。**
- `packages/server/.../ReadModelRabbitListener.java` 订阅事件;
- `packages/server/.../ReadModelProjection.java` 按 `event.eventType()` 分派投影(现已处理 `ObjectCreated / FieldChanged / StateChanged / Archived / SoftDeleted / Relation* / ObjectUpdated / Batch*`);
- `packages/server/.../ReadModelRepository.java` 用 **Postgres(JdbcTemplate)** 存/查,读模型表前缀 `rm_`(`rm_object`、`rm_relation`、`rm_object_source`…);Flyway 迁移 `V{n}__*.sql`,当前至 `V20`;
- `packages/server/.../ViewQueryController.java` 暴露 `GET /workspaces/{id}/views/objects/{objectId}` 等端点;
- 前端 `packages/views/src/api/view-client.ts` 打这些端点。现有读能力:`object()`、`lineage()`(字段级血缘)、`simRuns()/simSeries()`(仿真时序)、`captureSnapshot/listSnapshots/getSnapshot`、`checkResults()`。**无** `history()`。

**结论**:历史读模型 = 在既有投影链上新增一张 `rm_object_history` + 一个查询端点,是这条链的**同构扩展**,不引入新架构。

## 3. 数据契约

### 3.1 历史页签

#### 3.1.1 读模型表(新增迁移 `V32__rm_object_history.sql`)

```sql
CREATE TABLE rm_object_history (
  workspace_id   uuid        NOT NULL,
  object_id      uuid        NOT NULL,     -- 归属对象(字段/关系事件归到其对象)
  seq            bigint      NOT NULL,      -- 信封 sequence,同聚合单调递增,排序与幂等去重
  event_id       text        NOT NULL,
  kind           text        NOT NULL,      -- 见 §3.1.4 映射(create/edit/state/link/unlink/veto/rule/comment/ai/import…)
  field_code     text        NULL,
  before_val     jsonb       NULL,
  after_val      jsonb       NULL,
  actor_kind     text        NOT NULL,      -- user|rule|ai|artifact_sync|simulation|system
  actor_id       text        NULL,
  actor_display  text        NULL,
  source         text        NOT NULL,      -- manual|rule|AI|artifact_sync|simulation|system
  object_version int         NOT NULL,
  correlation_id uuid        NULL,
  occurred_at    timestamptz NOT NULL,
  PRIMARY KEY (workspace_id, object_id, event_id)   -- 幂等:重复投递 ON CONFLICT DO NOTHING
);
CREATE INDEX ix_rm_object_history_obj
  ON rm_object_history (workspace_id, object_id, seq DESC);
```

> 归属规则:`FieldChanged` 归到 `after.objectId`;`RelationCreated/Unlinked` 归到**两端**各写一行(方向用 `after_val` 标注 from/to),使两端对象的历史都能看到这条连线变更。按天分区可后置优化。

#### 3.1.2 查询端点(`ViewQueryController`)

```
GET /workspaces/{workspaceId}/views/objects/{objectId}/history?page=0&size=30
→ 200 ObjectHistoryPage   （seq DESC,分页;仅返回调用者可见对象的历史)
```

#### 3.1.3 前端类型(`packages/views/src/api/view-client.ts`)

```ts
export type ObjectHistoryKind =
  | "create" | "edit" | "state" | "link" | "unlink"
  | "veto" | "archive" | "delete" | "rule" | "comment" | "ai";

export interface ObjectHistoryEntry {
  readonly eventId: string;
  readonly seq: number;
  readonly kind: ObjectHistoryKind;
  readonly fieldCode: string | null;
  readonly before: unknown | null;
  readonly after: unknown | null;
  readonly actor: { readonly kind: string; readonly id: string | null; readonly display: string | null };
  readonly source: string;                 // 复用 sourceLabel() 出中文
  readonly objectVersion: number;
  readonly correlationId: string | null;
  readonly occurredAt: string;             // RFC3339;复用 relativeTime() 出「12 分钟前」
}
export interface ObjectHistoryPage {
  readonly items: readonly ObjectHistoryEntry[];
  readonly page: number; readonly size: number; readonly total: number;
}
// ViewClient 新增: objectHistory(workspaceId, objectId, page?, size?): Promise<ObjectHistoryPage>
```

文案在**前端**由 `kind + fieldCode + before/after + source` 组装(与既有 `display-labels` / `relativeTime` / `sourceLabel` 一致),读模型只存结构化字段,不存拼好的句子。

#### 3.1.4 事件 → 历史条目映射(投影规则)

| eventType | kind | 前端文案模板 | 备注 |
|---|---|---|---|
| `ObjectCreated` | `create`(source=import→`import`,=AI→`ai`) | 「创建 {类型}」 | 链首 |
| `FieldChanged` | `edit` | 「{字段名} {before} → {after}{单位}」 | 每字段一行;`ObjectUpdated` 是汇总,**不再单独投影**以免重复 |
| `StateChanged` | `state` | 「{fromState} → {toState}（{reason}）」 | |
| `Archived` | `veto`/`archive` | 「废止（{reason}）」 | toState=VOID |
| `SoftDeleted` | `delete` | 「删除」 | |
| `RelationCreated` | `link` | 「关联 {关系类型} → {对端代号}」 | 两端各写 |
| `RelationUnlinked` | `unlink` | 「解除 {关系类型}」 | |
| `AIChangeSetConfirmed` | `ai` | 「AI 变更集已确认」 | 逐项主数据事件另按上表落行 |
| `CheckCompleted` | `rule` | 「规则 {ruleCode} → {severity}」 | 载荷带 `dataVersion`,按对象过滤 |
| `CommentAdded`/`ReviewDecision` | `comment` | 「{批注/评审结论}」 | 审阅服务同信封 |
| `SimulationCompleted` | — | 不落对象历史(非对象级) | |

投影落点:在 `ReadModelProjection` 各 handler 末尾调用新增私有方法 `appendHistory(event, kind, fieldCode?)` → `repository.insertHistory(...)`;并为当前未处理的 `CheckCompleted / CommentAdded / ReviewDecision / AIChangeSetConfirmed` 增 `case`(只落历史,不影响其他读模型)。

> 前提校验:确认 `EventEnvelope` record 已暴露 `actor() / source() / correlationId() / sequence() / before()` 访问器(契约 §4.1 要求)。若当前 record 尚未携带,先补齐访问器与监听侧透传——这是投影 actor/来源/顺序的必需字段,属本方案的**前置任务**。

### 3.2 版本 · 护照页签(组合,不新增端点)

护照 = 已有数据 + 历史里程碑的**前端组装**:

| 区块 | 来源 |
|---|---|
| 身份(代号/类型/版本/状态) | `ObjectDetail.object`(已有) |
| 来源徽标 + 新鲜度条 | `object.source`(`sourceLabel`)+ `relativeTime(object.updatedAt)`;新鲜度阈值 24h → `clamp(1 - age/24h)` 作进度 |
| 下游依赖数 | `ObjectDetail.relations.length`(已有;可点跳选) |
| **来源链** | `objectHistory` 过滤到里程碑 `kind ∈ {create, import, ai, artifact_sync, state, veto, archive}`,取每条 `{文案, actor.display, relativeTime(occurredAt)}`,时间正序 |
| 字段血缘(可选展开) | 已有 `lineage(workspaceId, objectId, fieldCode)` |

即护照页签**零新增后端**:历史端点就绪后,前端做一次过滤映射即可。

- **可见性**:历史端点必须走与 `object` 相同的越权保护(不可见对象返回与"不存在"一致,不泄露存在性,契约 §8)。

## 6. 风险与待决

1. **历史量与分页**:活跃对象事件可能上千 → 端点强制分页(默认 30/页,`seq DESC`),前端滚动加载;`rm_object_history` 按天分区可后置。
2. **before/after 体积**:信封 `before/after` >32KB 存引用 `{ref}`(契约 §4.1);历史读模型对超大值只存摘要或 ref,前端按需拉取。
3. **外部信源接入**:`CheckCompleted/Comment/Review` 来自规则/审阅服务,同信封但不同 outbox;需确认这些事件已进 `ReadModelRabbitListener` 的订阅范围,否则历史缺这几类(可分期:先内核事件,再接外部)。
4. **图样 v1 仅本地**:换设备/清缓存丢失;可接受(纯视觉偏好),v2 再落 `view_element`。
5. **「历史 vs 版本护照」职责**:两者同源(历史流),护照是其"里程碑 + 身份"视图。保持读模型单一(只有 `rm_object_history`),护照在前端派生,避免双写不一致。

## 7. 工作量与顺序建议

关键路径是 **Phase 1(后端历史读模型)**——一旦就绪,历史与护照两页签在前端一并落地,图样页签可与之并行(纯前端、零依赖)。建议顺序:Phase 0 核对 → Phase 1 后端(投影/端点/迁移/契约)→ Phase 2 SDK → Phase 3 前端页签(历史 + 护照 一批,图样 并行)→ Phase 4 全量验证。
