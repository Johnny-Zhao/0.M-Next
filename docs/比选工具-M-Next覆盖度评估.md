# 比选工具 → M-Next 覆盖度评估

- 评估日期:2026-06-19。基于 main(至 v1.34:元模型/泛化/值类型、规则、派生/计算含 interp、模板生命周期含 tpl-api、审计、评审/审批、视图 SDK、交换/输出、SimulationEngine SPI)。
- 口径(承载方式):**配置**=profile 对象/字段/关系;**派生**=计算层;**规则**=校验/否决/风险;**视图**=表/矩阵/图;**输出**=快照→渲染;**已有**=模板/审计/审批等现成能力;**扩展·方法引擎**=方法引擎 SPI(见《比选决策引擎-框架设计稿》);**需补**=附件/图表/导出/录入 UI。

## 0. 结论

**覆盖 ~25/29,且这是最"正中 hub 靶心"的验证域**——无物理、无几何、无重计算,~90% 是配置+派生+规则+报告,把 tpl-api(模板)、审计、评审/审批、派生、规则、视图、输出**全部复用一遍**。少数缺口(附件、图表、Excel 导出、录入 UI)都是有边界的增量。**建议定为首个旗舰验证域**:领域无关(任何行业都做方案比选),最快能出完整闭环 demo。

## 2. 缺口清单(需补,均有边界)

## 3. 复用盘点(已有能力直接对口)

模板复用=tpl-api;操作留痕=audit_log;结果确认=review/审批;加权/汇总/归一=派生(+interp);权重校验/否决/风险=规则;对比表/排名=视图;报告=快照渲染。**这 7 类是比选工具的主体,全部现成。**

## 4. 方法层(加权之外)

13 加权计算 = **派生即可,内置默认**。若升级到 TOPSIS/AHP/优化 → **方法引擎 SPI**(详见《比选决策引擎-框架设计稿》):加权和内置、标准 MCDA 自研轻量、组合优化外挂。各行业不同的指标/权重/否决/风险 = **声明式比选模型配置**,换行业改配置不改代码。

## 5. MVP 切法(首个闭环 demo)

一个最小比选 profile:`比选项目`+`候选`+`指标(含权重)`+`评分` 对象/关系;派生(加权综合分);规则(权重100%校验、一票否决、低分风险);视图(候选×指标对比矩阵 + 综合排名);快照→报告。**纯配置+派生+规则+视图+输出,零生产代码**(同 energy 阶段A 路线)。先做"加权和"方法;附件/图表/导出/录入 UI 作为后续增量。

## 6. 战略定位

比选/方案权衡是**所有行业**(采购、选型、招投标、技术方案评审…)的通用动作 → 领域无关,印证 hub。它最轻、最快成型,且**复用面最广**(把平台几乎所有自带能力串一遍),适合做**首个完整产品级验证域**与对外 demo。
