# 选型推荐 设计稿(energy 阶段B)

状态:**设计稿(待拍板)**。蓝本:能源可行性备忘"长板4"、平台定位(hub=统一数据+综合分析,不自研专业引擎)。本稿只定方案与接口,不写代码。

## 0. 目标与口径

- **推荐 + 备选**:给一个设计槽(如 `solar_array`/`battery_pack` 实例),从产品库(`product_item` 子类)里筛出**满足要求**的候选,按目标**排序**,返回"推荐(首选)+ 备选(次选若干)"。
- **替换即复算**已成立:换选型 = 改 `selected_as` 关系(既有 CreateRelation/Unlink 命令)→ 既有派生自动重算(energy 阶段A 已验证)。**所以"推荐"只是读侧建议,"选型"是既有写命令,两者解耦。**

## 1. 方案抉择:规则/派生驱动的只读查询(推荐),不做新引擎

| 方案 | 说明 | 评价 |
|---|---|---|
| A. 规则/派生驱动 + 只读查询 | "资格"=布尔谓词、"评分"=数值表达式,均用现有规则/派生 DSL;查询端点筛+排+取 top-N | **推荐**:贴合 hub 定位(声明式、复用已有引擎)、零新引擎、只读零副本 |
| B. 专门推荐引擎 | 独立打分/排序服务 | 不推荐(MVP 过重;多目标加权用表达式即可表达) |

**结论:推荐 = 读侧能力**(资格谓词 + 评分表达式 + 排序),复用规则/派生 DSL 求值器;**不新造写路径、不加计算引擎**。

## 2. 核心机制

1. **候选集**:产品库中目标子类(如 `solar_cell`)的全部产品(读模型,分页有界)。
2. **资格(eligibility)**:布尔表达式,逐候选求值,过滤掉不满足要求的(如 `field('power_max_w') >= 要求功率`)。
3. **评分(score)**:数值表达式,逐候选求值(如 `0.6*归一(成本) + 0.4*归一(质量)`,越小越优 / 越大越优可配)。
4. **排序 + 取 N**:按 score 排序 → 首个=推荐,其后 N 个=备选;有界(top-N、候选分页)。

## 3. 关键设计点:表达式怎么同时看"槽要求"与"候选字段"

DSL 的 `EvalContext` 现为**单对象**。推荐要"候选 vs 槽要求"两份数据,提议**双绑定上下文**:

- `field('code')` → **候选产品**字段;
- `require('code')` → **设计槽**上的(派生)要求值(如 `solar_array.required_power_eol_w`)。

实现:推荐服务先算/读槽的要求值(已是派生字段),构造一个暴露"候选字段 + require(槽值)"的 EvalContext,逐候选跑资格/评分表达式。`require()` 作为新内置函数加进求值器(小扩展,engines),或 MVP 先把槽要求值作为表达式参数注入(更轻,不改 DSL)。

## 4. 准则(eligibility/score 表达式)存哪

| 选项 | 说明 | 取舍 |
|---|---|---|
| MVP:查询参数传表达式 / 命名准则 | 调用方(UI/卡)把 eligibility/score 表达式作为查询参数传入 | **MVP 推荐**:零新实体/契约,先把机制跑通 |
| 产品化:`selection_criteria` 实体 | 每 (slotType→productType) 存一组资格/评分表达式,随 profile 配置 | 更产品化,但需新实体+命令+迁移+**契约 addendum(人发起)**,留作后续 |

建议:**MVP 先走查询传表达式**,验证机制;成熟后再上 `selection_criteria` 实体做产品化。

## 5. 接口

- **只读查询端点**(AG-101/102 零副本只读):`GET /workspaces/{id}/views/recommendations?slotId=&candidateTypeCode=&eligibility=&score=&order=asc|desc&size=`;
- 返回:候选列表(产品 id/关键字段/score/是否资格通过),首个标记 recommended,其余 alternatives;
- **有界**(AG-202/203):候选读取分页、返回 top-N 上限。

## 6. 与闭环的关系

推荐只读、不改模型;用户选定后走既有 `CreateRelation(selected_as)` / `Unlink`(命令入口)→ 既有派生(质量/成本/裕度)与规则自动重算。**推荐(读)与选型(写)解耦,符合 CQRS。**

## 7. 红线

- 只读、零副本(AG-101/102);候选/返回有界(AG-202/203);复用规则/派生 DSL,不新造引擎/写路径。
- 若走选项 4 的 `selection_criteria` 实体 → 命令/实体需**契约 addendum(人发起)**,Codex 不擅自加。
- `require()` 若作为新 DSL 内置函数 → engines 小扩展(类似 interp),需在表达式语法附录登记(轻);MVP 用参数注入则免。
