### 1.2 代码存在但用户不可用

1. **TECHDOC 示例项目从 UI 打不开。** Home/项目列表硬编码室内 workspace `11111111-…`(`app.tsx:22`、`home.tsx:62`、`project-list.tsx:17`)。技术方案 seed 在 `22222222-…`,没有任何 UI 入口。这直接砍断核心闭环第一步。
2. **Word 导出的"文档"不是文档视图。** 前端导出走 `captureSnapshot(workspaceId, objectType)`(`document-output-action.tsx:57-66`)——按**单一对象类型**取平面快照,与文档树(rootId + hierarchical 关系)无关。

### 1.3 Demo 级

1. **DocxRenderAdapter**:输出 = 一行标题 `"Output"` + 一张 objectId/字段平表(`engines/output/office/DocxRenderAdapter.java:23-45`)。没有章节、标题层级、段落。**这不是技术方案文档,是导出成 Word 的 CSV。** Pdf/Xlsx 同级。
2. `OutputTemplate` 只有"对象类型+字段+分节顺序",无章/节/段落/文档树绑定概念。
3. 项目列表 fetch 失败时降级到占位假项目「技术方案A」(`project-list.tsx:95-99`)——看起来有,点进去是室内。
4. 维度按钮部分 disabled(`shell-chrome.tsx:22-29`),约 70 处"待接入"痕迹。

### 1.4 P0(阻断 v0.1)

- **P0-1 入口**:UI 无法进入技术方案示例项目(1.2-1)。
- **P0-2 导出内容**:docx = 平表,且导出范围与文档结构脱节(1.2-2 + 1.3-1)。这是核心卖点,现状不可交付。
- **P0-3 校核交互**:改参数后规则不自动重跑,需手动点「重新校验」。要么自动触发,要么把按钮做成闭环的明确一步——必须二选一定死,不能含糊。
- **P0-4 发布基线混乱**:HEAD 停在 `feat/T-V36-xmi3-project-refs`(不是 main),XMI-3 卡未提交;9 个 prunable worktree;`ux-a-workspaces`、`ux-c-new-project` 等分支未合。**现在连"v0.1 从哪个 commit 出"都答不上来。**
- **P0-5 运行成本**:docker-compose 5 服务(PG/MinIO/OpenSearch/RabbitMQ/Redis)。techdoc 闭环实际只强依赖 PG。不要求瘦身(那是重构陷阱),但 v0.1 必须有一页"30 分钟从零跑起来"的可复现步骤,且亲测过。

### 1.5 附带发现

- 交接简报引用的 `架构-总纲-模块即需即装与能力市场.md`、`扩展性架构-项目模块profile.md` 等文件**在仓库中不存在**(现存为 `架构总纲-平台扩展性与插件.md`)。文档索引已失真。

## 二、首发楔子:硬判断

**v0.1 = 技术方案文档同源生成。** 不是并列备选,是唯一选择:

1. **技术方案文档同源生成 → 做,作为 v0.1。** 后端骨架已在(profile、规则、派生、导出管线),缺口全部集中在"最后三公里"(入口、示例真实感、章节化 docx),7~14 天可达。且可 dogfood——用它维护你自己的《技术说明书 V3.3》,第一个真实用户就是你。
2. **室内设计插件 → 暂停,冻结为回归资产。** 它是目前 UI 最完整的域(floorplan、维度、演示脚本),别删、别改,留作插件机制的回归验证。但它没有付费/使用场景的近路,不配做首发。
3. **MBSE / SysML-like → 只作技术验证保留,停止新投入。** T-V35 已打穿灯塔,机制已被证明。继续 XMI-2/3 是平台叙事,不产生一个真实用户。**当前 HEAD 所在的 XMI-3 应立即停手。**
4. **多领域平台 → 停止作为产品目标。** 它是 M-Next 的机制,不是 v0.1 的产品。平台价值只有在第一个楔子有人用之后才存在。

## 三、范围收敛与砍项

**v0.1 必须做**(全部服务核心闭环):

1. UI 入口能打开技术方案示例项目;
2. seed 加厚成一份"像真的"技术方案(含参数链、一条校核不通过、一组比选结果);
3. 改参数 → 派生值刷新 + 校核灯变化(定死交互);
4. 从文档树导出章节化 docx;
5. golden path 上的错误/加载/空状态(仅这条路径上的)。

**v0.1 可以假实现**:比选(seed 预置比选对象和结果,不做交互式决策 UI——决策引擎已有,先不接);登录(保持 demo-actor);项目列表(真实列出 seed 的 2~3 个 workspace 即可,不做新建项目向导)。

**v0.1 必须砍**:XMI-3(当前分支)、MANIFEST-TAGS/能力市场、"第二域复制性验证"、时序脊 T2、实例复用 T2、看板/甘特、Office 结构化抽取、验证覆盖仪表深化。

**做了会拖慢**:Fluent 皮肤/令牌继续打磨、五镜头视觉重构、compose 瘦身重构、前端 E2E 框架搭建(v0.1 用手动验收脚本顶)。

**继续讨论就是浪费时间**:新领域 profile(能源/SysML 转 profile)、即需即装、perspective/视角系统、流程引擎、3D、联合仿真、UAF/DoDAF/SysML 完整兼容、架构分类法(行业/专业/场景)重写。这些全部有设计稿了,冻结即可,不需要更多文字。
