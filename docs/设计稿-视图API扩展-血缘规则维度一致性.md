# 设计稿(征求):视图 API 扩展 —— 规则灯 / provenance 血缘 / 维度集 / 跨表达一致性

> 目的:把后端**已有但未暴露**的事实(规则检查、来源/派生依赖、M2M 对应)通过**只读 view-API** 暴露,让 P3 前端把现在满屏的 `TODO(view-API)` 真正填上。
> 性质:**契约变更人发起(AG-301/501)**。本稿是给产品负责人确认的提案,确认后每块各出"契约 + 夹具 + 封闭卡"。
> 红线:**只读、零拷贝、有界**;写一律不经此处;新增 schema 走 `check-contracts` 登记 + 夹具随卡(AG-406);错误码前缀沿用 view 侧规范。

## ① 规则灯汇总(per-object rule status)—— 建议先做

**需求**:图元/属性面板要显示每个对象当前的规则态(BLOCK/WARN/OK),现在前端只能 `ruleStatus: "TODO"`。

**现有底座**:规则检查产生 `check_result`(severity = WARN/BLOCK,scope = 对象/字段,绑定 runId)。数据已在,只是 view 没有"按对象聚合的最新态"读端点。

**拟暴露**(只读、有界):
- 在 `GET /workspaces/{wid}/views/objects` 与 `…/objects/{id}` 的返回里**增一个只读字段** `ruleStatus`:取该对象**最新检查批次**内命中的最高 severity(`BLOCK` > `WARN` > `OK`;无检查 → `UNKNOWN`)。
- 可选:`GET /workspaces/{wid}/views/rule-status?objectIds=…`(批量,≤200)给图面板一次拉全。
- 字段级(连线/单元格)态:`…/objects/{id}` 的 fields 里每字段附 `ruleStatus`(同法)。

**契约改动**:扩 object 视图 DTO(只增字段);新增 `rule-status` 读端点(若走批量)。无迁移(读 `check_result`)。
**就绪度**:底座齐,纯读聚合;**最便宜,建议第一张**。
**对应前端**:WEB-P3d 校验面板 + 图元规则灯;SKIN 的 `ObjectNode` ruleStatus 从 TODO 接真值。

## ② provenance 血缘(单值的上游/算法/下游)

**需求**:属性面板"护照"要显示 来源 / 新鲜度 / 下游依赖;血缘抽屉要显示"这个派生值由哪些输入 + 哪条派生/规则算出、被谁依赖"。现在 `provenanceText: TODO`。

**现有底座**:
- **来源**:每对象/命令带 `SourceInfo`(artifact_sync/excel-import/人工/规则/AI…)——未在 object 视图暴露;
- **新鲜度**:`updatedAt` 已暴露;
- **依赖**:`DerivedEvaluator` 知每个派生字段的输入字段/对象;规则知其引用——这层"依赖图"在引擎内,未持久化为可查血缘。

**拟暴露**(只读、有界):
- object 视图增 `source`(来源类型 + 标识,来自 SourceInfo)——便宜;
- `GET /workspaces/{wid}/views/lineage?objectId=&fieldCode=` 返回该值的:**上游**(输入对象/字段 + 各自来源/新鲜度)、**算法**(派生表达式 id / 规则 code)、**下游**(依赖它的字段/规则/推荐),**有界**(深度 ≤2、节点 ≤200)。

**契约改动**:object DTO 增 `source`(只增);新增 `lineage` 读端点 + schema + 夹具。**可能需后端把派生/规则的依赖关系做成可查**(DerivedEvaluator 暴露依赖,或落一张只读血缘投影)——这是本块主要工作量。
**就绪度**:`source`/`新鲜度` 即时可给;**完整血缘图需补"依赖暴露"**。建议拆两半:②a `source` 字段(便宜,随①)②b lineage 端点(中等)。
**对应前端**:WEB-P3a 属性面板护照(②a)+ 血缘抽屉(②b)。

## ③ 维度集(字段 → 维度分组)

**需求**:维度信息视图叠加(能量/热/质量;风/热/光)需要知道"哪些字段属于哪个维度",才能切叠加层。现在元模型里字段**没有维度标签**。

**现有底座**:元模型有字段定义(类型/必填/枚举/派生/单位…),但**无 dimension 维度归类**。

**拟暴露 + 需补**:
- **元模型加一个字段属性** `dimension`(可空,如 `energy`/`thermal`/`mass`;由 profile 配置)——这是**元模型/契约新增**,非纯读;
- view 侧:`GET /workspaces/{wid}/views/dimensions` 返回该 profile 的维度清单 + 每维度的字段集 + 规则子集;object 视图字段附 `dimension`。

**契约改动**:**元模型字段定义加 `dimension`(人发起,较重)** + 模板配置支持 + 维度读端点。需迁移(字段定义表加列)或放 constraints。
**就绪度**:**最依赖元模型扩展**,比①②重;建议在①②落地、维度 demo 真要做时再启。
**对应前端**:WEB-P3c 维度叠加。
**备选(零后端)**:先用**约定**(字段 code 前缀/命名,如 `energy_*`)在前端归类做 demo,正式维度标签后置——可让维度 demo 不等后端先跑起来。

## ④ 跨表达一致性比对(同实体两表达差异)

**需求**:一致性裂缝面板要并排两种表达(语言/阶段/维度)并标出"对不上"的字段 + 判别"真不一致 vs 口径误差"。

**现有底座**:M2M 投影(V14 transformation)+ 对应互查(FED correspondence)——能查"此实体 ↔ 彼实体"的对应,但**没有"对应值逐字段比对 + 差异分类"的读端点**。

**拟暴露**(只读、有界):
- `GET /workspaces/{wid}/views/consistency?leftId=&rightId=`(或按 correspondence 对)返回:逐字段 `{ field, leftValue, rightValue, equal, deltaPct? }`,**有界**(字段 ≤200);
- "真不一致 vs 口径误差"的**判别**先**不自动下结论**——只给差值 + 来源/单位/时间戳线索,判别交人(避免假智能)。

**契约改动**:新增 `consistency` 读端点 + schema + 夹具;依赖 correspondence/M2M 已有数据。
**就绪度**:**最高难度**;且语言轴(SysML↔Modelica)本身是后续。建议**最后做**,先支持"阶段轴/维度轴"这类同构比对(无损),语言轴留待往返投影成熟。
**对应前端**:WEB-P3e 一致性裂缝。
