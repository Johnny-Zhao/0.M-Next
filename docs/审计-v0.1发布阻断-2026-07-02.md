## 一、仓库真实状态

**能跑到哪里**(main 代码具备):

- 后端:CQRS 命令链、乐观锁、规则引擎(`RuleCheckRunner`)、派生读时求值(`DerivedEvaluator`)、technical-proposal profile 自动装载 + seed(workspace `22222222-…`,13 个对象)、导出管线(`OutputController` + RenderAdapter SPI + POI)。
- 前端:登录→项目列表→Dockview 工作台(左树/中多视图标签/右 Inspector/下校验);表格双击编辑与 Inspector 编辑均接命令 API,409 冲突弹窗完整;保存后自动双刷视图(`inspector-panel.tsx:211-224`),**派生值会自动更新**;文档视图支持 hierarchical 关系树;导出菜单已接线可下载。

**跑不到哪里**(用户视角断点,按闭环顺序):

1. **打不开 TECHDOC 项目**:HOME 硬编码室内 workspace `11111111-…`(`app.tsx:22`、`home.tsx:62`、`project-list.tsx:17`),`22222222` 无任何 UI 入口;列表请求失败还会降级到假项目「技术方案A」(`project-list.tsx:95-99`),点进去是室内。
2. **改不了"工程参数"**:techdoc profile 的字段**全是字符串**(title/author/responsibility/protocol/priority),唯一派生字段是 `child_count_fx`(数子节点)。"改一个参数→派生值变化"这一步没有内容可演示。**方案比选对象在 seed 里为零**(grep 无 alternative/decision)。
3. **校核灯不自动变**:规则只在手动点「重新校验」时跑(`validate-panel.tsx:97,132`),保存参数不触发。
4. **导出的不是技术方案文档**:`DocxRenderAdapter` 输出一行 `"Output"` + objectId/字段平表(`office/DocxRenderAdapter.java:23-45`);且前端导出按**单一 objectType 平面快照**(`document-output-action.tsx:57-66`),与文档树无关。
5. **发布基线不明**:HEAD 在 XMI 特性分支,XMI-3 卡未提交,9 个 prunable worktree,`ux-a`/`ux-c` 等分支未合。

## 五、给 Codex 的最小开发卡(5 张,按序执行)

> 每张卡通用红线:单分支;只 add 本卡文件;不重构无关代码;不新增依赖;命中"需改契约/迁移/API 取不到"→ 停下回报;合并前 `corepack pnpm verify` 全绿 + `node scripts/check-no-skipped.mjs` 显示 Skipped:0。

### 卡A — 仓库收口与基线(先做,人工为主,Codex 只跑验证)

- **目标**:确定 v0.1 从哪个 commit 出发,main 可构建可测试。
- **修改范围**:仅 git 操作 + 可能的 CI 小修。XMI-3 未提交文件提交到其分支后切回 main;`git worktree prune`;逐一处置未合分支(合或标记弃置,不新写代码);main 上跑 `docker compose up -d` + `corepack pnpm verify`。
- **禁止范围**:任何功能代码;任何"顺手升级依赖"。
- **测试要求**:verify 全绿、Skipped:0,记录耗时。
- **手动验收**:`git log --oneline -3` 在 main;`git status` 干净;`git worktree list` 只剩主目录;写下基线 commit 号到 `docs/总纲-v0.1.md`。

### 卡B — 项目入口与 techdoc 默认布局

- **目标**:从 HOME 两次点击进入技术方案示例项目,进入后默认视图面向 techdoc。
- **修改范围**:`packages/web/src/app.tsx`、`home/home.tsx`、`home/project-list.tsx`(列出三个 seed 项目、删失败降级假项目、失败显式错误态)、`workbench/workbench.tsx`(按 workspace 选默认 objectType:techdoc→`module`,默认开文档面板)。
- **禁止范围**:不新增后端端点;不做新建项目向导;不动 Dockview 布局引擎;不动室内工作台行为。
- **测试要求**:home/project-list 现有测试更新 + 新增"三项目渲染/失败错误态"用例;workbench 默认 objectType 分支用例。
- **手动验收**:HOME → 点「技术方案 Demo」→ 工作台表格显示 module 对象、文档面板有树;断网刷新 HOME 显示错误态而非假项目。

### 卡C — techdoc 示例加厚:数值参数链 + 比选 + 红灯

- **目标**:示例项目具备"改参数→派生变化→校核变灯"的真实内容。
- **修改范围**:`packages/domains/technical-proposal/profile.manifest.json`(module 加 `power_w:number`、proposal/system 加 `power_budget_w:number`;派生 `total_power_fx = sum(traverse('proposal_contains_module','out').power_w)` 按现有表达式能力写;新规则 `R-TD-PWR` severity=BLOCK:总功耗超预算);`DevSeedRunner.java` techdoc 段(给模块赋功耗值、预置 1 条超预算红灯、加 3 个"备选方案"普通对象存比选结论字段)。
- **禁止范围**:零 DB 迁移(全部走 manifest 声明式);不接决策引擎 UI;不动其它 profile;不改表达式引擎——若现有函数不支持 sum/traverse 聚合,停下回报,不自造语法。
- **测试要求**:仿照 `TechDocPluginInstall` 现有集成测试,断言装载后派生值与规则结果;seed 幂等性不回归。
- **手动验收**:进入 techdoc 项目,校验面板显示 1 红(超预算);表格能看到 total_power_fx 数值。

### 卡D — 保存即校核

- **目标**:修改参数保存成功后,校核灯自动更新,无需手动点「重新校验」。
- **修改范围**:`web/src/workbench/inspector-panel.tsx`(onFieldSaved 追加 `runRuleCheck` 调用,复用 `views/src/api/view-client.ts` 现有方法)、`views/src/table/table-view.tsx` 保存成功回调同样处理、`validate-panel.tsx` 支持外部触发刷新(沿用现有 selection/subscribe 模式)。
- **禁止范围**:不改后端;不做 websocket/轮询;不做防抖框架——每次保存跑一次即可;规则运行失败时静默保留手动按钮,不弹阻断错误。
- **测试要求**:前端单测:保存成功→runRuleCheck 被调用→面板刷新;失败→不影响保存结果提示。
- **手动验收**:把某模块 power_w 改大→3 秒内校验面板出现红灯;改回→红灯消失。全程不点「重新校验」。

### 卡E — 文档树导出章节化 docx(最大卡;5a 契约先行,人审后再做 5b/5c)

- **目标**:从文档视图导出一份有章节结构的 Word 技术方案。
- **修改范围**:
  - E-a(契约,人审 diff 后才继续):快照/`OutputTemplate` 支持"rootId + hierarchical 关系"的树范围与"层级→标题级别、字段→段落/表格"映射;
  - E-b:`engines/output/office/DocxRenderAdapter.java` 重写为:树遍历生成 1~3 级标题、对象描述字段作段落、数值字段汇成参数表、规则结果汇成校核结论表(拿现有规则结果读侧数据);
  - E-c:`web/src/workbench/document-output-action.tsx` 改为携带当前文档视图 rootId 触发。
- **禁止范围**:不做模板可视化编辑器;不做样式/主题美化;不动 Pdf/Xlsx 渲染器;不改 Markdown/Html 渲染器;不新增依赖(POI 已在 allowlist)。
- **测试要求**:集成测试断言导出的 docx 包含 ≥2 级标题、参数表行数、校核表存在(POI 读回断言);快照契约测试;前端导出动作单测更新。
- **手动验收**:文档视图选中 proposal 根 → 导出 docx → Word 打开:能看到"方案→系统→模块"章节层级、模块参数表、末尾校核结论表;文件名与 toast 正常。

**排序即依赖:A → B → C → D → E。** B/C 可并行,D 依赖 C(要有红灯可变),E-a 人审是唯一契约闸口。
