# Office 抽取(Excel/Word → 对象/字段/关系)— 设计稿(待人确认后才发实现卡)

> 状态:**设计征求**。本稿提出把 Excel/Word 解析为统一数据(对象/字段/关系)的适配器、映射方式、入库路径。契约新增(适配器登记/映射描述/可能的读端点)属 AG-301/501 人发起,需你拍板后开实现卡。

## 1. 为什么 / 边界

直击说明书"替代 Office 文件式工作":把用户手里的 Excel 表 / Word 结构化内容,一键解析为统一数据源的对象/字段/关系,而不是再当孤立文件。复用现有**交换适配器 SPI**(ReqIF/XMI 同款)+ POI(已在依赖,无新依赖)。

**非目标(本期)**:Excel 公式求值/图表、Word 复杂排版/修订、PPT、回写 Office(导出已由 RenderRegistry 覆盖)、AI 抽取(归 AI 执行层)。

## 2. 关键决策(每条给推荐 + 备选)

### D1 先做哪个 —— 推荐:**Excel 先行,Word 押后**
- Excel 是结构化数据的主力(行=对象、列=字段),价值最大、语义最清晰;Word 结构化块解析更含糊,押 Phase 2。
- 备选:两者一起——范围翻倍,不利 MVP。

### D2 映射方式 —— 推荐:**声明式映射描述(mapping descriptor),不内置猜测**
- 一个 Excel 导入 = 一份映射描述:`{sheet → objectTypeCode, headerRow, columns:[{header|colIndex → fieldDefCode}], keyColumn(可选,作对象名/幂等键)}`。
- **平台不猜列义**;映射由用户/profile 提供(可存为模板复用)。无映射 → 只登记 + 元数据(见 D4),不入库。
- 备选:按表头模糊匹配字段——易错、不可控,否。

### D3 关系 —— 推荐:**MVP 只做对象+字段,关系押后**
- Phase 1 把行映射成对象、列映射成字段值;**跨表/跨列引用→关系**留 Phase 2(需引用解析规则)。
- 备选:同时做"某列值=另一对象名→建关系"——可做但增复杂度,押后。

### D4 三级解析(对齐 §8.8)—— 推荐:**登记 → 元数据 → 按需深解析**
- 上传即登记(文件名/大小/sha256,复用附件 blob 存储);元数据解析(sheet 列表、表头、行数);**深解析(按映射入库)用户显式触发**。避免大文件即时卡顿。
- 复用 ATT-A 的 `StorageBackend` 存原文件;attachment 关联到"导入任务"对象。

### D5 入库路径 —— 推荐:**解析为交换 DataSet → 经命令入口建对象(AUTHOR)**
- 适配器只产出中间 `DataSet`(与 ReqIF/XMI 同款);入库走现有命令(CreateObject/UpdateFields),**不绕过命令入口**(AG-110)、受 RBAC 约束(AUTHOR)、留审计、可幂等(keyColumn)。
- 冲突处理:同 keyColumn 已存在 → 更新字段(或报冲突,见开放问题)。

### D6 落点 —— 推荐:engines 适配器 + server 编排
- `engines/exchange/office/ExcelImportAdapter`(POI XSSF 读 → DataSet),挂交换适配器 SPI;
- server 侧导入编排(登记→元数据→深解析→产命令),与 ReqIf 编排同模式。

## 4. 分期落地
- **Phase 1(MVP)**:Excel 登记 + 元数据 + 按映射深解析入库(对象+字段)+ 幂等(keyColumn)+ e2e(传 xlsx → 映射 → 入库 → 校验对象/字段);走 RBAC(AUTHOR)。
- **Phase 2**:Word 结构化块、跨表引用→关系、AI 辅助映射建议、回写对比同步。

## 5. 决策(已定,2026-06)
1. **Excel 与 Word/Visio 分开做,Excel 先行** ✅ —— 三者解析语义本质不同,各自独立适配器(见 D7)。
2. 映射:用户传映射描述 **+ 可存"导入模板"复用**(tpl-api)。
3. 冲突:同 keyColumn 命中 → **默认更新字段** + 可选"仅新增"。
4. **不依赖 RBAC,可并行** —— 导入=写=AUTHOR,RBAC 上线后自动受约束;先做不必等。
5. `import_task` 表 **持久化**(登记/状态/映射/结果),可追溯可重放。

## D7 三类 Office 来源各自独立(分开做,语义不同)
| 来源 | 语义 | 产出 | 复杂度/排序 |
|---|---|---|---|
| **Excel** (.xlsx) | 行=对象、列=字段;表格结构清晰 | 对象 + 字段值 | 最清晰,**Phase 1 先做** |
| **Word** (.docx) | 自然语言 + 结构化块(标题/表/列表);需块识别 + 数据引用 | 对象 + 字段(+ 文档引用) | 中,Phase 2(POI XWPF) |
| **Visio** (.vsdx) | **图形:节点=对象、连线=关系**(正对平台"图形画线=建关系") | 对象 **+ 关系(强语义)** | 较高,Phase 3 |

> **Visio 值得纳入**:它天然映射到平台的图形镜头(节点→对象、连线→关系),是"画图即建数据"最直接的入口,比 Excel 多产出**关系**。技术上 `.vsdx` 是 OOXML/ZIP+XML 包,**POI 对 Visio 支持很弱**,适配器宜直接解析 vsdx 内的 pages/shapes/connects XML(纯 JDK XML,无新依赖),产出节点+连线 → 对象+关系 DataSet。因为它落"关系"(强语义,见 §D3 押后项),排在 Excel(只对象/字段)、Word 之后。三者各自一个交换适配器,共用"DataSet → 命令入库"编排。
