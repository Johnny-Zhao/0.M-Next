# 比选工具 — 前端开发任务 & Design Brief

> 对应需求:比选工具 29 功能(`docs/比选工具-M-Next覆盖度评估.md`)。后端能力已大部分就绪(BID 加权闭环、REC-A 推荐查询、TOPSIS 方法引擎、派生/规则/模板/审计);本任务聚焦**产品/前端层**(③UI 插件)。

## 1. 用户目标
让采购/选型负责人与评审人在一个工具里走完"**建比选项目 → 录候选与指标权重 → 打分 → 自动加权/排名/一票否决/风险提示 → 看对比与推荐 → 确认并出报告**"的全流程:少翻表、计算自动、结论可追溯、模板可复用。

## 2. 核心场景
1. **负责人立项**:新建比选项目(背景/预算/截止),配指标与权重(或套模板),邀请评审人。
2. **录候选**:添加多个候选(供应商/产品/方案),录报价、周期、资质等,上传报价单/方案附件。
3. **评审打分**:评审人在评分矩阵按指标打分(人工)或由规则自动换算(价格/周期→分),填理由;支持多人分别打分。
4. **自动比选**:系统加权算综合分、生成综合/单项排名;触发一票否决(资质不符/超预算)与风险提示(报价异常/关键低分/材料缺失)。
5. **看结果**:对比表 + 雷达/柱状图看优劣;查看系统推荐对象与推荐理由;查看风险面板。
6. **确认出件**:负责人确认最终结果,导出比选报告(含评分/排名/推荐/风险);全程操作留痕。
7. **复用**:把常用指标/权重/规则存为模板,下次一键起项目。

## 3. 页面 / 组件清单
**页面**
- P1 比选项目列表(+ 新建向导)
- P2 项目详情/总览(进度、关键指标、报警灯)
- P3 候选对象管理(列表 + 录入表单 + 附件区)
- P4 指标与权重配置(指标表 + 分类 + 权重 + 100% 校验条)
- P5 评分工作台(候选 × 指标 评分矩阵)
- P6 比选计算与排名(综合分、综合排名、单项排名切换)
- P7 结果分析(对比表 + 雷达/柱状图 + 推荐卡 + 推荐理由 + 风险面板)
- P8 报告预览 / 导出
- P9 模板管理
- P10 审批留痕(操作记录时间线 + 结果确认)

**关键组件**
- 数据表(可排序/筛选)、评分矩阵(可编辑单元格 + 理由气泡)、权重输入+实时合计校验条、雷达图、柱状图、综合得分排名榜、推荐卡(含理由)、风险徽标 / 否决标记、附件上传与关联、确认/审批条、导出格式选择器、空/加载/错误占位。

|---|---|---|---|---|---|
| 项目列表 | 列表 | 骨架行 | "暂无比选项目,去新建" | 加载失败+重试 | — |
| 候选管理 | 候选表 | 骨架 | "还没有候选,添加第一个" | 保存失败提示 | 保存成功 toast |

| 报告导出 | 预览 | 生成中 | — | 导出失败+重试 | 下载就绪 |

## 5. 交互规则
- **权重实时校验**:所有指标权重合计≠100% 时,顶部校验条红色并阻断"开始比选/确认"。
- **改分即重算**:任一评分/选型/权重变更 → 综合分、排名、推荐、风险**实时重算并刷新**(乐观更新 + 后台确认)。
- **一票否决**:命中否决条件的候选**置灰 + 淘汰标记**,排名中下沉/剔除,推荐不选它。
- **风险提示**:风险项以徽标挂在候选/评分单元格,汇总到风险面板;低分/缺料/合规不过各有图标。
- **推荐**:按综合分 + 风险给出推荐对象 + 自动理由;切换方法(加权和/TOPSIS)推荐可变。
- **附件**:可拖拽上传并关联到候选或具体评分项,审查时一键查看。
- **确认前置**:权重=100% 且无未评必填项,方可"确认结果";确认后锁定 + 留痕。
- **导出**:选 Excel/PDF/Word;报告含评分明细、排名、推荐理由、风险提示。

## 7. 验收标准
- 全流程端到端走通(立项→候选→指标权重→打分→比选→结果→确认→导出);
- 权重≠100% 阻断、改分实时重算、否决置灰/剔除、风险徽标与面板正确;
- 综合分/排名与后端派生一致;推荐对象+理由随分/风险/方法正确变化;
- 对比表与雷达/柱状图数据准确、可读;
- 报告含评分/排名/推荐/风险并可导出;模板可复用;操作留痕 + 结果确认锁定;
- 各屏 default/loading/empty/error/success 状态齐全;键盘可达、对比度达标(a11y)。

## 8. 是否需要 Claude Design:**Yes**
理由:这是**多屏、信息密集、强交互**的产品界面——评分矩阵(可编辑表格)、对比表、雷达/柱状数据可视化、推荐卡与风险面板、实时重算与校验反馈,都需要先做**信息架构 + 线框 + 交互/状态设计 + 组件系统**再开发,不宜直接写代码。属于典型"先设计后实现"。

## 9. Design Brief

**项目**:比选/方案权衡工具(领域无关,首期以采购/技术选型为样例)。
**目标用户**:① 比选负责人(立项、配权重、看推荐、确认出件);② 评审专家(按指标打分、填理由)。
**核心价值**:把"凭经验拍脑袋的方案比选"变成"可配置准则 + 自动加权/排名/否决/风险 + 可追溯报告"。

**关键屏(设计优先级)**
1. 评分工作台(P5)——核心:候选×指标可编辑矩阵,人工/自动分、理由、否决/风险标记、底部实时综合分预览。
2. 结果分析(P7)——对比表 + 雷达图(多候选能力对比)+ 综合排名榜 + 推荐卡(含理由)+ 风险面板。
3. 指标与权重(P4)——指标分类分组、权重输入 + 醒目的 100% 合计校验条。
4. 项目总览(P2)——四阶段进度 + 报警灯 + 关键数。

**信息架构**:左项目导航 / 顶阶段流程(立项→候选→评分→比选→结果);右侧/底部常驻"实时结论"(当前综合排名 Top + 报警)。

**关键交互**:实时重算反馈(改分→分数/排名动效更新);权重校验条(红/绿);否决置灰;风险徽标 hover 详情;方法切换(加权/TOPSIS)即时改推荐;附件拖拽关联。

**数据可视化**:雷达图(候选×指标归一能力轮廓,多候选叠加可比);柱状图(综合分排名);得分热力(评分矩阵单元格按分着色)。强调"一眼看出优劣与差距"。

**视觉基调**:专业、克制、数据优先;弱装饰、强对比与层级;报警/风险用语义色(红/橙/绿),否决用灰+删除态。桌面优先(信息密度高),响应式次之。

**状态与边界**:覆盖 §4 全部状态;空态引导(逐步建项目);错误可重试;大候选/多指标时矩阵的虚拟滚动与列冻结。

**可访问性**:键盘可操作评分矩阵;色彩不作唯一信息载体(否决/风险配图标);对比度 WCAG AA。

**交付物**:信息架构图 → 关键屏线框 → 高保真(P5/P7 优先)→ 组件与状态规格 → 设计 token / 开发 handoff(对接现有视图 SDK 与 REC-A/派生/规则 API)。

**约束**:后端契约已定(见 §6);UI 不引入新写路径,数据走既有命令/查询;图表/附件为本任务新增前端能力,后端附件存储需小幅通用化(另卡)。
