## C. 数据模型

> T-US-001 更新(2026-07-11):本节实施口径已从设计稿 UI 形状模型切换为 M-Next 内核形状模型。Mock 不再建 `Library/Record/SourceCenter` 作为事实源,而是在 `packages/web/src/unisource/model/` 使用 `Workspace`、`SceneTemplate`、`ObjectTypeDef`、`DataObject`、`FieldDef`、`DataFieldValue`、`RelationType`、`DataRelation`、`ViewDef`、`SelectionRef`、`CheckResult`、`Comment`、`ReviewRecord`、`ChangeSet/ChangeItem`、`OutputSnapshot`。`Expression`、`FieldRef`、`ChangeEvent`、`ActivityItem`、`Member`、`PluginDef`、`SimScenario` 作为 UI 层补充模型放在 `model/view-layer.ts`。
>
> ChangeSet 已通用化为 `source: 'manual' | 'ai'`;`AIChangeSet`/`AIChangeItem` 仅保留为 AI 场景别名。`ObjectTypeDef` 表达「产品规格库/渠道销量表」等库的类型定义,`DataObject` 表达具体记录,`DataRelation` 是带独立 id/类型/状态/自有字段/版本/批注的一等关系。后续接真后端时页面只替换 service/store 实现,不按旧 UI 形状改页面。

```ts

interface Member { id: MemberId; name: string; dept: string;        // 王芸/产品·管理员 李晓/研发 陈默/渠道运营 周然/法务 同源AI/代理

interface Record_ { id: string; values: { [fieldId: string]: FieldValue } }    // S3 记录 #001 等 8 条产品
interface FieldAddress { libraryId: string; recordId: string; fieldId: string }

// —— 表达与描述形式 ——
type FormKind = 'grid'|'doc'|'canvas'|'matrix'|'bi'|'ana' | `plugin:${string}`; // 开放集合

  boundLibraries: string[]; lastActivity: ActivityRef }                        // 6 个表达 + 装机系列
interface DocModel { docNo: string; template?: string; binding: FieldAddress;  // Tiptap JSON,含内联节点:
  content: TiptapDoc }                                                         //   refChip{address,state} / dataTableBlock{libraryId,recordId,rows}
type RefState = 'fresh'|'justSynced'|'inserting'|'lowConfidence'|'dangling';

  shownFields: string[]; visibility: { sourceBadge: boolean; fieldRows: boolean; docBadge: boolean; edgeLabels: boolean } }

interface CanvasEdge { id: string; source: string; target: string; label?: string; writeBack: 'interconnect' } // 连线写回「互联关系」
interface MatrixConfig { rowField: string; colField: string; cardFields: string[]; aggregate: 'count' }
interface TemplateDef { id: string; name: string; version: string; slots: SlotSpec[] }  // 装机方案 V1

// —— 变更/活动(双轨,一切可撤销/恢复的基础)——

interface ChangeEvent { id: string; track: Track; actor: MemberId; viaAi?: boolean;
  target: FieldAddress | { exprId: string; what: string };
  old?: FieldValue; next?: FieldValue; syncedRefs?: number; at: string;
```

## D. 状态管理方案

> T-US-001 更新:底座先落 `workspace-store`、`selection-store`、`changeset-store` 三个 store。`workspace-store` 持有唯一 seed 派生的对象/字段/关系/校验/活动流快照;`selection-store` 只保存交互选择,不得写主数据;`changeset-store` 负责 manual/ai 变更集 submit/confirm/reject/acceptItems,落库一律回到 `workspace-store.updateField()`。

沿用仓库既有风格(无 redux/zustand;类 store + Context + 纯函数模块 + `useSyncExternalStore`),零新增状态库依赖:

1. **SourceStore(核心)** — 持有统一数据源树 + 内存 pub/sub「引用同步引擎」(交接规格 07):`write(address, value, meta)` → 更新权威值 → 广播 `FieldChanged` → 订阅方(RefChip/DataGrid/KpiCard/DataTableBlock)刷新并进入 `justSynced`(10s 计时回落,集中在 store 管理定时器,组件只读状态)。所有写入生成 `ChangeEvent`(含 inverse)进 HistoryStore。
2. **HistoryStore** — 双轨(data/view)变更流 + 活动流;支持 undo(Toast 撤销、ActionCard 撤销全部、版本条目恢复,统一走 inverse 重放,数据轨恢复=一次新写入再走同步管线)。
3. **SessionStore** — 当前身份(演示身份切换器:王芸/李晓/陈默/周然 + AI 代理)、权限矩阵求值 `can(member, resource, action)`;越权写 → 生成 ApprovalRequest 而非直接落库(AI 同理)。
4. **ExprStore / CanvasStore / ImportStore / ChatStore / ValidationStore / PluginStore / SimStore** — 各页面域 store,只经 Service 接口(E.2)与 SourceStore 交互;CanvasStore 内选择集(多选)复用/参考现有 `SelectionCoordinator` 模式。
5. **URL 即状态** — `form/layout/tpl/run/drawer` 全部由 searchParams 驱动(react-router);store 不冗余存储路由态;「记住表达上次形式」存 `localStorage`,键前缀 `ui.`(AG-102:仅界面偏好可入 localStorage,对象/字段/关系数据禁止持久化)。
6. **动效状态** — FlowEdge/PulseRing 用 CSS keyframes(dvFlow 0.9s/dvPulse 1.6s);PlayBar 播放进度用 rAF 驱动的 SimStore 时钟;`prefers-reduced-motion` 全局降级为静态。
