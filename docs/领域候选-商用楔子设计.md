# 领域候选 × 商用楔子设计(M-Next profile)

> 目的:把候选领域设计成 M-Next 的 profile(对象/关系/规则/派生/视图/引擎),标清**复用已建 vs 新建**,并按"商用楔子"打分(契合度 / 痛点 / 竞争 / 工作量)。给出主楔子建议。
> 评分:★越多越好(契合度/痛点),工作量与竞争是"低更好"。

---

## 你提的三个

### 1. 技术方案编写(画框架图 → 模型驱动自动生成强语义文档)
- **对象**:方案(根)、系统、子系统、模块、组件、接口、数据流、需求项、指标/KPI、风险、里程碑。
- **关系**:contains(层级)、depends_on、interfaces_with(接口)、satisfies(模块↔需求)、realizes、traces。
- **派生**:模块/接口计数与汇总、指标 rollup、需求覆盖率。
- **规则灯**:完整性(模块缺负责人 / 接口未定义 / 需求无对应模块 = 未覆盖)、一致性(图与文档同源不冲突)、命名规范。
- **视图**:graph(架构框架图)、**document(自动生成的方案文档,章节按模型结构遍历)**、table(模块/接口清单)、matrix(接口依赖 / 需求-模块覆盖矩阵)、tree(分解树)。
- **引擎**:**Render SPI(Md/Docx/Pdf/Html)已建** → 文档生成直接复用;文档=模型的视图,**改模型即重生成,图文永远同源**。
- **复用度 ★★★★★**(graph+document+matrix+render+rules 几乎全有)。**新建**:一个"方案"profile + 文档模板(章节↔模型映射)+ 生成编排。
- **楔子**:痛点普遍(工程师厌恶手写并维护图文一致);差异化强(单一真值源);**可 dogfood——你自己的《技术说明书 V3.3》就是这个**。竞争=Word+Visio 分离 / Confluence,都没模型底座。
- **评:最佳商用楔子。契合 ★★★★★ / 痛点 ★★★★★ / 竞争 低 / 工作量 中。**

### 2. 室内设计(进行中)
- 已设计(户型/房间 + 风热光 + 派生/规则灯)。**作教学/演示极佳**(贴生活、把全部能力串起来)。
- 但作**商用楔子偏弱**:全屋设计市场被 3D 渲染 + 素材库主导(酷家乐/SketchUp 类),M-Next 的数据治理边际价值在这里不是买点,且 3D 是巨大工程。
- **务实商用方向**:不拼全屋 3D,做**"户型合规校核"细分**——采光/通风/日照/消防间距/无障碍**规范校核 + 报告**(复用规则引擎 + render),这反而是 M-Next 能打、对手薄的点。
- **评:最佳演示;商用走"合规校核"细分。契合 ★★★★ / 痛点 ★★★(校核向)/ 竞争 中 / 工作量 中(3D 高、校核中)。**

### 3. UML + 外接开发平台(代码可视化,双向同步)
- **对象**:package/class/interface/method/field/component;**关系**:inherit/implement/depends/calls/contains。
- **视图**:graph(类图/组件图)、tree(包树)、table。**引擎**:Exchange SPI 加 "code↔model" 适配器。
- **难点(诚实)**:多语言解析、**回写不破坏手写代码**、IDE/平台集成;且**重型 round-trip UML 在萎缩**,轻量 diagram-as-code(Mermaid/PlantUML/Structurizr)在涨。这正是 EA/Cameo 深耕且开始退潮的地带。
- **务实版**:先做**单向"代码 → 架构/依赖可视化 + 文档"**(对标 Structurizr / CodeSee,需求真实、工作量可控,且能和 #1 文档生成合流);**双向同步作为远期重注**,别一上来做。
- **评:最难、最 competitive。契合 ★★★ / 痛点 ★★★ / 竞争 高 / 工作量 高(双向)中(单向)。先单向。**

## 建议(收窄成"最短可收费路径")
- **主楔子 = #1 技术方案编写(模型驱动文档)**:复用已建能力最多(Render SPI + document + graph + matrix + rules),痛点普遍、可 dogfood(你的说明书),差异化清晰(图文同源真值)。**这条最可能先收到钱。**
- **旗舰演示 = 室内设计**:留作"贴生活、全能力串联"的对外演示;商用只切"合规校核"细分,不拼 3D。
- **第二楔子(与 #1 协同)= B 工程选型校核 或 A 需求追溯**:都高度复用已建,且把你和 EA/Cameo 的差异(Web 原生数据平台 + 实时派生/规则/追溯)讲实。
- **UML = 先做单向"代码→架构可视化+文档"**(还能并进 #1 的文档生成),双向同步后置。

> 共性洞察:M-Next 最强的地方是**"治理模型 → 多视图(图/表/矩阵/文档)+ 规则 + 派生 + 追溯/血缘"**。凡是"画出关系后要出文档 / 出矩阵 / 做校核 / 查覆盖与影响"的场景,都几乎是复用已建;凡是"拼渲染 / 拼素材库 / 拼双向代码同步"的场景,都是重投入低差异。**沿前者收窄。**
