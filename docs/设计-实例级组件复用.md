# 设计稿 — 实例级组件复用(复用轨)

> 蓝本:`docs/设计-领域定制能力边界.md` §3.8 / §4。本稿补"复用阶梯"里**最缺的一环**:实例层可复用组件/装配。
> 定位:今天只能"整模板实例化",缺细粒度可复用装配;统一在 KerML/SysML v2 的 **definition vs usage** 思想下。**纯设计;实现卡待评审后另拆。**

## 0. 一句话
复用要分层:**元模型层**(值类型/模块/profile)平台基本够得着;**实例层**(可复用的子模型/装配——标准泵、标准窗、一个子系统)**完全缺**。本稿设计实例层复用,核心借 **def/usage**:定义一次、使用多次,改 definition 时 usage 跟随或按版本钉住。

## 1. 现状(已核实)
- **元模型层复用**:值类型/对象类型挂 `template_version`(profile);阶段一已按 profile 隔离类型身份;阶段二在做多 profile 项目 + 映射 + profile 依赖。→ 模块/profile 复用顺着现有路线长。
- **实例层**:`InstantiateWorkspace` 只能从**单个模板整体实例化**进新工作空间;**没有**"把一个可复用装配拖进已有模型、用多次"的机制。
- 写入经命令入口;rm_* 读模型;版本/快照/血缘齐全(可支撑钉版本与出处)。

## 2. 复用粒度阶梯(定位本稿在哪一环)
| 粒度 | 复用什么 | 机制(有/缺) | OMG 借鉴 |
|---|---|---|---|
| 值类型/基元 | 单位、量纲 | 值类型有,缺共享库 | SysML QUDV / SI 库 |
| 类型片段 | 单个 stereotype | 缺跨 profile 引用 | Package element import |
| 模块 | 一组类型+关系+规则 | extends 增量(思想) | Package import/merge、«modelLibrary» |
| Profile/标准库 | 整个领域 profile | 能力市场 + profile 依赖(阶段二) | profile import |
| **实例组件/装配** ← 本稿 | 可复用子模型(泵/窗/子系统) | **缺** | **KerML def/usage、可复用 Block/Part、Modelica 组件库** |
| 项目模板 | 整套起步项目 | scene_template/template_version(有) | 参数化模板 |

## 3. 核心模型:definition vs usage

### 3.1 可复用片段(definition)
- **`reusable_assembly`**(定义):一个"装配/组件"= 一组 object + relation 的**可复用子图**,带:`assembly_id, name, profile(所属 template_version), version, params(可配置点 jsonb), 内容(对象/关系模板)`。
- 定义 = 在某 profile 下声明一个**命名的、参数化的子模型蓝图**。版本化(随 template_version 思想推广)。

### 3.2 放置(usage)
- 在某工作空间里**放置**一个 assembly = 实例化其子图到该工作空间,生成一组真实对象/关系(usage)。
- 一个 definition 可被**放置多次**(多 usage);每个 usage 记 `assembly_id + version + 放置参数 + 来源出处`。
- 经**既有命令入口**落地(createObject/createRelation 批量;一次"放置命令" PlaceAssembly 包裹)。

### 3.3 def 改了,usage 怎么办(两种语义)
- **by-copy(克隆)**:放置时拷贝子图,usage 独立演化;改 definition **不影响**既有 usage(可手动"升级")。
- **by-ref(引用)**:usage 绑定 definition 版本;改 definition 升版 → usage 可"跟随升级"或**按版本钉住**。
- **混合 + detach**:by-ref 可"脱钩"转 by-copy。
- v1 建议先 **by-copy + 版本钉住记录**(最简、可追溯),by-ref 跟随升级后置。

## 4. 治理(让大规模复用不塌)
- **版本化**:definition 版本钉住;消费者(usage)记锚定版本;升级显式。
- **extends 只增不改**:definition 演进遵循增量扩展,不破坏既有 usage。
- **命名空间隔离**:阶段一的 (profile, code) 隔离是前提(装配内类型不撞)。
- **血缘/出处**:每个 usage 可追"来自哪个 definition / 哪个版本 / 谁放的"——接现有血缘机制。
- **废止/迁移**:definition 可 withdraw(沿用模板 withdrawn 机制思想),既有 usage 不受影响。

## 5. 视图 / 交互(接交互面)
- **目录浏览**:能力市场延伸到**实例级目录**(可复用装配库);按 profile/标签检索。
- **拖放放置**:在视图里把 assembly 拖入模型(交互面;合法性由 profile 元模型约束)。
- **usage 标识**:视图中 usage 对象标出"来自库 X 版本 v";区分 by-ref/by-copy。

## 6. 与其它轨/OMG
- **KerML/SysML v2 def-usage**:本稿的 definition/usage 直接对标,是统一复用阶梯的主线。
- **Modelica 组件库**:层次化组件复用的范本(深层嵌套包 → 嵌套装配)。
- **能力市场**(MANIFEST-TAGS 后):实例级目录复用其检索/装载。
- **结果时序脊**(另稿):含仿真行为的装配,其 run 结果同样进时序脊。

## 7. 分期
- **T1 最小可用**:`reusable_assembly` definition + PlaceAssembly 命令(by-copy)+ 出处记录 + 目录列表只读端点。一次加性迁移(新表)。
- **T2**:by-ref + 版本钉住/跟随升级;拖放放置 UI;usage 来源标识。
- **T3**:实例级目录接入能力市场;跨组织库共享;参数化高级(条件/循环子图)。
