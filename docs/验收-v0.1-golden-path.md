# v0.1 黄金路径验收脚本（目标：陌生 Windows 机器 ≤30 分钟走通）

> 计时从解压/克隆完成算起。每步附预期结果；任何一步不符即停，按文末速查表排查。

## 0. 前置（一次性，约 10 分钟）

1. Docker Desktop 已安装并启动（托盘图标绿色）。
2. JDK 21（推荐 Temurin：`winget install EclipseAdoptium.Temurin.21.JDK`），`java -version` 显示 21.x。
3. Node ≥22（`node -v`），启用 corepack：`corepack enable`。
4. **禁止**从别的机器拷贝 node_modules（pnpm 链接会全断）；本机 5432 端口无其它 PostgreSQL 服务占用（`netstat -ano | findstr :5432` 应无 postgres.exe）。

## 1. 安装与构建（约 10 分钟）

```bat
cd /d <仓库目录>
corepack pnpm install --frozen-lockfile
node scripts/run-maven.mjs -DskipTests package
```

预期：安装无 ERR；maven 末尾 BUILD SUCCESS。

## 2. 启动（约 3 分钟）

```bat
corepack pnpm dev:up
```

预期：compose 5 容器就绪 → `postgres healthy` → 后端后台启动 → 前端打印 `Local: http://localhost:5173/`。
后端日志在 logs/server.log，就绪标志 `DEV SEED: ... ready`（seed 自动创建示例项目）。

## 3. 黄金路径（约 5 分钟，全程零命令行）

| # | 操作 | 预期 |
|---|------|------|
| 1 | 浏览器开 http://localhost:5173，任意账号登录 | 项目列表显示「技术方案 Demo」与室内项目 |
| 2 | 点「技术方案 Demo」 | 文档树+表格+校验面板默认打开；顶部概览条：总功耗 820W / 预算 800W · 超预算（红） |
| 3 | 表格中把某模块 功耗 从 260 改为 200 并保存 | 数秒内概览条自动变 760W · 在预算内（绿），全程不点任何按钮 |
| 4 | 把该值改回 260 保存 | 概览条回到 820W · 超预算（红） |
| 5 | 点导出 → docx | 浏览器下载 .docx |
| 6 | 用 Word 打开，视图→导航窗格 | 章节树：方案→各模块；参数表显示「功耗(W)」等中文标签；模块描述为正文段落；文末「校核结论」表含 阻断 项 |

## 4. 停止

```bat
corepack pnpm dev:down
```

## 常见问题速查

| 症状 | 原因 | 处理 |
|---|---|---|
| 后端等待就绪超时 + 日志 UnsupportedClassVersionError | Java 不是 21 | 装 Temurin 21，新开终端重试 |
| 日志 password authentication failed for "mnext" | 本机另一个 PostgreSQL 抢 5432 或旧数据卷 | 停本机 PG 服务；仍不行则 `docker compose down && docker volume rm m-next_postgres-data` 后重启 |
| 前端 Cannot find module .../vite | node_modules 是拷贝来的/不完整 | 删各级 node_modules 后 `corepack pnpm install --frozen-lockfile` |
| 打开 8080 页面样式异常 | 看了后端旧打包页 | 用 5173 |
| 改了 seed/manifest 但界面没变化 | seed 对已有库跳过重种 | 重置数据卷（见上）再 dev:up |
| verify 在 repackage 步骤失败 Unable to rename | dev 后端占着 jar | 先 `corepack pnpm dev:down` 再 verify |

## 开发者门禁备忘

前端改动合并门槛 `corepack pnpm verify:web`（约 1~2 分钟）；后端/契约改动与发布前跑全量 `corepack pnpm verify` + `node scripts/check-no-skipped.mjs`（Skipped:0）。
