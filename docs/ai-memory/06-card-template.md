# 开发卡模板（发 Codex 用）

## 结构（每张卡必含）

```
先完整阅读仓库根目录 AGENTS.md 并遵守全部 AG 规则，再开始本卡。

【本卡】T-V01-x：<一句话目标>

基线与分支：
- 开工前确认在 main、git status 干净、上一张依赖卡已合并；否则停下回报。
- 新建分支 feat/T-V01-x-<slug>。

背景事实（已审计核实）：<3~5 条，给足上下文，防止 Codex 自行探索跑偏>

要做的事（仅此 N 件）：<编号列出，能写文件路径就写>

红线（违反任一条即返工）：
- 只实现本卡，只改列出的文件及其测试；
- 不做顺手重构、不新增依赖、不改核心机制；
- 不修改 /docs/spec 与 contracts（契约卡除外，且契约卡必须人审 diff）；
- 用户可见文案不得暴露内部词（UUID、objectType 代码、原始错误码）；
- 遇到"需改契约/能力不足/API 取不到" → 停下回报，不绕路。

测试要求：<具体断言，不写"补充适当测试"这种软话>

完成时必须报告：
1. 改动文件清单；
2. 验证输出（见下方分级）；
3. 手动验收路径（从 dev:up 到眼见为实的逐步操作）。
```

## 审查分级（快节奏模式，2026-07-03 起）

- **低风险卡**（纯前端、seed 数值、文档、杂项）：verify 绿 + 本人手动验收过 → 直接合并，Fable 合并后审查，问题走修复卡。
- **高风险卡**（契约、kernel/engines、跨包改动、导出管线）：Fable 审查通过后才可合并；契约 diff 必须人审。

## 验证分级（提速规则）

- **纯前端卡**：开发期 `corepack pnpm --filter @m-next/web test` + typecheck 即可；
  合并前跑一次全量 `verify` + `check-no-skipped.mjs`。
- **后端/契约/seed 卡**：每次交付都跑全量 verify。
- **文档卡**：无需 verify，直接 main 提交并通报。

## 并行规则

发卡时标注「可与 T-V01-y 并行」的前提：两卡改动文件集合零交集，且无语义依赖。
契约卡（4a 类）人审期间，恒可并行发一张杂项/文档卡。

## 验收纪律

- seed/manifest 卡：验收前必须重置数据卷（见 03-run-commands.md）
- verify 前必须 dev:down（jar 文件锁）
- 任何一步验收断了：当天只修这一步，不发新卡
