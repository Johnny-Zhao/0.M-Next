- 2026-07-15 **电脑采购插件边界**：电脑采购是 M-Next 的第一个领域插件验证样例，用于验证统一数据源、语义 Profile、派生校验、多视图和文档链路；不得将其扩展为独立采购 ERP。未来领域插件必须通过注册机制接入通用工作台。

- 2026-07-04 分支规则最终版（v3.1，取代此前全部分支规定）：①人改代码默认直接 main，push 前 verify:web/verify 绿即可；②给 Codex 的任务一条分支从头用到尾（中途修复/返工都在原分支上继续，不另开 fix 分支），验收通过整条合并，烂尾整条丢弃；③仅跨多天的大块头工作才专门开分支。

- 2026-07-03 **工作流 v3（现行，覆盖 v1/v2 的流程部分）**：背景——原重流程是前任（不写代码）设计的，现任项目主为八年前端开发。规则：**代码默认都由 Codex 实现**（前后端皆是）；前端任务用轻简报（目标+文件+一句验收即可），产出由业主本人快速审查合并，Fable 不设卡；后端/契约任务用 06 格式，Fable 审查；契约变更人审。业主可随时亲自改代码但非默认义务。底线不变：main 合并点 verify 绿+Skipped:0；01-do-not-do 范围清单。AGENTS.md 对 AI 代理保持强制力，对人是架构参考。
- 2026-07-03 工作流 v2 双轨制（已被 v3 覆盖，留档）（业主为八年前端开发，流程按此重校）：**前端轨**=业主主导，自写或指挥 Codex，自审自合，小改动可直提 main（合并通报），测试只写纯函数/状态逻辑，Fable 仅做范围刹车；**后端/契约轨**=Codex 实现+Fable 审查，契约必人审；后端卡模板缩为四段（目标/允许范围/硬红线/验收）。底线不变：main 合并点 verify 绿、Skipped:0、do-not-do 清单生效。
- 2026-07-03 v0.1 收尾方向修订（用户拍板）：Word 导出合龙后，优先做**最小创作能力**（从模板新建方案项目、文档树上加章节/模块、填参数、导出自己的 Word；复用既有 NewProjectWizard 与 CreateObject/CreateRelation 命令，不复活能力市场）；杂项演示打磨降级为低优先尾巴；demo 种子数据退居回归资产。dogfood：第一个真实用户是作者本人。
