# v0.1 目标（权威，冲突时以本文为准）

## 一句话定位

M-Next v0.1 = 面向工程方案/技术说明书的**结构化活文档工作台**。
文档入口、模型内核：文档背后是统一工程数据模型（需求/参数/组成/关系/方案/校核），图表由模型驱动，改一处全局联动，导出 Word 交付物。AI 只是结构化入口，不是产品本体。

不是：Word 生成器；不是：完整多领域 MBSE 平台。

## 黄金路径（一切开发的判断标尺）

打开 TECHDOC_DEMO → 文档式工作台（章节/内容块）→ 查看需求/参数/组成/关系/方案/校核 → 改一个参数 → 派生值+校核灯+图表联动 → 文档同步 → 导出章节化 Word。

一项能力若不推进此闭环，v0.1 默认不做。

## v0.1 必须证明的 4 件事

1. 文档像文档（章节、内容块、导出）
2. 数据像模型（结构化对象，非散文）
3. 图表像视图（来自统一模型，非死图）
4. AI 像入口（抽取→人确认→入模型；可假实现）

## 发布最低标准

1. 陌生 Windows 机器按文档 ≤30 分钟跑通
2. UI 零命令行打开示例项目
3. 改 1 个参数看到派生+校核联动
4. 导出的 docx 有章节层级、参数表、校核结论表
5. 黄金路径无未处理报错
6. main 上 verify 全绿、Skipped:0
7. 至少 1 个本人之外的用户完整走通
