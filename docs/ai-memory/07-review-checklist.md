# PR/卡产出审查清单（Fable 审 Codex 用）

1. **范围**：`git diff main --stat` 文件清单 == 卡内允许清单？多一个文件即问责。
2. **红线抽查**：有无顺手重构、新依赖（package.json/pom/lockfile 变动）、契约/spec 触碰、引擎级文件改动。
3. **架构规矩抽查**（AGENTS.md）：
   - 查询是否带 workspaceId+分页/范围（AG-202/203）
   - 写操作是否走命令入口（AG-110）
   - views/web 是否越界 import（AG-100/101）
   - 测试是否用 sleep 等异步（AG-504）
4. **测试是真的吗**：断言具体数值/状态，而非"不抛异常"；失败路径有覆盖；Skipped:0。
5. **语义正确性**（最容易错的地方，逐卡想一遍）：
   - 例：自动校核必须全工作空间跑（objectType=null），因为规则挂在别的对象类型上
   - 例：派生值是读时求值，测试改值后要重读而非重算缓存
6. **文案**：用户可见字符串无 UUID/objectType 代码/原始错误码；中文、给出下一步动作。
7. **室内回归**：改动是否可能影响 interior 工作台默认行为？有疑问就加验收步骤。
8. **验收路径可执行**：照着能点出来，包含失败态；seed 卡含数据卷重置。
9. 审查结论三选一：合并 / 带小修合并（列出小修）/ 整张返工（说明违反哪条）。
