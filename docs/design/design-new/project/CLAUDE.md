# 同源 UniSource — 项目维护规则（设计系统模式）

本项目按设计系统维护，不是一次性的画布探索。每次输出遵循以下结构与流程。

## 文件结构
- `同源 主版本页面集.dc.html` — **当前主版本（MAIN）**。左侧页面导航，14 屏，每屏带版本号。所有正式修改落在这里（原地更新，升版本号），不要只在归档画布里加新图。
- `设计系统 Design System.dc.html` — 设计 Token、全局组件库、交互状态矩阵、术语表、页面复用关系、变更协议。
- `交接规格 Handoff Spec.dc.html` — 前端交接：页面地图/组件清单（G/B/P 三级）/Token/响应式 1440·1280/状态清单/交互规则/Mock 边界/未解决问题。交接内容变更时同步更新。
- `同源 UniSource 关键屏.dc.html` — 探索历史归档（turn 1–9，1a…9c）。只读参考，除非用户明确要求，不再往里加内容。**不交接。**

## 全局规则变更流程（必须遵守）
1. 用户提出全局规则修改（token、组件、术语、交互模式）。
2. 先更新 `设计系统` 文件中对应的 Token/组件/状态定义。
3. 按设计系统内「页面复用关系」判断受影响页面。
4. 在 `同源 主版本页面集.dc.html` 内**原地更新**所有受影响页面（升该页版本号，如 v1 → v2）。
5. 回复中输出：**受影响页面清单**（页面名 + 变更点 + 新版本号）+ 未受影响页面简述。
6. 不确定影响范围时先列清单向用户确认，再动手。

## 画布规范
- 屏幕尺寸 1440×900，`data-screen-label` 必填。
- 样式全部内联；仅 @font-face/@keyframes/body reset 在 helmet。
- 动画元素在 renderVals 用 React.createElement 构建（如 simSvg/simPulse）。
