# 空项目到 DOCX 黄金路径验收脚本

目标: 从新建技术方案项目开始,不依赖 seed、SQL 或 AI,完成对象创建、正文填写、校验闭环、需求覆盖和 DOCX 导出。

## 前置

```bat
corepack pnpm dev:up
```

预期: 前端显示 `http://localhost:5173/`,后端服务可用。

## 路径

| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开首页,新建项目,模板选择「技术方案」 | 进入工作台,模型树默认打开,校验面板可见 |
| 2 | 点顶栏「新增模块」,填写名称、职责、功率(W),提交 | 模块出现在图/树中,并挂到方案根下 |
| 3 | 在文档或属性面板填写该模块正文 body | 文档面板能看到正文内容 |
| 4 | 把模块 `power_w` 调到超出方案预算,保存 | 校验面板出现 R-TD-PWR 红色阻断 |
| 5 | 把 `power_w` 调回预算内,保存并等待自动校验 | 红色阻断消失,校验恢复通过或仅剩其他真实告警 |
| 6 | 点「新增需求」,填写需求编号、需求内容、优先级 | 需求出现在字段总表/矩阵中 |
| 7 | 打开矩阵,在 module x requirement 的 `proposal_satisfies` 单元格建立覆盖关系 | 覆盖总览显示已覆盖数增加,未覆盖数减少 |
| 8 | 点导出 DOCX | 浏览器下载 `.docx` 文件 |
| 9 | 用 Word 打开,视图 -> 导航窗格 | 看到方案标题和模块章节 |
| 10 | 检查正文、参数表、文末校核结论表 | 正文段落存在;参数表含功率等中文标签;文末有校核结论表 |

## 不在本脚本验收

- 需求、接口和覆盖矩阵进入 DOCX 正文属于后续增强;本脚本只要求它们完成建模和覆盖校验闭环。
- 不手动改数据库,不运行 seed 重置,不使用 AI 抽取。

## 收尾

```bat
corepack pnpm dev:down
```
