## 目标

落地 JSON **双向**轻交换:导出(读模型→JSON 制品)+ 导入(解析→映射→**diff 预览**→确认→**经 M1 命令回写**)。外部 JSON 永不作事实源(AG-507),回写全经命令入口(AG-110),交换组只做纯解析/映射/diff、不写主数据(AG-108)。

## 涉及文件(封闭清单)

- `packages/engines/src/main/java/com/mnext/engines/exchange/`:`JsonArtifact`(制品 record,见设计稿 §3.1)+ `JsonCodec`(Jackson 序列化/解析 JsonArtifact ↔ `DataSet`,复用 701 的 DataSet)+ `ArtifactMapper`(按 `key`/`sourceKey`/`targetKey` 对齐:已存在→更新,缺失→新建;关系按 (relationType, sourceKey, targetKey) 对齐)。**纯运算,无主数据写、不发命令。**
- server:`ExchangeController`——`GET /workspaces/{id}/exchange/json/export?objectType=`(读模型→JSON 制品)、`POST .../json/preview`(JSON→解析+映射→与当前读模型集 `StructuredDiff.diff` →返回 DiffResult,**不写**)、`POST .../json/apply`(按 diff 逐项经 `KernelCommandService` 发 M1 命令回写);DTO。
- 测试(engines 纯单测 + server Testcontainers 集成;**非 relay 的 @SpringBootTest 加 `mnext.outbox.enabled=false` 关实时调度,消除拆机噪声**)。**禁止新增依赖(AG-502)。**

## 行为要求(逐条可测)

1. **导出**:`/export` 由读模型(rm_*,501)拼 `JsonArtifact`(objects 含 objectTypeCode/fields/key=objectId;relations 含 relationTypeCode/sourceKey/targetKey/fields)。只读、不写。
2. **解析/映射(AG-507)**:`/preview` 把 JSON 解析为内部 `DataSet`,按 key 映射(不依赖内部 UUID 直传);JSON 不作读写目标。
3. **diff 预览**:`/preview` 返回 `StructuredDiff.diff(current, parsed)` 的多维 DiffResult(对象/属性/关系 added/removed/changed),**不产生任何写**。
4. **回写(AG-110)**:`/apply` 按 diff:added 对象→`CreateObject`;changed 字段→`UpdateFields`(带 expectedFieldVersion,冲突→KERNEL-409);added 关系→`CreateRelation`;**removed 默认不自动删**(需显式 `confirmRemovals` 才接 Archive/SoftDelete);命令 source 标 `import`;全程经 `KernelCommandService`,engines/exchange 不直接写主数据。
5. **冲突**:apply 时字段版本漂移→KERNEL-409→返回未应用项 + 冲突详情(与表格/502 同一冲突语义),已应用项不回滚(逐项)。
6. **隔离(AG-108/201)**:engines/exchange 无主数据写 SQL、不 import kernel/internal;解析/diff 不在命令事务内;架构断言覆盖。
