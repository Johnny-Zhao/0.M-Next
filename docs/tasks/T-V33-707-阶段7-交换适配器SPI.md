## 目标

把 JSON/ReqIF 两遍重复的交换骨架,抽成 **`ExchangeAdapter` SPI**(纯,engines/exchange)+ **`AdapterRegistry`(JDK ServiceLoader)**,把 server 端点统一为 **`/exchange/{format}/export|preview|apply`** 按 formatId 派发,**行为对现有 702/705 零变**。**重构,不加功能;为插件留插座。无新依赖、无迁移、无新命令/事件。**

## 涉及文件(封闭清单)

- **新增** `packages/engines/src/main/java/com/mnext/engines/exchange/ExchangeAdapter.java`:SPI 接口(formatId/mediaType/importToDataSet/exportFromDataSet)。
- **新增** `.../exchange/json/JsonAdapter.java`:实现 SPI,**包装现有** `ArtifactMapper`/`JsonCodec`(不改其逻辑)。
- **新增** `.../exchange/reqif/ReqIfAdapter.java`:实现 SPI,**包装现有** `ReqIfCodec`/`ReqIfMapper`(不改其逻辑)。
- **新增** `packages/engines/src/main/resources/META-INF/services/com.mnext.engines.exchange.ExchangeAdapter`:登记 JsonAdapter、ReqIfAdapter。
- **新增** `.../exchange/AdapterRegistry.java`:`ServiceLoader` 加载 + 按 formatId 索引;未知 format → 抛 `KERNEL-400-SCHEMA-INVALID`(或由 server 转 404)。
- **修改** `packages/server/.../ExchangeController.java`:新增通用 `/exchange/{format}/export|preview|apply`,经 `AdapterRegistry` 取 adapter,**复用现有 apply 编排 + 快照基准**;**保留** `/exchange/json/*`、`/exchange/reqif/*` 既有端点(或令其委派到通用路径),行为不变。
- **新增** 测试:`AdapterRegistryTest`(ServiceLoader 发现含一个**测试用 adapter**,证明外部可插)+ `ExchangeAdapterSpiTest`(json/reqif 经 SPI 往返)。扩 `ExchangeArchitectureTest` 覆盖新类仍纯。
- **新增/更新** `docs/插件-交换适配器开发指南.md`(简版扩展点说明:实现 SPI + META-INF/services + 在 M2 建类型)。
- **禁止新增依赖(AG-502)**;ServiceLoader 为 JDK 内置。

## 行为要求(逐条可测)

1. **SPI 纯**:`ExchangeAdapter` 及 Json/ReqIf 实现在 engines/exchange,**无 Spring/JDBC/SQL/命令**(架构断言)。
2. **行为零变**:`/exchange/json/*` 与 `/exchange/reqif/*` 既有端点的**输入输出与既有 702/705 测试全部不变、仍绿**。
3. **通用派发**:`/exchange/{format}/preview|apply|export` 按 format 取注册 adapter;`format=json`/`reqif` 与既有端点等价;未知 format → 400/404(明确,不 500)。
4. **apply 编排共享**:diff→发 CreateObject/UpdateFields(expectedFieldVersion)/CreateRelation、source=`artifact_sync`、removed 不自动删、KERNEL-409→unapplied——**只此一份代码**,与格式无关。
5. **导出走快照**:通用 export 支持 `base=snapshot:{id}`(AG-208)与 current。
6. **可插性**:`ServiceLoader` 能发现 classpath 上的 adapter;测试放一个 `TestEchoAdapter` 于测试源,断言被 `AdapterRegistry` 发现并可调用(证明插件机制成立,**不进生产代码**)。
