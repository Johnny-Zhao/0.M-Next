## 背景与关键决策(必读)

**现状勘误(务必先读代码):** unisource **没有任何评审/批注 UI**——`model/kernel.ts` 的 `ReviewRecord`(审批审计:submit/approve/reject/accept)与 `Comment`(锚定评论:anchor/body/author/resolved)是 **model-only**,全仓 `.tsx` 无展示,`addRelationComment` 无调用点。所以本卡**不是"接线",而是新建一个批注 drawer + 接内核**。内核侧已全就绪:`view-client.annotations(ws,…)→ReviewAnnotation[]` 读、`command-client.createAnnotation/resolveAnnotation/reopenAnnotation` 写。

**概念对齐:** 内核 `ReviewAnnotation{id, roundId, targetType:object|field|relation, targetId, fieldCode?, anchoredDataVersion, severity, body, status:open|resolved, createdBy, createdAt, resolvedBy, resolvedAt}` ↔ 本地**锚定评论**(近 `Comment`),**不是** `ReviewRecord`(审批审计,后者与 017c 审批流保持不动)。

**决策 1 —— 新建批注 drawer(本卡的 UI 主体)。**
新增评审批注 drawer,**镜像现有 AI 对话 drawer 的挂载与开关**(`?drawer=review`,对照 `expr-page.tsx:61` 的 `search.get("drawer")==="chat"`):锚定当前 expr / 选中对象,列批注(open/resolved、severity、作者、时间)+ 加批注(body + severity)+ resolve / reopen。**⚠️ drawer 挂载点(镜像 chat)是本卡定的,审查确认;若更偏好 inspector tab 我改。**

**决策 2 —— 模式注入 + 异步 fire-and-forget(对齐 017a/b)。**
新增 `state/annotations-store.ts`:持 `KernelAnnotationSource`(gateway 子集:`setActor`+`listAnnotations`+`createAnnotation`+`resolveAnnotation`+`reopenAnnotation`),经 `setKernelSource(src|null)` 由 boot 注入;`kernelAnnotations` 片 + `busy`;异步 `refresh(targetId?)`/`create(...)`/`resolve(id)`/`reopen(id)`(**fire-and-forget**:setActor→命令→刷新→Toast;失败只 Toast、不抛、busy 复位)。**Mock 模式** drawer 显示本地 `comments`(seed),不发内核。

**决策 3 —— create 的 anchoredDataVersion 取当前对象版本。** 加批注前从工作区取该 target 对象的 `version` 作 `anchoredDataVersion`(内核按此锚定数据版本);relation/field target 同理取所属对象版本。

**决策 4 —— actor 随角色 + 权限投影。** 命令前 `setActor(currentMemberId)`;**周然(VIEWER)只读**——drawer 加批注/resolve 按 `projectSpaceRole`(017c)投影 gate,VIEWER 隐藏写操作、可读。

**决策 5 —— 演示简化。** `severity` 用小枚举(`info|warn|block`);`roundId` 单轮置 `null`(不做多轮评审管理)。

**范围裁剪(写清理由):**
- **不动 `ReviewRecord` 审批审计**(与 017c 审批流独立)。
- **不做多轮评审 / round 管理、不做批注→校验(G9 忽略)联动**(另立)。
- **不改 016–019 已成面**。
