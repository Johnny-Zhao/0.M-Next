## 目标
设计**实例层组件/装配复用**:可复用模型片段(标准泵/窗/子系统)的定义、放置、引用语义、目录浏览与版本治理,统一在 KerML/SysML v2 的 **definition vs usage** 思想下。

## 设计稿须覆盖
1. **可复用片段模型**:一个"装配/组件"= 一组对象+关系(子图)的可复用单元;其定义(definition)与放置(usage)的数据表达;参数化点(可配置字段)。
2. **def/usage 语义**:定义一次、使用多次;改 definition 时 usage 跟随 vs 按版本钉住的策略;与 extends「只增不改」、命名空间隔离(阶段一)的关系。
3. **by-ref vs by-copy**:共享库件(引用,随库更新)与克隆(拷贝,独立演化)两种放置语义;混合与转换(detach)。
4. **复用粒度阶梯落地**:值类型库 / 模块(Package import-merge)/ profile 库 / 实例装配 / 项目模板 各自的存储与引用机制;与能力市场(检索/装载)的衔接,延伸到**实例级目录**。
5. **治理**:版本化(template_version 思想推广到库件)、消费者钉版本、血缘/出处(放置来源可追溯)、库件废止/迁移。
6. **视图/交互**:目录浏览 + 拖放放置(交互面)、放置后的 usage 在视图中的标识(来自哪个库/版本)。
7. **OMG 借鉴**:KerML def/usage、SysML 可复用 Block/Part、UML Package import/merge、«modelLibrary»、Modelica 组件库层次。
8. **分期与依赖**:最小可用(单装配 by-copy 放置)→ by-ref + 版本钉住 → 实例目录/市场;与 WORKSPACE-PROFILE、映射 profile 的关系。
9. **红线**:写入经命令入口、视图只读零拷贝、契约/迁移人工发起。
