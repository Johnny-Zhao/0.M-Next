## 目标

落地 **XMI 最小子集的双向交换**:导出 = 快照/当前读模型 → XMI XML;导入 = 解析 XMI → 按 `xmi:id` 映射内部 DataSet → `StructuredDiff`(vs 快照/current)→ 冲突 → 经 **M1 命令**回写(承 702/705)。**engines/exchange 纯解析/映射;回写在 server 经命令入口(AG-110);用内置 XML,无新依赖。**

## 语义边界(必读,写进 PR 说明)

XMI/UML 本质描述**模型(类/类型)**,本卡采用**"结构化对象图"近似映射**(非完整 MOF/M2 对齐,后者另排):
- `packagedElement xmi:type="uml:Class"` → **对象**(`xmi:id` = key;`name` 属性 → 字段 `name`;objectTypeCode 约定固定为 `uml_class`)。
- `ownedAttribute xmi:type="uml:Property"`(类内) → 该对象的**字段**(Property 的 `name` → fieldCode;若有 `<defaultValue value=...>` → 该字段值,否则值为属性名字符串)。
- `packagedElement xmi:type="uml:Association"` → **关系**(`xmi:id` = relationId;relationTypeCode 约定 `uml_association`;两端取 `memberEnd`/`ownedEnd` 引用的 Class `xmi:id` 为 sourceKey/targetKey)。
- **明确不做(本卡)**:真实 MOF 元模型/M2 对齐、profile/stereotype、OCL、generalization、多重性(multiplicity)、嵌套 package 层级、datatype 解析、xmi:idref 跨文件引用。

## 行为要求(逐条可测)

1. **导出**:`export` 由快照(AG-208,base=snapshot:{id})或 current 组装 XMI——DataSet 的 object→uml:Class、字段→ownedAttribute、关系→uml:Association;含 `xmi:version`/命名空间(uml、xmi)头;只读。
2. **预览**:`preview` 解析 XMI→映射→`StructuredDiff.diff(base, parsed)`→DiffResult(**零写**,AG-201)。
3. **应用**:`apply` 按 diff 发 M1 命令回写(承 705 语义:added→CreateObject、changed→UpdateFields 带 expectedFieldVersion、relation added→CreateRelation;source=artifact_sync;**removed 不自动删**;KERNEL-409 冲突逐项落 unapplied、不回滚)。
3.5 **往返**:`toDataSet(parse(serialize(ds)))` 语义保身份(objectId/类型/字段/关系一致)。
4. **健壮性**:非法 XML / 缺 `xmi:id` / Association memberEnd 指向不存在 Class / 未知 `xmi:type` → 明确拒绝(`KERNEL-400-SCHEMA-INVALID` 或 400),不静默吞。
5. **隔离**:engines/exchange/xmi 纯——无主数据写、无命令、不被 kernel import(AG-108);回写唯一通道是 server 经 `KernelCommandService`(AG-110);外部 XMI 文件永不作事实源(AG-507)。
