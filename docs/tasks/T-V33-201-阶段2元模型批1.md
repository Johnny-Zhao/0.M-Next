## 行为要求(逐条可测)

1. **DefineObjectType**:在指定 draft 模板版本下建对象类型;`(workspace_id, code)` 唯一(承 V1 约束);目标模板版本若 `published` → 拒绝 `KERNEL-409-TEMPLATE-VERSION-IMMUTABLE`;`template_version_id` 允许 NULL(无模板直挂,兼容 demo)。
2. **DefineFieldDef**:归属对象类型必须存在;`data_type` 必须在封闭集 `string|text|integer|number|boolean|date|datetime|enum|ref|json`,否则 `KERNEL-400-SCHEMA-INVALID`;`constraints` 与 `data_type` 相容性校验(如 enum 必须有非空 `enumValues`、ref 必须有存在的 `refObjectTypeCode`、number 的 `min≤max`),违例 `KERNEL-422-FIELD-CONSTRAINT-INVALID`(details 列出问题);`pattern` 长度上限 256 且拒绝灾难性回溯模式(简单静态检查,无法判定则拒绝)。
3. **DefineRelationType**:source/target 对象类型存在;`hierarchical=true` 必须 `cardinality=one_to_many`(承 V2 注释约束),否则 `KERNEL-422-FIELD-CONSTRAINT-INVALID`;`semantics ∈ {weak,strong}`。
4. **FieldValidator 挂点**:CreateObject/UpdateFields 写入前,按字段定义校验值:类型不匹配 / 必填缺失 / 越界 / 越长 / 非枚举 / 不匹配 pattern / ref 指向不存在对象 → `KERNEL-422-FIELD-VALUE-INVALID`(details 逐违例字段);**校验在命令事务预检内完成,零出站(AG-201)**;校验器为纯函数,不写库。
5. 审计:三命令均填 `created_by/updated_by`(认证上下文,AG-321);事务内只写元模型表 + 预检(AG-201);**本批不发元模型事件**(进 Outbox 属批2/addendum,留挂点)。
