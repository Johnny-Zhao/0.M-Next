# 室内设计工具 → M-Next 映射与可行性评估

- 评估日期:2026-06-19。候选验证域之二(域之一=卫星能源分系统)。基于 main(至 v1.32:元模型/泛化/值类型、规则、派生/计算含 interp、模板生命周期、SysML/总线 profile、联邦 M2M、能源闭环、仿真 SPI/L0、交换适配器)。
- 口径:M-Next 在本域扮演**"统一数据 + 分阶段流程 + 选材成本 + 工程估算 + 仿真编排"中枢**,**不是几何内核、不是物理求解器**。采光/气流/热由外部工具算,**数据集成回平台**(输入快照喂出去、结果回灌成模型数据 + provenance,下游闭环消费)。

## 0. 结论

**可行,且是比能源更强的通用性证据**(航天 + 室内设计同底座)。早期设计(功能区→选材)+ 工程估算级分析 = profile 配置级,复用能源那套。三个物理仿真**外挂求解器、数据集成回平台**——正是平台既有的"快照出→外部算→结果回灌(命令入口+provenance)→下游闭环"模式(同 SimulationEngine SPI / M2M)。**唯一新地基 = 几何/空间数据集成层**(数据集成,非 CAD 内核),工作量中等、边界清晰。

## 1. 核心架构:仿真外挂 + 数据集成回平台(本域关键)

```
平台模型(房间/材料/开口/几何引用)
   │  导出快照(snapshotId,只读)
   ▼
外部求解器(Radiance 采光 / CFD 气流 / EnergyPlus 热)   ← 平台不算
   │  结果(每房间照度/采光系数、每区 ACH/风量、每区热负荷/温度)
   ▼
经命令入口回灌为模型字段/对象 + provenance(哪次 run、哪个工具、哪份输入快照)
   │
   ▼
下游闭环:派生(成本/裕度)、规则(照度<阈值告警)、选材(换材料→重算)
```

- **接缝**:复用 **SimulationEngine SPI + 交换适配器**(输入=snapshotId,AG-208;结果回灌走命令,AG-110;只读源,AG-105)。
- **结果即一等公民数据**:照度/换气/热负荷成为对象上的字段(带 provenance),下游派生/规则/选材直接消费——这就是"数据在平台上体现"。
- **不锁定工具**:每种仿真一个适配器(平台↔工具),换工具换适配器,模型不变。

## 2. 六阶段映射

| 阶段 | 能力 | 承载方式 |
|---|---|---|
| 功能区 | 房间/区域划分、面积、相邻关系、用途 | 【配置】对象+字段+关系(几何=参数级:面积/层高/朝向/相邻) |
| 初步设计 | 布局、开口(门窗)、流线 | 【配置】+【几何集成·参数】;高保真布局图=引用工件 |
| 风格设计 | 风格标签、配色、意象 | 【配置】(多为描述性字段/引用);渲染图=外部,引用回挂 |
| 选材 | 材料库(光学反射率/热工 U 值/价格)、选型 | 【配置】+【派生】产品库+选型+成本汇总(**直接复用能源**) |
| 水电暖气走向 | 管线/回路/风管拓扑、负荷 | 【配置】拓扑关系 +【派生】负荷汇总;clash/3D 走向=高保真几何外部 |
| 全屋智能 | 设备、场景、联动规则 | 【配置】设备对象 +【规则】联动 +(可选)行为执行挂 SPI |

## 3. 几何/空间数据集成层(新地基,scoped)

**不是 CAD 内核,是数据集成。** 两级:

- **参数化区域模型(原生)**:房间/区域 = 对象,带 area/height/volume/orientation/adjacency + 材料属性引用。够做:工程估算 + 区域级求解器输入(多区气流、RC 热网、采光系数)。**这一级 M-Next 直接建。**
- **高保真几何(引用工件)**:IFC/glTF/DWG 等几何文件作为**外部工件**挂在对象上(交换适配器登记/引用),喂重型求解器;平台**不解析几何**,只存引用 + 把结果**锚回**模型元素(roomId ↔ 照度值)。
- **结果锚定**:外部仿真结果按 元素 id / 区域 code 回灌到对应对象字段,保证"哪个房间什么照度"可追溯、可闭环。

工作量:**中**(对象模型 + 工件引用机制 + 结果锚定),**远小于几何内核**;是继 fUML 执行之后的另一块地基,但因"只集成不计算"而可控。

## 4. 三仿真集成(分高低保真)

| 仿真 | 工程估算级(平台直接算) | 高保真级(外挂求解器) |
|---|---|---|
| 采光 | 采光系数(窗地比)、流明法照度 = 派生 + interp 查表 | Radiance 光线追踪(需几何+反射率)→ 外接,结果回灌每房间照度分布 |
| 气流 | 换气次数 ACH(区体积) = 派生 | CFD(OpenFOAM,需几何+网格)或多区气流网络(区+开口拓扑,较轻)→ 外接,结果回灌每区风量/风速 |
| 热 | 热负荷(面积/朝向/U 值)= 派生 + interp;逐时 = A 类数值算子(同能源 SOC) | EnergyPlus 全建筑能耗(需几何)→ 外接,结果回灌每区温度/能耗时序 |

**分层结论**:工程估算级 = 派生层 + interp + A 类数值算子,**现有能力即可**(同能源);高保真级 = 几何 + 外部求解器,平台编排 + 数据集成,**不亲自算**。

## 5. 复用 vs 新建

- **直接复用**:分阶段 profile、产品(材料)库 + 选型 + 成本汇总、拓扑关系、派生/规则闭环、interp 查表、A 类数值算子(待做)、SimulationEngine SPI、交换适配器、快照/报告。
- **新建**:① 几何/空间数据集成层(§3);② 每种外部求解器一个集成适配器(输入快照→工具作业、结果→回灌);③ 室内设计 profile 本身(对象/字段/关系/派生/规则);④ app-UI(户型/布局/3D 多为定制前端 + 引用外部渲染)。

## 6. 诚实边界

- M-Next = 室内设计的**数据/流程/选材/估算/仿真编排中枢**;**几何与物理求解永远外挂**,平台只集成其数据。
- 早期设计 + 工程估算 = 高可行(profile 级);高保真仿真 = 编排可行、依赖几何集成层 + 外部工具。
- 不声称"M-Next 做采光/CFD/能耗仿真";只称"集成并编排这些工具,统一承载其输入与结果数据"。

## 7. 与平台战略

第二个差异极大的验证域(航天↔室内)。若成立,强证"领域无关的统一数据+编排底座"。它新增的**几何/空间数据集成层** + **外部求解器适配器模式**,也反哺其它需要外部仿真/几何的工程域(总线 EMC、结构、热控……)。排序上属愿景层候选,在 fUML/energy 主线之后评估立项。
