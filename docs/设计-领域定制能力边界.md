# 设计稿 — 领域定制能力边界(插件机制能力契约)

> 目的:给"领域定制插件"划定**能覆盖什么、怎么覆盖、边界在哪、越界走哪条逃生舱**。作为整个 profile/插件机制的能力契约,统一后续所有领域卡的取舍。
> 立场:能覆盖全面的不是"声明式 DSL 万能",而是**分层 + 逃生舱**架构——让声明式尽量多吃(零代码、即需即装),长尾用窄而明确的 SPI 接出去。**DSL 永不往图灵完备方向撑。**

## 1. 八个定制面(总览)
领域定制 = 在以下八个面上做声明/扩展。前七面是"做什么",第八面(复用)横切前七面。

| # | 面 | 定制内容 | 声明式甜区? |
|---|---|---|---|
| 1 | **结构** | 对象类型、字段(类型/单位/值类型)、关系(基数/方向/层次)、泛化 | ✅ 几乎全包 |
| 2 | **行为** | 派生计算、校验规则、约束 | ✅ 有界部分包(DSL) |
| 3 | **交互** | 合法连接、编辑可供性、吸附/端口、专属工具 | 🟡 大头可从元模型推导 |
| 4 | **呈现** | 维度/perspective、视图(图/表/矩阵/树/平面图/文档) | ✅ 通用视图 + 声明维度 |
| 5 | **动态/动画** | 时序结果、仿真回放、状态/数值随时间动画 | 🔴 需新增结果时序脊 |
| 6 | **互换** | 导入导出格式(ReqIF/XMI/JSON/FMU) | 🟡 内置 + codec SPI |
| 7 | **跨域映射** | 映射 profile、stereotype↔stereotype 对应 | 🟡 阶段二,声明式映射 |
| 8 | **复用(横切)** | 值类型→模块→profile→实例组件→模板,多粒度复用 | 🟡 元模型层够得着,实例层缺 |

## 2. 四层实现 + 判断准则
覆盖全面靠这四层,逃生舱越往下越窄:

| 层 | 用什么 | 吃下什么 | 写代码? |
|---|---|---|---|
| **L1 声明式 manifest** | 类型/字段/关系/值/泛化/维度 | 结构、呈现骨架、推导式交互(大头) | 否 |
| **L2 表达式 DSL(OCL 子集)** | 派生/规则/映射条件 | 有界计算、导航、校验 | 否(写表达式) |
| **L3 SPI 插件** | 派生 provider / 校验器 / 交换 codec / 转换适配 / 求解器适配 | 重计算、行为执行、外部集成、仿真 | 是(窄接口) |
| **L4 视图/前端插件** | 维度注册 / 自定义视图 / 专属工具 | 专属编辑器、可视化、领域手势 | 是(前端) |

**判断准则(每条定制往哪层放):**
> 能用**结构**表达的进 L1;能用**有界表达式**算的进 L2;要**解方程/跑流程/调外部引擎/仿真**的一律不进 DSL、走 L3;要**专属交互/可视化**的走 L4。
> DSL 的边界 = **有界、可判定、可静态校验**。越界即逃生舱,**绝不把 DSL 撑成通用语言**。

## 3. 逐面详解(声明式→逃生舱阶梯)

### 3.1 结构 — L1 甜区
对象类型/字段/关系/泛化/值类型,全声明式。信息建模类领域(室内、技术方案、MBSE、需求、系统架构)主体在此,零代码。借鉴 MOF/UML 类元模型。

### 3.2 行为 — L1 声明 + L2 计算
规则 `when`、派生 `derivation` 走表达式引擎(现已是递归下降解析 + 密封 AST + EvalContext 求值)。演进为 **OCL 受限子集**(导航/集合算子/布尔算术/if-then-else),共享 AST、加静态类型检查、按 manifest 渐进迁移(见《OMG 评估稿》横切轨道)。**解方程/优化/代码生成不进 DSL → L3。**

### 3.3 交互 — 大头从元模型推导(免费),长尾走 L4
- **推导式(零代码)**:能连哪条线由关系 source/target+基数决定;能怎么编辑由字段 dataType/valueType 决定;选中联动已有。**定义结构的声明同时约束合法交互。**
- **配置式(声明参数)**:吸附网格、端口定义、连接规则进 manifest。
- **专属工具(L4)**:"画墙""布管"等领域手势工具才写前端代码。

### 3.4 呈现 — 通用视图 + 声明维度
图/表/矩阵/树/平面图/文档为通用只读零拷贝视图(切视图=换读法,快)。维度/perspective 声明式(能耗/光/热/风叠加)。专属可视化 → L4。

### 3.5 动态/动画 — 重的真新增:逼出三件现在没有的东西
现模型是**静态快照**。动态仿真 = **随时间变化的结果序列**,DSL 补不了,是架构要加:
1. **结果时序脊(新数据层)**:Modelica transient、状态机 token、优化迭代步,**不塞 rm_object**,独立结果存储按 (run, object/field, t) 索引 + 时序查询 API。平台从"结构"扩成"结构 + 观测/结果"两条脊。
2. **L3 仿真适配 + FMI**:求解器/行为执行产出序列;借 **FMI/FMU**(模型交换与协同仿真标准)耦合外部仿真器。**播放只读预算好的序列,绝不在帧循环现算。**
3. **时间维视图绑定(新)**:playhead + 时间轴拖拽 + 时序→视觉编码(颜色/位置/大小)。平面图热力图随 transient 演化、图里 token 流动、矩阵逐格填充。是已有视图上的一层动画绑定,非新视图。

### 3.6 互换 — 内置格式 + codec SPI
ReqIF(已用)、JSON 内置;XMI(UML/SysML,`SysmlXmiCodec` 已有地基)、FMU(仿真)走 codec SPI(L3)。

### 3.7 跨域映射 — 阶段二,声明式映射 profile
专门的映射 profile 定义跨 profile correspondence relation(元模型层),挂字段映射+基数+方向,复用 m2m_transformation;配映射视图。借 **QVT-Relations 声明式范式**。详见《Profile/Stereotype 设计稿》阶段二。

### 3.8 复用(横切)— 多粒度阶梯;元模型层够得着,实例层缺
横切前七面:结构/行为/视图/映射/交互工具都能被复用。粒度阶梯:

| 粒度 | 复用什么 | 机制(有/缺) | OMG 借鉴 |
|---|---|---|---|
| 值类型/基元 | 单位、量纲 | 值类型有,缺共享库 | SysML QUDV / SI 库 |
| 类型片段 | 单个 stereotype | 缺跨 profile 引用 | Package element import |
| 模块 | 一组类型+关系+规则 | extends 增量(思想),缺正式 module 单元 | Package import/merge、«modelLibrary» |
| Profile/标准库 | 整个领域 profile | 能力市场装载、profile 依赖(阶段二) | profile import + 依赖 |
| **实例组件/装配(最缺)** | 可复用子模型(标准泵/窗/子系统) | **缺**——今天只整模板实例化 | KerML def/usage、可复用 Block/Part |
| 项目模板 | 整套起步项目 | scene_template/template_version(有) | 参数化模板 |

**统一主线借鉴:KerML/SysML v2 「definition vs usage」**——定义一次、使用多次;改 definition,usage 跟随或按版本钉住。把它吃进元模型,整条复用阶梯统一。
**真正大缺口 = 实例层组件/装配复用**:零件目录、可复用子系统。需新增可复用模型片段 + 按引用/按拷贝语义 + 目录浏览(能力市场延伸到实例级)+ 版本钉住。与"结果时序脊"并列为两块重的真新增。

## 4. 两块分量最重的新增架构
1. **结果时序脊(动态/动画)**:静态模型 → 结构 + 结果两条脊;独立时序存储 + 时间维视图绑定 + FMI 仿真适配。
2. **实例级组件复用**:整模板实例化 → 细粒度可复用装配(def/usage、by-ref/by-copy、实例目录)。
其余六面主体顺着现有路线(声明式 + 已有 SPI + 阶段一/二)生长。

## 6. 复用与定制的治理(让大规模不塌)
底子已有/在建:版本化(template_version + withdrawn/restore)、**extends 只增不改**(安全扩展不破坏消费者)、命名空间隔离(阶段一)、血缘/出处。任何复用/扩展先过平台红线:写入经命令入口、视图只读零拷贝、契约/迁移人工发起、转换/仿真异步不进同步视图路径。

## 7. 与路线的衔接
- **阶段一**(profile 隔离)= 一切复用/多 profile 的前提(命名空间不撞)。
- **阶段二**(多 profile 项目 + 映射 profile)承接跨域映射 + profile 依赖 + 元模型层复用;吸收 QVT/XMI/MDA。
- **横切 OCL 子集**统一行为/映射表达式。
- **两块重新增**(结果时序脊、实例级组件复用)= 阶段二之后的两条独立大轨,各自需专门设计稿。
- **长期**对标 SysML v2 API 校准对外接口;MOF 严格分层指导阶段三解耦。

## 8. 反向纪律(再强调)
- 让 **L1+L2 尽量多吃**;长尾用**窄而明确**的 L3/L4 SPI,**别让专属代码漏成每领域定制开发**(否则"可装卸/即需即装"破功)。
- DSL 守住"有界、可判定、可静态校验";越界即逃生舱。
- OMG 借**思想与语义**,不照搬整套元模型与引擎——我们的优势是轻、数据驱动、CQRS 快切视图。
