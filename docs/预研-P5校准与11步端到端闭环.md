# 预研 · P5 校准:同源=视图引擎组 + 11 步端到端闭环走查

> 用途:对照《统一数据驱动办公平台技术说明书 V3.3》给同源前端重新定坐标,并把"MVP 11 步闭环在真内核上怎么走通/怎么验证"固化下来。像 E.3 之于 P4,本文件是 P5 的锚。
> 结论先行:**同源 = 平台的「视图引擎组 / 一级功能域#3 多视图工作空间」,一个插件层;016–022 全部待在这条车道内(消费引擎、写回内核、不自建引擎、不复制事实源)。门锁 MVP 必做闭环已接通内核。下一步不是再接引擎端点(映射/装配/仿真是阶段6–7/暂缓),而是端到端验证 + 选定真实场景。**

## 一、同源在平台里的坐标(先定死)

平台(说明书)= 6 层 / 9 个一级功能域 / 小内核 + 多引擎 + 插件化。同源不是"整个前端",而是其中一层一域:

- **层:** 用户交互层(6 层之首),即 3.8 落地总图的「工作空间与多视图工作台」。
- **域:** 一级功能域 **#3 多视图工作空间** + 6.4.1 选中联动。
- **研发分工(10.7):** 「**视图引擎组**」——负责"文档、表格、图形、矩阵及插件SDK";**红线:"不得复制主数据事实"**。
- **它消费、不拥有:** 规则检查(#4 规则组)、AI(AI 能力组)、审阅(#7 审阅协同组)、输出交换(#8 输出交换组)、仿真(#6 仿真与制品组)、来源/血缘(#2 数据管理)——都是**别的模块组/引擎**,同源只**表达和写回**。

**这直接回答了"为什么一直只改前端":** 同源就是最上层视图引擎组,小内核与各引擎是独立下层(后端 T-V33 线早建好),视图层消费它们并语义写回,正是说明书规定的架构。后端只在**非视图引擎组**能力缺失时才动(slot_binding、真实 STEP/FMU 适配器等),那不是同源的活。

## 四、边界守则(视图引擎组红线)

说明书 10.7:视图引擎组"**不得复制主数据事实**"。同源有本地 `WorkspaceStore`,但它是**乐观缓存**——016 的写是"本地先写 + 后台内核命令 + 冲突回滚",**内核始终是唯一事实源**。守住这条:本地态永远可由内核重载覆盖(demo-reset backend 分支),不得让本地成为与内核并立的第二事实源。
