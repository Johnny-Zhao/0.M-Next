# 验证场景 — 四插件联合验证(备忘,非任务)

状态:**愿景/验证策略备忘**(产品负责人定,2026-06-16)。用于指导后续地基与插件的取舍排序;**本身不是任务卡**,不立即实现。

## 目的

用 4 个差异极大的插件**联合验证平台地基**的表达力与通用性:平台底座(统一数据源 + M2 元模型 + 泛化/重定义/值类型 + 规则 + 交换 SPI + 仿真 SPI + profile-as-模板)必须**同时**容得下"标准 profile"和"私有工具",才算合格。

## 四个验证插件

| # | 插件 | 性质 | profile 来源 | 交换 | 仿真/分析 |
|---|---|---|---|---|---|
| 1 | **SysML 建模** | 标准(OMG profile) | Block/Requirement/Part/Port… + satisfy/derive/allocate | XMI(L1 已起步) | —(结构为主) |
| 2 | **fUML / PSSM / PSCS 仿真** | 标准(OMG 执行语义) | 复用①的结构(活动/状态机/组合结构) | — | 执行器**外接**,挂 L0 仿真 SPI(研究级、重) |
| 3 | **Modelica 建模** | 标准(Modelica Assoc.) | 类/模型/连接器/方程(acausal) | .mo / FMI(待做适配器) | FMI 联合仿真挂 L0 SPI(求解器外接) |
| 4 | **总线设计** | **非标准 / 私有设计工具** | **全自定义** profile(节点/链路/消息/信号 + 分配)+ 私有 schema | 自有 schema 适配器(BL-13 类) | 可选:带宽/调度分析引擎 |

关键:1–3 是**标准 profile**(验证"平台能承载业界标准建模语言"),4 是**私有工具**(验证"平台同样能承载客户自有的非标准设计域")。两类都跑通 = 地基足够通用。

## 地基现状(对照需求)

- 元模型:类型 / 泛化 / 重定义 / 值类型 / 关系 / 规则 — ✓ 已落地(v1.12–v1.18)
- 交换 SPI(`ExchangeAdapter`,707)— ✓;每个插件 = 一个适配器
- 仿真/分析 SPI(`SimulationEngine`,L0)— ✓ 编排层;**执行器/求解器/分析器本体外接**
- profile-as-可复用模板(**批2,待做**)— 4 套 profile 发布/复用/版本化的共同前提

## 这 4 个将逼出的地基缺口(JIT 补,勿过早抽象)

1. **派生/计算层(原"规则聚合",升格)**:属性之间存在**可配置、链式(多跳遍历)、嵌套、多样(sum/avg/max/min/count+算术)**的计算关系。拆两层:**派生属性**(值由其它值+关联对象算出,如 链路.总负载=沿 carries 求和)+ **用派生值的校验规则**(总负载≤带宽)。当前 DSL 仅单对象 + relationCount,缺图遍历+派生。**这是 4 插件里 3 个的共同底层**:总线带宽=沿关系求和;**SysML 参数化/约束块**=值绑定计算图;**Modelica 方程**=变量 acausal 关系(极致形态)。属收官级能力(涉派生语法/路径表达/依赖环检测/求值缓存),JIT——总线或 SysML 参数化上日程再设计。
2. **多 profile 同项目共存(BL-11 元模型联邦)**:若一个项目里 SysML 结构 + fUML 行为 + Modelica 物理 + 总线通信并存互引,需跨 profile 身份/重叠裁定。批2 是其前提。
3. **Modelica 方程/连接器(acausal)表达力**:不完全是"对象+字段+关系";建模插件可"存结构 + 外接 FMI 求解",但 profile 表达力需专门评估(flow/stream 变量、方程)。

## 总线设计插件(细化,2026-06-16)

需支持具体 **1553B、RS422、新型总线** 的全流程:**定义 / 选型 / 设计 / 分析 + 信息流拓扑描述**。

- **总线类型 = 泛化树**:基类"总线"(名称/节点/拓扑/余度/介质…)→ 子类 1553B(BC/RT/BM、RT 地址/子地址、命令-响应、双余度 A/B、主次帧、字类型、1Mbps)、RS422(差分点对点/多点、波特率、驱动/接收器数、线长↔速率、承载的私有协议)、**新型总线(用户自定义子类)**。→ 直接复用平台的泛化/重定义;"定义新总线"= DefineObjectType 挂父类 + 加/重定义参数。
- **四动作映射**:定义=泛化树(profile);**选型**=权衡结构(候选总线 × 准则[带宽/延迟/余度/重量/成本/成熟度] × 打分 → 决策,新结构待设计);设计=节点/链路/消息/信号 + 分配 + 寻址/调度(对象+关系);**分析**=总线负载 Σ(速率×字节)≤容量、1553B 帧时序、端到端延迟、余度覆盖(**跨对象聚合规则 +(可能)分析引擎挂 L0 SPI**);**信息流拓扑**=关系 + 图谱视图。
- **头号驱动"聚合规则"缺口**:总线负载/带宽分析需 Σ over 关联对象 + 算术比较,是规则 DSL 聚合扩展的第一驱动场景。
- **非标准**:以上为通用骨架;真做时需用户提供其工具的**实际 schema/样例**(参数集、私有格式、ICD 结构)对准 profile 与适配器。

## 跨插件数据互通(模型联邦,核心验证目标,2026-06-16)

**终极验证 = 4 插件的数据互相使用**:同一实体在不同 profile 里是不同"面",视图是同一份数据的不同镜头(非拷贝)。

- **同一身份多 facet**:一台"装备/部件" = SysML Block = Modelica Block = 总线图节点/装备。
- **IBD → 总线图**:同一组 block+连接器换镜头渲染——block→节点,承载信号的 connector→总线链路。底层同一份关系数据。
- **SysML Block ↔ Modelica Block**:结构面 ↔ 物理面,靠对应/实现关系绑定。
- **意义**:这是平台"统一数据源 + 视图只读零副本(AG-101/102)+ 外部文件不作事实源(AG-507)"铁律的终极兑现,也是区别于孤立点工具的根本卖点。

需要的能力(均属未来,BL-11 元模型联邦 + M2M 转换;docs/04 §1 行5 列为 B/C 级"借鉴不实现"):

1. **共享身份/对应**:同一对象挂多 profile facet,或不同对象 + 对应/trace 关系绑定;
2. **跨 profile 投影/转换(M2M)**:Block→节点、Connector→链路、IBD→总线图的映射规则;
3. **多 profile 同项目共存(联邦)**:跨框架身份与重叠裁定(人定规则)。

**前提与排序**:联邦是**收官能力**,前提是稳的元模型 + profile-as-模板(批2)。路径不变:地基先行 → 各 profile 成型 → 联邦/M2M 收官。**勿过早做联邦框架**。

## 排序原则(据此推进)

- **地基优先**:批2(profile-as-模板)是 4 个插件的公共地基,先做实。
- **缺口 JIT**:聚合/联邦/方程表达力等,等具体插件落到那步再补,不提前造框架。
- **标准先于私有验证**:1(SysML)走通"标准 profile + 交换"闭环,4(总线)再验"私有域"——两端都通才算地基达标。
