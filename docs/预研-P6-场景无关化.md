# 预研 · P6:同源"场景无关"化(demo → 产品)

> 承接:用户已选 A(让同源变场景无关);门锁 MVP 端到端已在真内核跑通(BE1 + 走查全通)。
> 目标:让同源从"写死门锁"变成"由内核的类型 + 视图配置驱动、能装任何场景"。这是 demo→产品的分水岭,也是平台说明书的立身之本(场景模板 → 多域)。本文件是 P6 的锚,像 E.3 之于 P4。

## 一、现在"锁死在门锁"的到底是什么(耦合图)

backend 模式下,`kernel-gateway.loadWorkspace()` 只把 **objects / relations / history / objectTypes / relationTypes** 换成内核的;**其余整套"表达层"仍来自前端门锁种子 `cloneDemoSeed()` + identity-remap**:

- **expressions**(表达面目录:`exp-dashboard`/`exp-spec-doc`/`exp-portal`/`exp-build-z890`…)——门锁设计的一批"面";**home 页就是列它们**。
- **views**(画布布局)/ **docModels**(文档结构 + 字段引用)/ **fieldRefs**(引用系统)——门锁专属。
- **kpis / biBars**(BI 卡)/ **sceneTemplates**(装机模板)/ **slotBindings** / **anaReports** / **simScenarios**——门锁专属。
- **permissions**——按 `exp-*` 表达 id 为键的门锁权限。

所以你把 ws 换成室内设计(`1111…`),网格显示的是**真数据**,但上面这些门锁面全**错位/悬空**。一句话:**同源现在是"门锁的多视图设计稿接了内核",不是"通用工作台"。**(这也是为什么之前全是前端卡——表达层是视图引擎组的活,但它被写死成了门锁一个场景。)

## 二、目标与关键取舍(要你拍板)

"场景无关" = 表达层不再写死,而是**跟着连上的工作空间走**。三条路:

- **A1 · 自动生成(推荐做地基)**:同源从内核**对象类型/关系自动派生默认面**——每个对象类型一个表格面、一个关系图画布、一个通用文档。**连任何空间即用、零场景设计、纯前端(视图引擎组车道,零后端)。** 代价:门锁那套精致设计(装机配置单、看板 KPI)在 backend 模式会退化成通用面。
- **A2 · 配置驱动**:每个场景的面/文档/模板是**设计好的视图配置**,存在场景模板/profile 里,同源加载渲染。精致,但每场景要设计 + **需要一个"存视图配置"的地方**(kernel 现在不存 = G6),**要动后端**。
- **A3 · 混合(终态)**:A1 自动默认 **+** A2 保存的配置覆盖。既通用又能精致。

**建议:先做 A1 当地基。** 理由:最快让同源对**任何**域可用(网格+关系图+通用文档),纯视图引擎组、零后端,风险小;门锁/任意场景的精致设计日后走 A3 的"保存配置"补回来。A2 纯配置驱动体量大且要后端,不作为起点。

**唯一要你现在定的:起点走 A1(快、通用、门锁暂退化成通用面),还是直接上 A3(保住精致但要同时动后端存视图配置)。**

## 三、decompose(P6 卡序 · A1 口径)

- **P6 批1 · 解耦 shell**:backend 模式 `loadWorkspace` 不再注入门锁 expressions/views/docModels/permissions;换成从内核 types 派生 + 极简 workspace shell。(前端,`kernel-gateway`/`identity-remap`/seed 装配)
- **P6 批2 · 自动面目录**:从内核对象类型生成默认表达面(每类型一个"数据源"面 + 一个关系图 + 一个通用文档);home 页列这批自动面。
- **P6 批3 · 通用渲染**:grid / canvas / doc 从内核 types/objects/relations **通用渲染**(grid 已近;canvas 由关系派生节点/边;doc 通用字段引用)。
- **P6 批4 · 权限/角色通用化**:权限从内核**空间角色**(017c `projectSpaceRole` 泛化)派生,不再按门锁 `exp-*` 键。
- **P6 批5 · 降级与空态**:BI/分析/仿真/模板对任意域**优雅降级**(无配置则空态,不崩)。
- **(后续 A3)** · 保存视图配置层:让门锁/任意场景的精致设计可存可载(这一步才需要碰后端存配置)。

## 四、边界与门锁去向

- 仍是**视图引擎组车道**(从数据渲染,不复制事实源);A1 **零后端**。
- 门锁不再是"写死的默认",而是**内核里的一个工作空间**(BE1 已建 `4444…`);同源连它 = 自动面 + 真门锁数据。
- 门锁那份**精致前端设计稿**:保留在 **Mock 模式**继续当招牌演示;或日后走 **A3** 存成视图配置、在 backend 模式也能载回来。
