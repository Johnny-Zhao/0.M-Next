# 演示脚本 · M-Next 室内户型"改一处全联动"

> 5 分钟现场演示,突出 M-Next 的核心:**画的图背后是受治理的数据,改一个数字,图/派生/规则/文档全联动**。
> 前置:`corepack pnpm dev:up`(或后端独立窗口 + 前端)已起,数据已重置为干净样板户型。

## 一、开场一句话(15 秒)
"市面上的画图工具,图是死的;M-Next 把'画图'变成'在一个活的数据模型上工作'——我改一个房间的尺寸,面积、采光、合规判断、文档会**一起自动更新**。"

## 二、登录 → 项目首页(20 秒)
1. 登录页:M-Next + "数据驱动的工程建模平台"。
2. 项目首页:项目卡(技术方案A · 室内设计 · 健康度圆点)。点进去。
   - 一句话:"项目里能力随用随装——这是室内设计插件。"

## 三、户型平面图:看"受治理的图"(60 秒)
1. 切"平面图"标签:**样板户型 A1**,客厅/主卧/暗次卧/厨房/卫生间/书房按真实位置排布。
2. 指出每间房:**面积、窗地比是后端实时算的派生值**(fx 芯片),不是手填。
3. 指出规则灯:**暗次卧红色(阻断)——采光/窗地比不达标**;主卧/书房黄;其余绿。
   - 一句话:"红黄绿不是我标的,是规则引擎按国标阈值实时判的。"

## 四、核心:改一处,全联动(90 秒)★高光
1. 点 **暗次卧** → 右侧属性区。
2. 把 **窗面积** 从 0.8 改到 **2.5**(失焦即自动保存)。
3. 现场观察(读库一拍内刷新):
   - **窗地比** 派生值上升(0.078 → ~0.245);
   - **规则灯** 由 **阻断(红)→ 达标(绿)**,平面图上该房间红边消失;
   - 树/校验面板的健康度同步变化。
   - 一句话:"我只改了一个数字,派生、合规判断、整张图的状态全跟着变——这就是'数据驱动'。"
4. 反向演示(可选):把 **暗次卧的长** 改小 → 面积变小 → 窗地比反而上升;或把窗面积改回 → 规则灯回红。强调"双向、实时、可追溯"。

## 五、多重表达:同一真值,多种视图(40 秒)
1. 切 **表格**:同一批房间的字段表(改过的值已同步)。
2. 切 **文档** / 点 **生成文档(导出)**:导出 Markdown/Word——"文档也是这个模型的一个视图,改了数据,文档重生成即最新。"
3. 一句话:"图、表、文档,都是**同一份受治理真值**的不同表达,不是各存一份。"

## 六、收尾:平台,不是单品(20 秒)
"室内只是第一个领域插件。底座是通用的——换一个插件(技术方案、系统工程、UML),同一套'数据驱动 + 多重表达 + 实时合规'就服务另一个行业。M-Next 是平台,不是一个画图工具。"

## 备注 / 兜底
- 改值后若画布没立刻变,等 1 秒(读写分离,读库一拍追平)或点"刷新";失焦自动保存,无需找按钮。
- 演示前先重置数据(`docker compose down -v` → 重起后端),确保暗次卧初始为红、窗面积 0.8,演示效果最干净。
- 阈值:窗地比达标线见室内 profile 规则;若改 2.5 不翻绿,改到窗地比明显超标线的值(如窗面积 3.0)。
