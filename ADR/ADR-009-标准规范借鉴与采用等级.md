# ADR-009 标准规范借鉴与采用等级

- 状态:已采纳
- 日期:2026-06-12
- 关联章节:7.15、附录A、附录F

## 背景

V3.3 引入标准规范借鉴原则。平台需要明确哪些标准直接采用、哪些仅做语义对齐、哪些只作为后续扩展参考,避免把标准借鉴误写成完整实现承诺,或让外部标准侵入统一数据内核与热路径。

## 决策

采用以下三级分类:

- **A 直接采用/兼容:**作为正式接口、文件格式或契约校验依据,必须形成可测试的 Schema、API、导入或导出契约。
- **B 语义对齐/借鉴:**采用概念、分层、语义、约束或映射思想,不承诺完整实现标准。
- **C 参考选型/后续扩展:**仅作为专项模块、插件或演进路线参考,不得成为 MVP 主流程强依赖。

标准文件不得作为平台唯一事实源。标准能力通过适配器、插件、Schema、任务队列和读写映射扩展;重型约束求解、全量模型转换、分布式联合仿真与大规模语义推理只能进入温/冷路径。

## F.2 矩阵裁决

| 技术域 | 标准/规范 | 等级 | 本平台裁决 |
| --- | --- | --- | --- |
| 元建模与模型驱动 | MOF、UML、SysML v2、KerML | B | 借鉴元模型分层、模型元素、关系、视图与语义一致性;不承诺完整实现。 |
| 领域特定语言 | DSML 五元组 | B | 场景模板按轻量 DSML 思想定义语义边界;不建设独立 DSML 工具链。 |
| 规则与约束 | OCL、SHACL、JSON Schema | A/B | JSON Schema 直接用于契约校验;OCL/SHACL 仅借鉴约束与图校验语义。 |
| 模型转换 | QVT、ATL、Acceleo、M2T | B/C | 仅借鉴转换规则、版本、差异与回写边界;不引入其实现库。 |
| 需求交换 | ReqIF | A | 实现时按受控子集提供可测试的导入、导出、差异与同步契约。 |
| 模型交换 | XMI | A/B | 实现时优先支持 UML/SysML/UAF 受控子集,并声明映射与兼容边界。 |
| 产品数据交换 | STEP / ISO 10303 | A/B | 分阶段支持元数据、结构、属性与几何子集,不得默认深解析。 |
| 仿真互操作 | Modelica、FMI/FMU、HLA/IEEE 1516 | A/B/C | Modelica/FMI/FMU 按阶段适配;HLA 仅为后续联合仿真参考。 |
| 知识语义 | RDF、OWL、SHACL | B/C | 仅用于资产语义增强与图校验的后续方向,不进入 MVP 事实源。 |
| API 契约 | OpenAPI、JSON Schema | A | REST API、命令/查询端点、错误码与请求响应须形成机器可读契约。 |
| 事件契约 | AsyncAPI、CloudEvents | A/B | 内部信封语义对齐;消息通道与异步接口应可 Schema 化描述。 |
| 需求工程 | ISO/IEC/IEEE 29148 | B | 借鉴需求属性、质量要求、追溯与过程控制方法。 |
| 系统与软件生命周期 | ISO/IEC/IEEE 15288、ISO/IEC/IEEE 12207 | B/C | 借鉴生命周期、过程活动与交付物组织方式,不作为唯一流程约束。 |

## 引入前置条件

1. 新标准或工具必须先通过 ADR,明确采用等级、支持子集、映射规则、兼容边界、替代方案与退出策略。
2. 依赖引入必须通过 ADR-008 准入:linux/arm64、离线解析、许可、国内/内网源与无公网硬依赖。
3. A 级适配器必须维护输入输出样例、映射规则、失败/差异处理与 golden files;变更后执行导入、导出、差异、冲突与回写回归。
4. B 级必须形成概念映射表,明确采用、裁剪与后续扩展概念。
5. C 级清单包括 HLA、AUTOSAR、EMF/CDO、Prolog/CLP、OR-Tools、Gurobi、CPLEX;在专项 ADR 获批前禁止进入 MVP。

## 后果

- 标准兼容承诺变得可测试、可审计,不会被误解为完整实现。
- 适配器与标准工具的引入成本前置到 ADR 和依赖准入阶段。
- 本 ADR 不引入任何代码、依赖、Schema 变更或后置能力实现。
