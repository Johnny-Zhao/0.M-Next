# ADR-002 前端框架与视图层方案

- 状态:已采纳
- 日期:2026-06-12
- 关联章节:3.2(14 类视图)、8.4(多视图性能)、8.4.1(选择联动 P95≤50/100/300ms)、9.6

## 背景

用户交互层需提供文档、表格、图形、矩阵、看板、甘特、BI、三维、Map、表单、白板、仿真回放、审阅批注共 14 类视图,且:

1. 视图必须插件化(3.8 功能总图"插件SDK+视图读模型");
2. 表格虚拟滚动、文档章节级加载、图形分层渲染、三维 LOD、Map 瓦片化(8.4);
3. 同工作台选择联动事件分发 P95≤50ms,高亮 P95≤100ms(8.4.1),要求前端有统一的选择协调器与局部语义索引;
4. E1/E2:构建链与运行时依赖须可离线、无 x86-only native addon。

## 备选方案对比

| 维度            | TS + React 18 + Vite(推荐)                        | Vue 3 + Vite       | Angular |
| --------------- | ------------------------------------------------- | ------------------ | ------- |
| 富文档编辑生态  | ProseMirror/Tiptap 一等公民,协同编辑(Yjs)集成成熟 | 可用但封装层少     | 弱      |
| 图形/图编辑     | AntV X6/G6、React Flow                            | AntV 同样可用      | 弱      |
| 插件化视图 SDK  | 组件模型 + 微前端方案成熟                         | 成熟               | 重      |
| 国内人才/组件库 | 充足(Ant Design)                                  | 充足(Element Plus) | 少      |
| 大表格虚拟滚动  | TanStack Table/Virtual、S2                        | vxe-table          | 一般    |

视图层关键子选型(均为可插拔渲染层,统一经"视图读模型 + 选择协调器"接入):

| 视图      | 方案                                                              | 备选                                                         |
| --------- | ----------------------------------------------------------------- | ------------------------------------------------------------ |
| 文档      | Tiptap(ProseMirror)+ 自定义"数据引用/结构化数据块"节点 + Yjs 协同 | Slate(生态弱)、Monaco(代码场景另用)                          |
| 表格/矩阵 | TanStack Table + TanStack Virtual(MIT);矩阵复用表格内核分区加载   | AG Grid(企业版收费,排除)、vxe-table                          |
| 图形/白板 | AntV X6(图编辑)+ G6(大图分层/聚合)                                | React Flow                                                   |
| 看板/甘特 | dnd-kit + 自研甘特(SVG/Canvas)                                    | dhtmlxGantt(GPL/商业,排除)                                   |
| BI        | ECharts(Apache-2.0,国产)                                          | AntV G2                                                      |
| 三维      | Three.js + LOD/按需加载                                           | Babylon.js                                                   |
| Map       | MapLibre GL(BSD,离线瓦片)                                         | OpenLayers;**排除 Mapbox GL v2+(需 token,公网依赖,违反 E2)** |

## 决策

**TypeScript + React 18 + Vite 构建;视图层为可插拔渲染插件,文档采用 ProseMirror/Tiptap + Yjs,大数据视图一律虚拟化/分层加载;所有视图只读"视图读模型",写操作以语义命令回传内核。** 与附录E ADR-002 一致。地图明确选 MapLibre 以满足 E2 离线。

## E1/E2 符合性逐项核对

| 检查项                    | 结论                                                                                                                              |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| arm64 官方二进制?         | ✅ 前端产物为静态资源,与 CPU 架构无关;构建期 native 依赖(esbuild、rollup native、swc)均有官方 linux-arm64 包,可在 arm64 CI 上构建 |
| 国内镜像源可装?           | ✅ 全部依赖可经 npmmirror.com 或 Nexus npm 私服安装;二进制类(esbuild 等)npmmirror 提供同步;锁定 pnpm-lock 离线打包                |
| 无公网硬依赖?             | ✅ 不使用 Mapbox token、Google Fonts、公网 CDN;字体、瓦片、ECharts 地图 JSON 全部本地化;CI 增加"产物外呼扫描"                     |
| 无 x86-only native addon? | ⚠→✅ 禁用 node-canvas、sharp 等易出问题 addon;如需服务端渲染图片改在 Java 侧实现;依赖准入清单核查(ADR-008)                       |
| 无云托管依赖?             | ✅ 静态资源由 Nginx 容器自托管                                                                                                    |

## 风险与缓解

| 风险                                                       | 缓解                                                                                                           |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 14 类视图并行开发导致交互不一致、选择联动达不到 8.4.1 指标 | 先落统一视图 SDK(读模型订阅、SelectionRef 协议、局部语义索引),MVP 只交付表格/文档/图形/看板,其余按插件节奏接入 |
| ProseMirror 定制"数据引用节点"复杂度高                     | 文档视图先支持章节级结构 + 只读数据引用,可编辑引用二期;预研专人                                                |
| 开源许可证踩坑(AG Grid/dhtmlx 等)                          | 前端依赖准入含 license 扫描,仅允许 MIT/Apache/BSD/ISC                                                          |
| 大图(10万级关系)渲染卡顿                                   | 强制走 G6 聚合/抽象层级,超过阈值只渲染可见子图(对应 8.4.1"超过100个表达位置仅高亮可见范围")                    |

## 标准对齐声明(V3.3)

- 涉及标准/事实标准:React/Vite 插件生态、DSML 具体语法与语法映射思想。
- 采用等级:A(直接采用/兼容)用于前端框架和构建接口;多视图作为同一抽象数据的具体语法为 B(语义对齐/借鉴)。
- 边界:不承诺完整 DSML 工具链,不在 MVP 提前实现可配置视觉语法框架。
