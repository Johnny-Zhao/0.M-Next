# ADR-006 对象存储

- 状态:已采纳
- 日期:2026-06-12
- 关联章节:3.7(文件存储/对象存储)、8.7(大仿真结果文件独立存储)、8.8(制品三级解析)、4.x(snapshot/artifact_file 含 hash、uri)、9.6.1(明确"对象存储可用 MinIO 替代")

## 背景

对象存储承载:上传制品原文件(STEP/XMI/ReqIF/FMU/Office)、输出成果(Word/PPT/PDF 快照)、仿真大结果、三维轻量化模型、搜索快照备份。要求内容寻址(artifact_file.hash)、版本化(快照不可变)、生命周期管理,并且 9.6.1 点名禁止硬依赖 AWS S3 等云服务。

## 备选方案对比

| 维度                 | MinIO(推荐)                           | Ceph RGW               | SeaweedFS  | 本地FS+NFS   |
| -------------------- | ------------------------------------- | ---------------------- | ---------- | ------------ |
| 部署复杂度           | 低(单二进制 Go,可单机可纠删码集群)    | 高(完整分布式存储系统) | 中         | 低           |
| S3 API 兼容          | 高                                    | 高                     | 中         | 无(需自封装) |
| 版本/生命周期/对象锁 | ✅ 原生                               | ✅                     | 部分       | ✗            |
| arm64 官方支持       | ✅ 官方 linux/arm64                   | ✅                     | ✅         | —            |
| 许可证               | AGPL-3.0(网络服务自用合规;分发需评估) | LGPL                   | Apache-2.0 | —            |
| 适配规模             | 私有化中小集群最佳                    | PB 级                  | 海量小文件 | 单机演示     |

## 决策

**MinIO 作为统一对象存储,S3 协议接入;应用侧封装 StorageClient(仅依赖 S3 兼容 API,不依赖 MinIO 私有特性),保持向 Ceph RGW 或客户自有 S3 兼容存储的可替换性。** 与附录E ADR-006 一致。

桶规划与策略:

- `artifacts`(制品原件,按 hash 寻址,开启版本)、`outputs`(输出快照,对象锁 WORM,防覆盖,对应 9.1.3"归档防覆盖")、`sim-results`(仿真大结果,生命周期降冷/过期)、`search-backup`;
- 全部经内网端点访问,凭证走环境变量/密钥管理,不嵌代码;
- 上传走预签名 URL,避免大文件穿透应用服务(8.8"避免大文件上传后卡顿")。

## E1/E2 符合性逐项核对

| 检查项            | 结论                                                                                                 |
| ----------------- | ---------------------------------------------------------------------------------------------------- |
| arm64 官方二进制? | ✅ MinIO 官方发布 linux-arm64 二进制与多架构镜像(Go 静态编译,无 glibc 纠缠,麒麟/UOS 友好)            |
| 国内镜像源可装?   | ✅ 镜像同步私有 Registry;单二进制亦可直接随离线介质分发                                              |
| 无公网硬依赖?     | ✅ 自托管;关闭版本检查/遥测;Console 与 API 全内网                                                    |
| 无云托管依赖?     | ✅ 本 ADR 即 9.6.1 要求的 AWS S3 替代方案;代码仅依赖 S3 协议,无 AWS SDK 区域/STS 等云特性            |
| 国密预留          | ⚠ 9.6.2 国密为后续合规项:MinIO SSE 为 AES;如客户强制 SM4,走应用层信封加密(国产密码库)而非依赖存储端 |

## 风险与缓解

| 风险                                                     | 缓解                                                                                                                                 |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| AGPL-3.0 许可证:若产品整体分发含 MinIO 修改版需开源      | 不修改 MinIO 源码、独立进程经网络 API 调用(AGPL 边界外);商务上保留 MinIO 商业授权或切换 Ceph RGW 的预案;StorageClient 抽象保证可替换 |
| MinIO 社区版近年功能裁剪(如管理控制台收缩)、版本策略变化 | 锁定经验证的版本入离线介质,升级须走兼容性测试;管理操作以 mc 命令行与 IaC 脚本为准,不依赖 Web 控制台                                  |
| 单机部署数据可靠性                                       | 最低交付规格即启用本地纠删码(单机多盘 EC);备份策略(mc mirror 到第二节点)写入交付手册                                                 |
| 大文件直传绕过权限                                       | 预签名 URL 短时效 + 桶策略最小权限 + 下载行为入审计日志(9.x 全审计)                                                                  |

## 标准对齐声明(V3.3)

- 涉及标准/事实标准:S3 兼容 API、标准制品适配与受控子集原则。
- 采用等级:A(直接采用/兼容)用于对象存储接口;制品语义映射为 B(语义对齐/借鉴)。
- 边界:对象存储只保存制品与快照,不得作为统一数据事实源;标准文件导入后必须解析为内部对象、字段、关系和映射。
