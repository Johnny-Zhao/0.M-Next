# ADR-005 搜索引擎

- 状态:已采纳
- 日期:2026-06-12
- 关联章节:8.2(对象搜索常规数据量 1 秒内)、8.10(对象搜索 P95≤1s,"索引可用时")、8.9(搜索索引更新属温路径)、3.7、9.6

## 背景

搜索覆盖对象、字段值、文档内容、批注、资产库,以中文为主,需:温路径异步增量索引(由 event_outbox 事件驱动,允许最终一致)、按 workspace/权限过滤、P95≤1s。E2 要求中文分词插件可离线安装。

## 备选方案对比

| 维度                         | OpenSearch 2.x(推荐)                              | Elasticsearch 8                                | Meilisearch                | PostgreSQL FTS(zhparser/pg_trgm) |
| ---------------------------- | ------------------------------------------------- | ---------------------------------------------- | -------------------------- | -------------------------------- |
| 许可证                       | Apache-2.0                                        | Elastic License/SSPL(私有化分发有法律审查成本) | MIT                        | PG License                       |
| 中文分词                     | analysis-ik(社区适配版)/analysis-smartcn 离线插件 | IK 成熟                                        | 内置 unicode 分段,中文一般 | zhparser 可用                    |
| 聚合/复杂过滤(权限+空间范围) | 强                                                | 强                                             | 弱                         | 中                               |
| 规模上限                     | 高                                                | 高                                             | 中(单机为主)               | 受主库资源挤占                   |
| arm64 官方镜像               | ✅                                                | ✅                                             | ✅                         | ✅                               |
| 运维复杂度                   | 中(JVM 集群)                                      | 中                                             | 低                         | 零新增组件                       |

## 决策

**OpenSearch 2.x 作为统一搜索引擎;MVP 单节点起步,中文分词用离线打包的 IK 适配插件(备选 smartcn);索引由 Outbox 事件消费者增量更新。** 与附录E ADR-005 一致("OpenSearch/Elasticsearch 兼容方案"),选 OpenSearch 而非 ES 的决定性因素是 Apache-2.0 许可证对私有化交付无分发限制。

**降级路径(写入设计而非口头承诺):** 搜索服务不可用时回退 PG `pg_trgm` 模糊查询,只保证对象名/编号检索——对应 9.1.2 降级可用要求,亦满足 8.10 指标的限定语"索引可用时"。

实施要点:索引文档冗余 workspace_id 与权限标签,查询侧强制 filter;索引 Schema 版本化,重建索引任务化(冷路径);快照备份到 MinIO(S3 兼容 repository)。

## E1/E2 符合性逐项核对

| 检查项            | 结论                                                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| arm64 官方二进制? | ✅ opensearchproject/opensearch 官方提供 linux/arm64 镜像                                                               |
| 国内镜像源可装?   | ✅ 镜像同步至私有 Registry;IK/smartcn 插件 zip 随安装包离线分发,`opensearch-plugin install file://` 本地安装,不访问公网 |

| 无云托管依赖?     | ✅ 不使用 Amazon OpenSearch Service/Elastic Cloud,自建容器部署                                                          |
| 备份目标          | ✅ S3 repository 指向 MinIO 内网端点(ADR-006)                                                                           |

## 风险与缓解

| 风险                                           | 缓解                                                                               |
| ---------------------------------------------- | ---------------------------------------------------------------------------------- |
| IK 对 OpenSearch 的适配为社区维护,版本错配风险 | 锁定 OpenSearch 小版本与插件版本配对,纳入离线介质清单;备选官方 analysis-smartcn    |
| JVM 搜索集群在小规格私有化环境占资源           | MVP 单节点 + 2GB 堆基线;与后端 JVM 统一容量规划;客户极小规格时启用 PG FTS 兜底模式 |
| 索引与主数据漂移                               | Outbox 消费者幂等 + 定时对账任务(冷路径)比对计数/校验和,差异触发局部重建           |
| 权限过滤遗漏导致越权搜出                       | 查询统一经搜索网关拼装 filter,禁止前端直连;纳入越权测试用例(9.5)                   |

## 标准对齐声明(V3.3)

- 涉及标准/事实标准:OpenSearch REST API、JSON Schema、RDF/OWL 知识语义参考。
- 采用等级:A(直接采用/兼容)用于搜索接口和索引 Schema;知识语义为 C(后续扩展参考)。
- 边界:搜索索引始终是可重建读模型,不得成为事实源;不在 MVP 引入大规模语义推理。
