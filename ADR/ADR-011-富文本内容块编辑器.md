# ADR-011 富文本内容块编辑器（Tiptap）

- 状态：草案（业主 commit 即批准）
- 日期：2026-07-06
- 关联：ADR-002（前端框架与视图层，已预选 Tiptap）、v0.2 批次 2

## 背景

v0.1/v0.2 批次 1 后，方案与模块的"正文"仍是纯文本字段输入框，写作体验不足以支撑"文档像文档"的定位承诺，是用户逃回 Word 的首要原因。ADR-002 视图层选型时已将文档视图方案预定为 Tiptap（ProseMirror），本 ADR 将其正式纳入依赖准入。

## 决策

引入 Tiptap 2.x 作为**正文内容块**的富文本编辑器：

- 依赖：`@tiptap/react`、`@tiptap/core`、`@tiptap/pm`、`@tiptap/starter-kit`（按需裁剪扩展），全部 MIT License，纯 JS 无 native 产物（满足 ADR-008 双架构与离线准入）；
- 使用位置：`packages/views` 文档视图层（body-editor/body-content，经字段编辑唯一出口保存）；web 不直接依赖 tiptap；
- 存储格式：Tiptap JSON 序列化字符串，存于对象的 `body` 字段（manifest 声明式 string 字段），主数据侧不解析；
- 允许的编辑能力子集：段落、加粗、斜体、无序列表。**不允许标题**——章节结构永远由模型（对象树）驱动，正文内不得再造层级，这是产品定位红线；
- 导出：DocxTreeRenderer 解析 body JSON 渲染为 docx 段落/粗斜体/列表；无法识别的节点降级为纯文本。

## 明确不做（防滑向通用文档编辑器）

表格/图片/嵌入块进正文；协同光标；全文档 Tiptap 化；自定义节点体系；Markdown 双向转换。以上任何一项若未来需要，须新开 ADR。

## 替代方案

- 继续 textarea：写作体验不达 v0.2 标尺，否决；
- Slate：生态与维护弱于 ProseMirror 系，ADR-002 已比较，否决；
- Milkdown/ProseMirror 裸用：封装成本高，否决。

## 后果

- `ci/deps-allowlist.yaml` 增补 @tiptap/*、prosemirror-*（随实现卡提交）；
- body 字段进入导出契约的默认段落角色（fieldRoles 已支持 paragraph，复用）；
- 编辑器子集扩展（如有）以 ADR-011 修订形式记录。
